## 설정 순서

### 1. NavMesh 베이크 (먹괴음이 길찾기 하려면 필수)

> ⚠️ 2026-08-16 정정: 이 프로젝트는 **AI Navigation 패키지(Unity 6)** 를 쓰고 있어서, 예전 Unity(Window → AI → Navigation의 Object/Bake 탭으로 굽는 방식)와는 워크플로우가 다릅니다. Navigation 창은 이제 Agent 종류(Agents 탭)/영역 비용(Areas 탭) 정의용일 뿐이고, 실제 베이크는 **`NavMeshSurface` 컴포넌트**로 합니다.

1. Hierarchy에서 `Ground` 선택
2. Inspector `Add Component` → **"Nav Mesh Surface"** 검색해서 추가
3. 컴포넌트 안에 있는 **`Bake`** 버튼 클릭 (컴포넌트 자체에 붙어있음, 별도 창 필요 없음)
4. Scene 뷰에 파란색 영역(NavMesh)이 Ground 위에 깔리면 성공

> ⚠️ 이 단계를 빼먹으면 `EnemyPyeong`이 `NavMeshAgent.SetDestination()`을 호출해도 아무 반응이 없습니다 (에러도 안 남 — 조용히 무시됨). 적이 안 움직이면 제일 먼저 이걸 의심할 것.
> 참고: [[13 먹괴음 AI 설계]]가 원래 상정했던 "씬 로드 시 `NavMeshSurface.BuildNavMesh()` 런타임 빌드"는 나중에 큐브 면 전환(⑤ 이후) 붙일 때 적용하면 됨 — 지금 v0.1 단일 씬에서는 에디터에서 한 번 굽는 걸로 충분.

### 2. 먹괴음 - 평 오브젝트 생성

1. Hierarchy 빈 곳 클릭 → 선택 해제
2. Hierarchy 우클릭 → `3D Object → Capsule` (임시 비주얼 — 나중에 실제 모델로 교체)
3. 이름을 `EnemyPyeong`으로 변경
4. Player와 겹치지 않는 위치로 이동 (예: Position X 5, Y 0.5, Z 5 정도)
5. `Add Component → Enemy Pyeong` 검색해서 추가
   - `[RequireComponent]`로 `NavMeshAgent`, `EnemyHealth`가 자동으로 같이 붙습니다
6. `NavMeshAgent` 컴포넌트가 잘 붙었는지 확인 (Capsule 기본 Collider와 충돌 안 함, 별도 컴포넌트라 안전)

### 3. 플레이어 체력 붙이기

1. Hierarchy에서 `Player` 선택
2. `Add Component → Player Health` 검색해서 추가

### 4. 확인

1. Play 버튼
2. `EnemyPyeong`이 배치된 위치에서 Player가 `sightRadius`(기본 6) 안에 들어가면 다가오는지 확인
3. `attackRange`(기본 1.5) 안까지 오면 잠깐 멈췄다가(Windup) 공격하는지 확인
4. Console에 "플레이어 피격! 남은 HP: ..." 로그가 뜨는지 확인
5. Player가 붓으로 `EnemyPyeong`을 3타 콤보로 치면 Console에 "EnemyPyeong 정화 완료!" 로그와 함께 사라지는지 확인 (HP 30, 콤보 대미지 6+7+10=23이라 최소 2콤보 필요)

## 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| 적이 플레이어를 감지해도 안 움직임 | NavMesh를 안 구웠음 | 위 1번 단계(Bake) 진행 |
| 적이 플레이어를 아예 감지 못함 | Player 태그가 `Player`가 아님 | Player 오브젝트 Tag 확인 (예전에 이미 고쳐뒀어야 함) |
| 붓으로 때려도 적이 안 죽음 | `EnemyPyeong`에 `EnemyHealth`가 자동으로 안 붙었거나, 붓의 `Attack Range`/`Hit Offset`이 적과 안 겹침 | Inspector에서 `EnemyHealth` 컴포넌트 존재 확인, 붓의 판정 범위(`Attack Range`, `Hit Offset`)와 적 사이 거리 확인 |
| 적 공격이 플레이어에게 안 먹힘 | `Player`에 `PlayerHealth`가 없음 | 위 3번 단계 진행 |
