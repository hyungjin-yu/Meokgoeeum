# 큐브 좌표계 씬 설정 (Addressables 면 전환)

> [[CubeMapManager]] + [[GameState]] + [[CubeFaceData]] + [[FadeManager]] 코드는 완성되어 있습니다.
> 이 문서는 그걸 실제로 동작시키기 위한 **Unity 에디터 설정 절차**입니다. Cinemachine/NavMesh 설정보다
> 훨씬 손이 많이 갑니다 — Addressables를 이 프로젝트에서 처음 실제로 쓰는 거라 그렇습니다. 천천히 순서대로.

## 왜 이렇게 복잡한가 (배경)

지금까지 `SampleScene` 하나에 Player, GameSystems(매니저들), Ground, 적들이 전부 같이 들어있습니다.
큐브 좌표계는 "면(Face)마다 별도 씬"이 전제라서, **Player/매니저는 계속 남아있고 면 콘텐츠만 통째로
갈아끼울 수 있게** 씬을 분리해야 합니다. 그래서:

- **SC_Game** (새로 만듦): Player, GameSystems(매니저 전부)가 사는 "영구 씬" — 절대 언로드 안 됨
- **SC_Face_0 ~ SC_Face_5** (SampleScene을 씨앗으로 6개 준비): Ground, 적, 장식물 등 "면 콘텐츠" — 회전할 때마다 하나만 로드되고 나머진 언로드됨

## Addressables가 대체 뭔가 (처음이면 이거부터)

지금까지는 씬을 "직접" 로드했습니다(그냥 씬 파일 하나 열고 Play). **Addressables는 "이름표(주소)를
붙여서 필요할 때만 불러오고, 필요 없어지면 메모리에서 완전히 내리는" 시스템**입니다. 왜 이게 필요하냐면:

- 씬 6개를 한꺼번에 다 로드해두면 메모리 낭비가 큼 (게다가 씬 하나에 있어야 할 Ground/적이 6개 씬에 다 겹쳐서 보이는 사고도 남)
- "지금 보이는 면 1개만 켜져 있고, 회전하면 이전 면은 완전히 꺼진다"를 코드로 제어하려면, 그 씬에 "주소"를 붙여서 `Addressables.LoadSceneAsync("이 주소")` / `UnloadSceneAsync()`로 불러오고 내릴 수 있어야 함

그래서 **1단계(최초 설정)**과 **5단계(씬에 주소 붙이기)**가 필요한 겁니다. 한 번 익숙해지면 별거 아닌데, 처음엔 낯선 창이 하나 늘어나는 느낌일 수 있어요. 아래를 그대로 따라오면 됩니다.

## 0단계 — 지금 상태 기준 v0.2 첫 테스트 범위 (읽고 시작할 것)

**전체 6개 면에 각각 다른 레벨 디자인을 채우는 건 이 단계의 목표가 아닙니다.** 지금 목표는 "회전하면
진짜로 다른 씬으로 전환되고, 플레이어가 SpawnPoint로 순간이동하는 핵심 메커니즘이 동작하는가"만
검증하는 것. 그래서 **SC_Face_1~5는 일단 SC_Face_0를 복제한 것으로 채워도 충분**합니다 (내용은 나중에
따로 다듬으면 됨). 6개를 전부 만드는 게 부담되면 **처음엔 2개(Face 0, Face 1)만 만들어서 전환 자체가
되는지부터 확인**해도 좋습니다 — 나머지는 GameState의 Face Data 슬롯을 비워두면 그냥 회전 후보에서
자동으로 제외됩니다 (코드가 null 체크를 하도록 짜여 있음).

---

## 1단계 — Addressables 최초 설정 (한 번만)

1. 상단 메뉴 `Window` → `Asset Management` → `Addressables` → `Groups`
2. 처음 여는 거라면 창 가운데에 **"Create Addressables Settings"** 라는 버튼 하나만 덩그러니 있는 화면이 뜹니다 → 클릭
3. 클릭하면 몇 초 안에:
   - `Assets/AddressableAssetsData` 폴더가 자동 생성됩니다 (설정 파일들 — 손댈 필요 없음)
   - `Groups` 창에 표 형태 UI가 나타납니다. 기본으로 `Built In Data`, `Default Local Group` 이렇게 두 줄(그룹)이 보일 겁니다
4. **여기서 더 건드릴 설정 없음.** Profiles, Build 관련 메뉴는 지금 신경 안 써도 됩니다 — 에디터에서 Play 버튼으로 테스트할 때는 Addressables가 기본적으로 "에셋을 그 자리에서 바로 읽는" 모드로 동작해서, 별도로 "빌드"하지 않아도 됩니다.

> 이 창(`Groups`)은 5단계에서 다시 씁니다. 지금은 닫아도 되고 그냥 열어둬도 됩니다.

## 2단계 — 영구 씬(SC_Game) 만들고 Player/매니저 옮기기

1. Project 창에서 `Assets/Scenes` 폴더로 이동 → 빈 곳에서 우클릭 → `Create` → `Scene` → 이름을 `SC_Game`으로
2. `SC_Game`을 더블클릭해서 열기 (Hierarchy가 텅 빈 상태로 바뀝니다 — 정상)
3. Project 창에서 `SampleScene`을 **Hierarchy 창 안으로 드래그** — 이렇게 하면 `SampleScene`이 "추가로(Additive)" 열립니다. 이제 Hierarchy 맨 위에 씬이 2개 보일 겁니다(`SC_Game`, `SampleScene`) — 각 씬 이름이 굵은 글씨로 구분되어 있고, 그 아래 자기 오브젝트들이 들여쓰기로 붙어있는 구조
4. `SampleScene` 아래에서 다음 오브젝트들을 **전부 선택**(Ctrl/Shift 클릭)한 다음, **Hierarchy 안에서 `SC_Game` 씬 이름 위로 드래그**:
   - `Player`
   - `GameSystems` (그 아래에 붙어있는 모든 매니저 컴포넌트 — ColorSystemManager, ColorOrbPool, ColorWaveEffect 등 — 오브젝트 자체를 옮기면 자식/컴포넌트는 그대로 따라감)
   - 카메라 관련 오브젝트 전부 (`Main Camera`, Cinemachine 가상 카메라 오브젝트 — 이름이 `CM ...`으로 시작하는 것들)
   - `EventSystem` (있다면)
5. 드래그하고 나면 그 오브젝트들이 Hierarchy에서 `SC_Game` 아래로 옮겨진 게 보입니다. `SampleScene` 아래에는 Ground, 적, 장식물 같은 **레벨 콘텐츠만** 남아있어야 정상
6. `File` → `Save`(또는 `Ctrl+S`) — 두 씬 다 저장됩니다(열려있는 씬 전부 저장)

> ⚠️ 오브젝트를 드래그로 옮기는 거지, 복사가 아닙니다. 실수로 잘못 옮겼다면 반대로 다시 드래그하면 됩니다. 헷갈리면 Hierarchy 맨 위 씬 이름들이 굵게 표시되니 지금 뭐가 어느 씬 소속인지 항상 그걸로 확인하세요.

## 3단계 — SampleScene을 SC_Face_0로 정리

1. `SampleScene`에 **SpawnPoint 빈 오브젝트 추가**: `SampleScene` 이름 위에서 우클릭 → `Create Empty` → 이름을 정확히 `SpawnPoint`로 (대소문자까지 정확히 — `CubeMapManager`가 이름으로 찾습니다) → 플레이어가 이 면에 도착했을 때 서 있을 위치/방향으로 Position 옮기기 (Ground 위, 막힌 벽 없는 자리로)
2. `Ctrl+S`로 저장
3. Project 창에서 `SampleScene` 파일을 클릭해서 선택 → `Ctrl+D`(Duplicate) → 새로 생긴 파일 이름을 `SC_Face_0`로 변경 (원본 `SampleScene`은 이제 안 씀 — 지워도 되고 그냥 둬도 무방, 헷갈리면 지우는 걸 추천)

## 4단계 — 나머지 면 씬 준비 (최소 2개, 권장 6개)

1. Project 창에서 `SC_Face_0`를 선택 → `Ctrl+D` → 이름을 `SC_Face_1`로 변경 (테스트용이면 내용 그대로 둬도 됨)
2. 나중에 시간 될 때 `SC_Face_2` ~ `SC_Face_5`도 같은 방식으로 준비 (지금 당장 안 해도 회전 시스템 자체는 잘 동작함 — 0단계 참고)

## 5단계 — 면 씬들을 Addressable로 등록 (Addressables 처음 실제로 쓰는 단계)

1. 1단계에서 열어둔 `Addressables Groups` 창을 다시 엽니다 (`Window > Asset Management > Addressables > Groups`)
2. Project 창에서 `SC_Face_0` 파일을 클릭해서 선택한 채로, **`Groups` 창의 `Default Local Group` 줄 영역 안으로 드래그**
3. 드래그하면 `Default Local Group` 아래에 새 항목이 하나 생깁니다. 이 줄에 보이는 열(컬럼)은 대략:
   - **첫 번째 칸(주소/Address)**: 기본값은 씬 파일 경로(`Assets/Scenes/SC_Face_0.unity`)로 길게 들어가 있음 — 이걸 더블클릭해서 **`SC_Face_0`처럼 짧게** 바꿔주세요 (필수는 아니지만 나중에 창에서 알아보기 훨씬 편함)
   - 나머지 칸(Path, Labels 등)은 지금 건드릴 필요 없음
4. `SC_Face_1`(그리고 준비했다면 `SC_Face_2`~`SC_Face_5`)도 똑같이 반복: Project 창에서 선택 → `Groups` 창 `Default Local Group` 안으로 드래그 → 주소 이름 정리

> 헷갈리기 쉬운 포인트: 여기서 정하는 "주소(Address)" 이름은 사실 코드에서 직접 쓰지 않습니다. 6단계에서 `CubeFaceData` 에셋의 `Scene Reference` 필드에 **씬 파일 자체를 드래그해서 연결**하기 때문에, 이름이 정확히 일치할 필요는 없어요. 그래도 보기 편하게 맞춰두는 걸 권장합니다.

## 6단계 — CubeFaceData 에셋 만들기

1. Project 창에서 `Assets` 아래 `Data` 폴더가 없으면 우클릭 → `Create` → `Folder` → 이름 `Data`
2. `Data` 폴더 안에서 우클릭 → `Create` → `MG` → `Cube Face Data` → 이름을 `CubeFaceData_0`로. 준비한 면 개수만큼 반복해서 `CubeFaceData_1`, `CubeFaceData_2`… 도 생성
3. 각 에셋을 Project 창에서 클릭 → Inspector에서:
   - `Face Index`: 파일 번호와 맞춰서 0, 1, 2… 순서대로 입력
   - `Scene Reference`: Project 창의 대응하는 `SC_Face_N` 씬 파일을 이 필드로 드래그 (5단계에서 Addressable로 등록한 씬만 여기 드롭됩니다 — 안 되면 5단계를 안 했거나 놓친 씬일 가능성)

## 7단계 — GameSystems에 매니저 부착 + 연결

`SC_Game`을 열고(2단계에서 옮긴) `GameSystems` 오브젝트에:

1. **`GameState.cs` 부착** → Inspector에서 `Face Data` 배열의 `Size`를 6으로 입력 → Element 0~5에 6단계에서 만든 `CubeFaceData_0~5`를 **인덱스 순서 맞춰서** 드래그. 준비 안 한 면은 슬롯을 비워둬도 됩니다(자동으로 회전 후보에서 제외됨)
2. **`CubeMapManager.cs` 부착** → `Starting Face Index`는 기본값 0이면 됩니다
3. **`FadeManager.cs` 부착** → 별도 설정 필요 없음 (Awake에서 알아서 화면 페이드용 Canvas를 만듦)
4. **`DebugOrbCheat.cs`가 이미 부착돼 있다면 그대로 둠** (F4로 회전 테스트 가능). 없다면 `GameSystems`에 부착

## 8단계 — 재생 테스트

1. **반드시 `SC_Game` 씬을 연 상태에서 Play** (`SampleScene`이나 `SC_Face_0`을 직접 열고 Play하면 Player/매니저가 없어서 안 됩니다)
2. Play 시작하면 콘솔에 `[CubeMapManager] 플레이어를 (...)로 이동.` 로그가 뜨면서 Face 0가 로드된 것 — Game 뷰에 Ground/적이 보이는지 확인
3. **F4**를 눌러 회전 테스트 → 콘솔에 이 순서로 로그가 뜨는지 확인:
   - `회전 시작! 축=... , 0면 → n면`
   - (화면이 잠깐 검게 페이드)
   - `플레이어를 (...)로 이동.`
   - `n층 도착. 현재 면: ...`
   - (화면이 다시 밝아짐)
4. Face 1을 준비했다면 화면 내용이 바뀌는 게 보여야 함 (지금은 Face 0 복제본이라 겉보기엔 똑같을 수 있음 — 그래도 콘솔 로그의 "현재 면" 숫자가 바뀌는지로 실제 전환 여부를 확인할 수 있습니다)

## 진행 상황 확인 체크리스트

각 단계 끝나고 이게 맞는지 스스로 확인해보세요:

- [ ] 1단계 후: `Addressables Groups` 창에 `Default Local Group`이 보임
- [ ] 2단계 후: `SC_Game`을 열면 Player/카메라/GameSystems가 보이고, `SampleScene`을 열면 그게 하나도 안 보임(Ground/적만 있음)
- [ ] 3단계 후: `SC_Face_0` 파일이 존재하고, 그 안에 `SpawnPoint`라는 빈 오브젝트가 있음
- [ ] 5단계 후: `Groups` 창의 `Default Local Group` 아래에 `SC_Face_0`(, `SC_Face_1`…) 줄이 보임
- [ ] 6단계 후: `Data` 폴더에 `CubeFaceData_0`(, `_1`…) 에셋이 있고, 각각 Scene Reference가 채워져 있음(비어있지 않음)
- [ ] 7단계 후: `SC_Game`의 `GameSystems`에 `GameState`/`CubeMapManager`/`FadeManager` 3개가 다 보임

## 자주 나올 수 있는 문제

| 증상 | 원인 |
|------|------|
| Play 해도 아무것도 안 보임 | `SC_Game`이 아니라 다른 씬을 열고 Play했을 가능성 — Player/매니저가 없는 씬 |
| "면 데이터 또는 씬 참조가 비어있습니다" 로그 | `CubeFaceData` 에셋의 `Scene Reference`를 연결 안 했거나, `GameState`의 `Face Data` 배열에 안 넣었음 |
| "GameState가 씬에 없습니다" 로그 | `GameSystems`에 `GameState.cs`를 안 붙였음 |
| F4 눌러도 반응 없음 | `DebugOrbCheat.cs`가 씬에 없거나, Game 뷰에 입력 포커스가 없음(Game 뷰를 한 번 클릭) |
| 씬 파일을 `Scene Reference`로 드래그해도 안 걸림(회색으로 거부) | 그 씬이 5단계에서 Addressable로 등록 안 됐을 가능성 — `Groups` 창에서 확인 |
| Play 시작하자마자 콘솔에 에러가 잔뜩 뜸 | 대부분 위 표의 원인 중 하나 — 에러 메시지 맨 앞의 `[CubeMapManager]` 같은 태그로 어느 스크립트가 원인인지 먼저 확인 |
