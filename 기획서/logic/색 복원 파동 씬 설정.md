# 색 복원 파동 씬 설정 (수동, Unity 에디터에서 진행)

> 2026-08-16 작성 — v0.1 목표 ⑤ (마지막 단계)

## 왜 Shader Graph가 아니라 C#인가

[[11 셰이더 설계 - 색 복원 파동]] 원안은 URP Shader Graph(거리 마스크) + VFX Graph로 픽셀 단위 그라데이션을 구현하는 스펙입니다. 하지만 Shader Graph/VFX Graph 에셋은 텍스트로 직접 만들기엔 직렬화 포맷이 복잡해서, 손으로 잘못 만들면 Unity가 아예 못 여는 위험이 있습니다 (지금까지 겪은 Cinemachine 씬 설정 문제보다 훨씬 위험도가 높음).

그래서 v0.1에서는 **같은 시각적 목표(파동이 퍼지며 색이 돌아옴)를 순수 C#으로** 구현했습니다: 오브젝트별로 색을 Lerp하고, 가까운 것부터 시간차를 두고 칠합니다. GPU 셰이더의 매끈한 픽셀 단위 그라데이션은 아니지만 게임플레이 효과는 동일합니다. 나중에 진짜 Shader Graph로 업그레이드하고 싶으면 `PaintableObject.Paint()` API는 그대로 두고 내부 구현만 바꾸면 됩니다.

## 사전 준비 (이미 완료됨, 코드 쪽)

- [x] `PaintableObject.cs` — 회색 → 원래 색 페이드
- [x] `ColorWaveEffect.cs` — 거리순으로 시간차를 두고 `Paint()` 호출, 싱글톤
- [x] `ColorOrbPickup.cs` 수정 — 구슬 획득 시 `ColorWaveEffect.PlayWave()` 자동 호출하도록 연결

## 설정 순서

### 1. ColorWaveEffect 매니저 부착

1. Hierarchy에서 `GameSystems` 선택 (이미 있는 오브젝트 — [[logic/색 구슬 시스템 씬 설정]]에서 만든 것)
2. `Add Component → Color Wave Effect` 추가

### 2. 테스트용 PaintableObject 만들기

지금 씬엔 회색→색 전환을 보여줄 오브젝트가 없어서, 눈으로 확인하려면 몇 개 만들어야 합니다.

1. Hierarchy 빈 곳 클릭 → 선택 해제
2. `3D Object → Cube`를 3~4개 만들어서 Ground 위 여기저기(플레이어 시작 지점 주변)에 흩어놓기 — 거리를 다르게 둬야 "가까운 것부터 칠해지는" 느낌이 보입니다
3. 각 Cube에 `Add Component → Paintable Object` 추가
4. 각각 `True Color`를 서로 다른 색으로 설정 (예: 빨강, 파랑, 노랑, 초록)
5. (선택) `Ground` 자체에도 `Paintable Object`를 붙이고 `True Color`를 지금 Ground 색으로 지정하면, 바닥도 같이 회색→원래색으로 전환되는 걸 볼 수 있음

### 3. 확인

1. Play 버튼
2. 먹괴음을 처치해서 구슬을 획득
3. 획득한 자리를 중심으로, 가까운 Cube부터 순서대로 회색에서 원래 색으로 부드럽게 바뀌는지 확인
4. Console에 `"색 복원 파동 발생! 위치: ..."` 로그가 뜨는지 확인

## 트러블슈팅

| 증상 | 원인 | 해결 |
|------|------|------|
| 구슬을 먹어도 아무 색도 안 바뀜 | `ColorWaveEffect`가 씬에 없음 | 위 1번 단계 진행 |
| 색이 바뀌긴 하는데 전부 동시에 바뀜 | 오브젝트들이 서로 너무 가까이 있어서 `waveDuration`(1.5초) 안에 거리 차이가 안 느껴짐 | 오브젝트를 더 멀리 떨어뜨려 배치하거나, `ColorWaveEffect`의 `Wave Duration`을 늘려서 테스트 |
| 특정 Cube만 안 바뀜 | 그 Cube에 `Paintable Object`가 안 붙어있거나 `Renderer`가 없음 | 컴포넌트 부착 확인 |
