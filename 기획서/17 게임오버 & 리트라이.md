# 게임오버 & 리트라이

> 2026-05-29 재작성

## 게임오버 조건

- HP가 0이 됐을 때

## 게임오버 연출

1. 플레이어 캐릭터가 먹물에 잠기는 연출 (VFX Graph)
2. 화면 서서히 흑백으로 전환 (Post Processing — Saturation 0)
3. 화면 중앙에 먹물 번짐 효과와 함께 게임오버 패널 등장
4. 통계 표시: 도달한 층 / 처치한 먹괴음 수 / 복원한 색

## 게임오버 화면 버튼

| 버튼 | 동작 |
|------|------|
| 다시 시도 | 현재 세션 처음부터 재시작 (색 구슬 보유 초기화) |
| 타이틀로 | 메인 메뉴로 이동 |

> **[2026-08-25 정정]** 위 표의 "다시 시도" 동작과 아래 "리트라이 방식"은 **원래 기획 의도**이고,
> 실제 구현([[GameOverManager]])은 다름 — 죽으면 **죽은 면(Face)을 그 자리에서 재시작**할 뿐,
> 색 구슬 보유량이나 큐브 회전 상태는 초기화되지 않는다. 원래 [[changelog/2026-08-20_4층콘텐츠-준비]]에서
> "층별 콘텐츠를 만들어가는 개발 중 테스트 흐름이 끊기는 걸 막기 위한 임시 결정"으로 시작했지만,
> 검토 결과 이 방식을 **정식으로 채택**하기로 함 — "처음부터"는 패널티 없는 리트라이 취지와도
> 오히려 안 맞고(죽을 때마다 진행이 다 날아가면 사실상 패널티가 생김), "죽은 자리에서 재도전"이
> 더 플레이어 친화적이라 판단. "타이틀로" 버튼은 아직 타이틀 화면 자체가 없어서 미구현 상태.
>
> **실제 리트라이 방식(확정):**
> - 죽은 면을 그대로 다시 로드 (스폰 위치 복귀, HP 전체 회복)
> - 색 구슬 보유량 / 방문한 면 상태 / 큐브 회전 상태 **모두 유지** (초기화 안 함)
> - `floorNumber`/`visitCount` 증가 없음 (새로운 방문이 아니라 재시작이므로)
> - 아래 "리트라이 방식"·"게임오버 화면 버튼"의 "처음부터" 서술은 폐기, 대신 위 내용이 최종 스펙

## 리트라이 방식

**처음부터 재시작** (로그라이트 구조 없음) — ⚠️ 위 정정 메모 참고, 폐기된 원안

- 색 구슬 보유 현황 초기화
- 큐브 회전 상태 초기화
- 단, **색 도감 수집 기록**은 유지 (다회차 수집 동기 보존)
- 색 복원 기록 초기화 (다음 회차 새로운 탐색)

## 패널티

- 별도 패널티 없음
- 게임오버 시 즉시 재도전 가능
