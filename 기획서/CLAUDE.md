# 먹괴음 (Meokgoeeum) — 개인 프로젝트

## 프로젝트 개요

- **목적/목표:** Steam PC 출시용 3D 실시간 액션 RPG 완성
- **플랫폼:** PC (Steam)
- **완성 기준 (MVP):** v0.1 — 이동 + 전투 + 색 복원 파동 + 먹괴음 1종이 돌아가는 프로토타입
- **팀:** 1인 개발 (기획·프로그래밍) + 디자이너 친구 합류 협의 중

## 기술 스택

- **엔진:** Unity 6.3 LTS
- **렌더 파이프라인:** URP (Universal Render Pipeline)
- **주요 패키지:** Addressables, New Input System, Cinemachine, VFX Graph, Timeline, NavMesh, Unity Behavior (Preview)
- **서드파티:** DOTween, UniTask
- **언어:** C# 전용 (Blueprint 없음)
- **세이브:** JsonUtility → `Application.persistentDataPath`

## 엔진 선택 배경 (중요)

- UE5 → Unity 6.3 LTS로 전환 결정 (2026-05-29)
- **전환 이유:** 1인 개발 + C# 친숙 + Asset Store + 빠른 이터레이션
- **URP 선택 이유:** HDRP는 1인 개발에 설정 부담이 크고, 이 게임의 핵심 연출(색 복원 파동)은 URP Shader Graph로 충분
- Lumen(UE5) → APV + Shader Graph로 대체. 스타일라이즈드 아트 방향으로 한계 희석

## 게임 핵심 컨셉 (빠른 파악용)

```
장르:  3D 실시간 액션 RPG
배경:  조선 풍 현대 도시 (회색조 → 색 복원)
주인공: 붓을 무기로 쓰는 성인 (어린 시절 기억을 잃은 상태)
적:    먹괴음 — 먹물 괴물 5종 (평/원/흡/분/광)
핵심:  적 처치 → 색 구슬 드랍 → 파동 연출로 색 복원 → 맵 회전
반전:  이 세계는 큐브 1개. 탑이 아니라 큐브 면을 순환하는 구조
보스:  포(鯆) — 핑크 돌고래, 3페이즈, 플레이어의 옛 친구
```

## 개발 원칙

### 답변 형식
- 한국어로 답변
- 단순 질문은 바로 코드로 가도 됨
- 빠른 프로토타이핑 흐름 우선
- 왜 해당 코드를 작성했는지 설명 필수

### 설계 우선순위
1. 혼자 빠르게 만들 수 있는가
2. 혼자 유지보수 가능한 복잡도인가
3. 디버깅이 쉬운가
4. 나중에 확장/개선 가능한가

### 설계 방식
- 단순한 버전 먼저, 필요하면 더 구조적인 버전 선택지 제시
- 더 나은 패턴이 있으면 제안해도 되지만 혼자 감당 가능한 수준으로

### 금지
- 혼자 유지보수 불가능한 복잡도의 설계 강요
- 팀 협업 전제의 불필요한 추상화
