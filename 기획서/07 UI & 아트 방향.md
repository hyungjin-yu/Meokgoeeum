## 아트 방향

### 톤 방향

세계관 문서의 "조선 풍 현대 도시"를 어떤 톤으로 구현할지 확정했다.

처음에는 한국과 사이버펑크를 결합하는 방향으로 접근했지만 두 가지 이유로 순화했다. 이 문서가 이미 정한 레퍼런스인 Tunic과 Gris는 둘 다 차갑고 날카로운 디스토피아와는 결이 다르고, 이 게임은 힐링게임을 지향하므로 시안과 마젠타 네온, 각진 홀로그램 같은 사이버펑크 요소는 그 방향과 부딪힌다.

그래서 "조선 풍 도시 + 색을 되찾는 등불과 초롱" 톤으로 확정했다. 기존 UI 팔레트의 Warm Yellow #FFE082와도 자연스럽게 이어진다.

| 배제 | 채택 |
|------|------|
| 차갑고 날카로운 디스토피아 사이버펑크, 시안·마젠타 네온, 각진 홀로그램 | 한지 초롱, 처마 밑 등불, 창호지 안쪽에서 새어나오는 부드러운 빛 |

### 색채 설계

- **기본 상태:** 회색조 도시. 채도를 0으로 클램프하며 발광 오브젝트도 예외 없이 적용한다.
- **색 복원 후:** 선명하고 따뜻한 색감
- **번지는 질감:** 색이 각지게 켜지는 대신 칠해지듯 번지는 질감으로 표현한다. Gris를 참고해 파동 경계가 날카롭지 않고 부드럽게 스며드는 느낌을 낸다.
- **먹괴음:** 검정과 먹물 텍스처, 이동 시 먹물 흔적 파티클

### 발광 오브젝트 디자인 원칙

- 각진 네온튜브나 홀로그램 광고판은 쓰지 않는다.
- 한지 초롱, 처마 밑 등불, 창호지 안쪽에서 새어나오는 부드러운 빛을 기본형으로 삼는다.
- 무채색 상태에서도 발광체의 형태와 명암 대비는 뚜렷하게 유지한다. 채도가 없는 대신 형태로 존재감을 보완한다.

### 색-오브젝트 매칭 (확정, 2026-09-10)

[[04 색 구슬 시스템]]의 6색-스킬 매칭에 오브젝트를 붙였다. 정육점, 목욕탕, 가로등, 약국, 뒷골목 초롱까지 다섯이 모이면 "조선 풍 도시"의 동네 상점가 한 세트가 완성된다. 검정만 성격이 달라서, 발광 오브젝트를 따로 두지 않고 이펙트로 처리하기로 확정했다.

| 색 | 스킬 | 발광 오브젝트 |
|----|------|---------------|
| 빨강 | 강타 | 정육점, 포장마차 등불 |
| 파랑 | 흐름 | 목욕탕 굴뚝 네온사인 |
| 노랑 | 번쩍 | 가로등. 기준 팔레트 Warm Yellow #FFE082와 직결 |
| 초록 | 되살림 | 약국 네온사인 |
| 보라 | 왜곡 | 뒷골목 초롱 |
| 검정 | 먹물, 보스 특효 | 오브젝트 없음. 다른 5색은 "세계가 색을 되찾는다"는 개념이라 발광 오브젝트가 자연스럽지만, 검정은 "먹혀서 침식된다"는 반대 개념이라 성격이 다르다. 이미 복원된 오브젝트 위에 빛을 빨아들이며 덧씌워지는 네거티브 이펙트로 구현하고, 보스전 전용으로 한정한다 |

### 색감 기술 구현 방향

[[11 셰이더 설계 - 색 복원 파동]]의 `_WaveRadius` 기반 원형 파동 Lerp 셰이더를 그대로 확장한다. 네온 전용 셰이더를 새로 만들지 않고 Emission과 채도 채널만 추가한다.

- 기본 상태는 완전 무채색으로 클램프한다. 네온 계열 머티리얼도 예외를 두지 않는다.
- 파동의 Lerp 곡선은 선형 대신 ease-out으로 바꿔 색이 확 터지는 손맛을 낸다.

### 캐릭터

- 붓의 먹물이 전투 시 튀는 이펙트 (VFX Graph)
- 피격 시 회색 먹물이 묻는 시각 효과

- 큐브 경계 구역: 기하학적 패턴의 벽면

## 구조 제작 계획

건물을 벽, 지붕, 장식 부품으로 나누고 그리드와 소켓 규칙 기반 조립 방식으로 제작하고 맵을 구성한다.

- **핵심 모듈:** 기둥, 처마와 지붕, 한지창과 문, 벽체 패널, 기단. 이 중 지붕이 난이도와 재사용도가 가장 높다.
- **발광 레이어:** 초롱과 등불은 구조 모듈과 분리된 별도 프리팹으로 만든다. 같은 구조에 레이어 조합만 바꿔 변형을 만든다.

이 구조 제작 계획은 [[05 맵 시스템 - 큐브 구조]]의 맵 생성 방식과 이어진다.

### 1차 모듈 제작 완료 (2026-09-10)

정육점 골목 스타일 상가 건물을 기준으로 5개 핵심 모듈을 그리드 2m 단위로 제작했다. 기둥과 벽체를 건물 앞면(같은 Y 위치)에 맞춰 배치해, 옆에서 봤을 때 사이가 뚫려 보이는 문제를 해결했다. 기단과 지붕은 그리드 1칸짜리 조각으로 만들어서 옆으로 이어붙여도 단차 없이 연결되도록 했다 — 지붕 경사는 건물 길이(X) 방향이 아니라 깊이(Y) 방향으로만 기울어져서, 1칸으로 잘라도 단면이 동일하다.

- `Assets/Models/Environment/BuildingModules/Columns/Column_Straight_01.fbx`
- `Assets/Models/Environment/BuildingModules/Walls/Wall_Cell_01.fbx`
- `Assets/Models/Environment/BuildingModules/Windows/Window_Cell_01.fbx` — 프레임 + 십자 문살 + 유리 포함
- `Assets/Models/Environment/BuildingModules/Foundations/Foundation_Cell_01.fbx`
- `Assets/Models/Environment/BuildingModules/Roofs/Roof_Cell_01.fbx`
- `Assets/Models/Environment/BuildingModules/Building_StreetUnit_Demo.fbx` — 위 모듈로 3칸(벽-창문-벽)을 조립한 참고용 예시

모든 모듈은 바닥이 로컬 Z=0, 중심이 로컬 X=0에 오도록 정리해뒀다 — 기단 위에 기둥/벽(Z=0.2), 그 위에 지붕(Z=2.8)을 쌓는 식으로 Unity에서 붙이면 된다.

### 벽·창문 폭 조절 (2026-09-10, `ModularPanelWidth.cs`)

"건물 특성에 따라 벽/창문 길이를 조절하고 싶다"는 요청으로, 그리드 배수가 아닌 임의의 폭에도 대응할 수 있는 Unity 컴포넌트를 만들었다. `Assets/Scripts/Level/ModularPanelWidth.cs`.

원리는 UI의 9-slice와 같다. 자식 파츠를 세 역할로 나눈다.

| 역할 | 대상 | 폭이 바뀌면 |
|------|------|-------------|
| Stretch | 유리, 문살, 벽면(위/아래) | 늘어난 만큼 그대로 커짐 |
| Reposition | 좌우 세로 프레임 | 두께(스케일)는 고정, 바깥쪽으로만 밀림 |
| Fixed | 중앙 세로 문살 | 폭과 무관하게 그대로 |

기준 폭(`baseWidth`, 기본 2.0m = 그리드 단위)과 원하는 폭(`width`)의 차이만큼 Stretch 파츠는 스케일에 더하고, Reposition 파츠는 위치를 절반씩 밀어낸다. 비율(곱셈)이 아니라 차이(덧셈)로 계산하는 게 핵심 — 그래야 프레임 두께 같은 "폭이 바뀌어도 그대로여야 하는 값"이 같이 늘어나지 않는다.

**Unity에서 실제 검증 완료:** `Window_Cell_01`에 폭 2.0 → 3.0m로 늘려서 테스트. 프레임 두께(0.05m)는 그대로 유지되고, 유리·문살·벽면은 정확히 늘어난 만큼 커지고, 좌우 프레임은 대칭으로 바깥으로 밀려나는 것을 좌표값과 스크린샷 양쪽으로 확인했다. `Wall_Cell_01`은 파츠가 하나뿐이라 Stretch 규칙 하나만 걸면 된다.

이 작업 도중 모듈 export 좌표 버그도 하나 발견했다 — 처음 export한 모듈들이 로컬 원점이 아니라 데모 조립 당시의 절대 좌표(예: 창문 x=-3)를 그대로 갖고 있어서, 좌우 판정에 쓰는 부호 계산이 틀어졌다. Blender에서 각 모듈을 X 중심 0으로 재정렬해서 재출고했다.

**재사용 가능한 프리팹으로 저장 완료:** 매번 컴포넌트와 규칙을 다시 설정할 필요 없도록, 컴포넌트와 규칙이 이미 설정된 상태로 저장해뒀다.

- `Assets/Models/Environment/BuildingModules/Walls/Wall_Cell_Adjustable.prefab`
- `Assets/Models/Environment/BuildingModules/Windows/Window_Cell_Adjustable.prefab`

프리팹을 새로 꺼내서 `width` 값만 바꿔도 규칙 재설정 없이 바로 적용되는 것까지 확인했다(벽 2.0→4.0m, 창문 2.0→1.5m 축소도 프레임 두께 불변으로 정상 동작).

## 맵 회전 연출 UI

- 회전 전: 화면 테두리 해당 구슬 색 파동 효과 (글로우)
- 중앙: 색 복원 텍스트 페이드인 ("붉은 기억이 되살아났다")
- 회전 중: 화면 0.3초 암전 + 큐브 아이콘 (로딩 표시 대체)
- 회전 후: 새 맵으로 페이드인

## 폰트 & 언어

- 기본 언어: 한국어 (영어 추후 추가)
- **메인 UI:** 나눔스퀘어라운드 — 둥글고 아기자기, 가독성 높음
- **연출용 텍스트:** 온글잎 밀기름체 — 손그림 느낌 (내레이션, 보스 대사)

## 스킬 UI

- 인벤토리 없음
- 하단 구슬 슬롯 클릭 → 사용 가능한 스킬 목록 팝업
- 단축키(1~6)로도 즉시 발동 가능
- 구슬 슬롯 길게 누르면 **잠금(Lock)** 토글 — 잠긴 슬롯은 작은 자물쇠 아이콘 오버레이, 최대 2개까지 동시 잠금 가능 (→ [[02 플레이어 시스템]] "5슬롯 vs 6색" 절)

## Unity & Blender 구현 참고

- UI 시스템: **Unity UI Toolkit** 또는 **uGUI (Canvas)**
- 쿨타임 표시: Image Fill Amount 애니메이션
- 글리치 텍스트 내레이션: DOTween으로 텍스트 노이즈 효과
- 발광 오브젝트와 건물 모듈은 Blender에서 제작한 뒤 Unity로 임포트한다.

  - **Unity 구현 시 주의:** 머티리얼을 공유하는 구조라, 먹괴음이 여러 마리 동시에 존재할 때 `material` 직접 수정은 같은 색을 흡수한 다른 개체에도 전부 영향을 준다. 개체별로 독립된 색 상태를 가지려면 CLAUDE.md 코드 최적화 원칙대로 `MaterialPropertyBlock`으로 개체마다 따로 적용할 것
  - **뼈대(Armature) 추가 (2026-09-10):** "가만히 서서 공격하면 이상하다"는 지적으로 리깅 필요성 확인. 척추(골반-허리-가슴-목-머리)와 팔다리 관절마다 총 17개 본을 넣고, 각 블롭 오브젝트를 해당 본 하나에만 100% 가중치로 묶는 리지드 스키닝 방식 적용 — 각 부위가 이미 별도 오브젝트라 버텍스 페인팅 없이도 정확히 맞아떨어짐. 팔을 들어올리고 다리를 굽히는 테스트 포즈로 실제 독립 동작 확인, 레스트 포즈 복귀도 뒤틀림 없이 확인됨. **한계:** 부드러운 스키닝이 아니라 블롭이 통째로 본을 따라가는 방식이라, 팔꿈치처럼 크게 꺾이는 관절에서는 이음매에 틈이 보일 수 있음 — 완전히 매끄러운 관절이 필요해지면 메쉬를 합치고 버텍스 웨이트를 손으로 칠하는 작업이 추가로 필요
  - **Unity Humanoid 리깅 실제 검증 (2026-09-10):** 사용자가 보유한 에셋스토어 패키지(Kevin Iglesias, Human Melee Animations)로 실제 리타겟팅 테스트. Blender 본 이름을 Unity Humanoid 규격에 매핑해 Avatar를 유효하게 만들었지만, 1차 테스트에서 **메쉬가 뼈를 안 따라가는 심각한 버그 발견** — 블롭 오브젝트에 Transform(Location)이 미적용 상태로 남아있던 게 원인. 전체 메쉬에 `transform_apply`를 적용해 좌표를 베이크한 뒤 재수출하니 정상적으로 리타겟팅된 펀치 애니메이션이 재생됨을 확인. 앞/뒤 방향도 사용자 재확인 요청으로 정측면 직교 뷰로 검증 — 얼굴이 Unity 기본 정면(+Z)과 정확히 일치함을 확인(버그 아님). 상세: [[changelog/2026-09-10_먹괴음골렘-유니티리깅검증]]
