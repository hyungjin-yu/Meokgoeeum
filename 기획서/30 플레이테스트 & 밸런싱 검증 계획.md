# 플레이테스트 & 밸런싱 검증 계획

> 2026-08-16 신규 작성

## 왜 필요한가

[[14 밸런스 수치 시트]]는 모든 수치가 "미결 — 프로토타입 후 조정"이라고만 적혀 있다. **어떻게 조정할지 방법론이 없으면 "조정"은 감으로 하는 추측이 된다.** 이 문서는 그 방법론을 정의한다. 1인 개발이므로 QA팀 없이도 돌아가는 저비용 프로세스로 설계한다 (필러 4 준수).

## 테스트 단계

| 단계 | 시점 | 인원 | 목적 |
|------|------|------|------|
| 데일리 도그푸딩 | 매일 | 본인 1인 | 빌드가 "재미있게 느껴지는가" 마찰 로그 기록 |
| v0.1 코어감 테스트 | v0.1 완료 시 | 외부 3~5인 | 전투 타격감, 색 복원 연출의 첫인상 |
| v0.2 큐브 인지 테스트 | v0.2 완료 시 | 외부 5~8인 | **큐브 회전을 힌트 없이 스스로 눈치채는지** (필러 2 검증) |
| v0.3 서사 임팩트 테스트 | v0.3 완료 시 | 외부 8~10인 | 반복 층 내레이션의 타이밍이 적절한지, 몇 층에서 눈치챘는지 |
| v1.0 오픈 데모 | 출시 전 | Steam Playtest 프로그램 | 광범위 밸런스 데이터 수집 |

## 데일리 도그푸딩 — 마찰 로그

매 빌드 플레이 후 아래 형식으로 1줄씩 기록 (Obsidian `changelog/` 규칙과 별개로 `playtest/friction-log.md`에 누적):

```
YYYY-MM-DD | [구간] | [무엇이 걸렸나] | [가설: 왜?]
2026-08-20 | 3층 원거리 적 | 투사체가 너무 빨라 반응 불가 | Startup 20f가 부족한 듯, 25f로 조정 후 재확인
```

## 정량 지표 (텔레메트리)

전용 분석 SDK 없이, 로컬 JSON 로그 append 방식으로 충분하다 (스코프 절제 — 필러 4).

| 지표 | 수집 방법 | 활용 |
|------|-----------|------|
| 적 타입별 처치 소요시간(TTK) | 전투 시작/종료 타임스탬프 로그 | [[27 전투 프레임 데이터]] 밸런스 검증 |
| 사망 위치 (층 + 좌표) | 사망 이벤트 시 `SaveData` 스냅샷과 함께 기록 | 난이도 스파이크 구간 식별 |
| 층별 재시도 횟수 | `RetryCount` 카운터 | 과도하게 어려운 층 식별 |
| 스킬 사용 빈도 (색별) | 스킬 발동 이벤트 로그 | 특정 색 스킬이 안 쓰이면 밸런스 or 접근성 문제 의심 |
| 평균 세션 길이 | 세션 시작/종료 시각 | 페이싱 검증 (→ [[28 레벨 디자인 - 인카운터 페이싱과 블록아웃]] 긴장도 곡선과 대조) |

```csharp
// PlaytestLogger.cs (개념 스케치)
public static class PlaytestLogger
{
    public static void LogEvent(string eventType, Dictionary<string, object> data)
    {
        var entry = new { timestamp = DateTime.UtcNow, eventType, data };
        File.AppendAllText(LogPath, JsonUtility.ToJson(entry) + "\n");
    }
}
```

## 밸런스 조정 루프

```
① 가설 수립 ("원거리 적 대미지가 너무 높은 것 같다")
② 변수 1개만 변경 (다른 수치는 고정)
③ 동일한 3~5인 테스터로 재테스트
④ TTK / 사망 위치 데이터 비교
⑤ 개선 확인 시 확정, 아니면 다음 가설로
```

> **한 번에 여러 수치를 바꾸지 않는다.** 뭐가 효과를 냈는지 알 수 없게 된다.

## 표준 설문 (v0.2 이후 매 테스트 공통)

1. 전투에서 가장 답답했던 순간은? (자유 서술)
2. 몇 층에서 처음 "어? 여기 아까 그곳 아닌가?"라고 느꼈나요? (→ 필러 2 직접 검증)
3. 색 스킬 중 안 쓰게 되는 게 있었다면 어떤 색인가요?
4. 색을 구분하는 데 어려움이 있었나요? (있다면 → [[25 색맹 접근성 설계]] 검토 대상자로 별도 인터뷰)
5. 다시 하고 싶은 마음이 들었나요? (뉴게임+ 동기 검증)

## 도구

- **색맹 검증:** Color Oracle / Sim Daltonism (무료) — 매 마일스톤 스크린샷 검수
- **성능 프로파일링:** Unity Profiler (내장) — 별도 툴 도입 없이 충분
- **로그 분석:** JSON 로그를 스프레드시트로 import 후 수동 검토 (전용 분석 대시보드는 이번 스코프에서 제외 — [[29 개발 리스크 진단 & 스코프 컷 계획]] WON'T 항목과 동일 기조)
