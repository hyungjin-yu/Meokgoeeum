# ColorSkillController를 큐브 프로토타입에 연결

## 배경

[[changelog/2026-09-16_흡-플레이어색흡수재설계]]에서 `SC_CubePrototype`에 색 구슬 시스템을 최소 연결했지만, 실제로 구슬을 스킬로 소모하는 `ColorSkillController`는 `[RequireComponent(typeof(PlayerController))]`/`[RequireComponent(typeof(CharacterController))]` 때문에 큐브 워커(`CubeSurfaceWalker`, `PlayerController`도 `CharacterController`도 안 씀)에 붙일 수 없어서 그동안 스킵해뒀던 항목.

## 작업

[[BrushWeapon]]이 같은 문제를 이미 겪고 해결해둔 패턴을 그대로 재사용:

- `[RequireComponent]` 두 개 제거.
- 입력: `PlayerController`가 있으면 그 `InputActions`를 공유(기존과 동일), 없으면 자체 `PlayerInputActions` 인스턴스를 만들어 `Enable()`/`OnDestroy()`에서 직접 관리.
- 강타(빨강)의 대시 이동: `CharacterController`가 있으면 기존대로 `cc.Move()`, 없고 `CubeSurfaceWalker`가 있으면 신규 `CubeSurfaceWalker.ExternalStep(Vector3 worldDelta)`로 대신 이동.
- `CubeSurfaceWalker.ExternalStep()`: 이동량을 현재 면의 접선 평면에 투영(면 밖으로 안 뜨게) → 위치에 더함 → `ClampToSurface()`(기존 Update() 끝부분 클램프 로직을 재사용 메서드로 분리)로 표면에 재보정.
- `CubeSurfaceWalker.Update()`가 대시 중(`skills.IsDashing`)엔 WASD 이동을 무시하도록 수정 — `PlayerController.Move()`가 강타 대시 중 자기 이동을 양보하는 것과 동일한 목적(두 이동 로직이 같은 프레임에 서로 다투지 않게).
- 대미지 판정([[BrushWeapon]]과 동일한 이유): `DamageAll()`/`CastFlash()` 양쪽에 `cubeWalker != null`일 때만 [[ICubeFaceMob]] 같은 면 검사 추가.
- 덤: `CastFlow()`(흐름)의 판정 박스가 `Vector3.up`을 기준으로 `LookRotation`하고 있었는데, 큐브 옆면/윗면에서는 "위"가 월드 Y가 아니므로 `cubeWalker.CurrentSurfaceNormal`을 up으로 쓰도록 수정(평지 던전은 그대로 `Vector3.up`).

## 검증

`CubeWalker_Player`에 `ColorSkillController` 부착 후(런타임에 `add_component`로 붙임 — `[RequireComponent]` 없이도 `CharacterController`/`PlayerController`가 자동으로 안 딸려오는 것 확인) 리플렉션으로 직접 3개 스킬을 캐스팅:

- 강타(빨강): 시전 → 좌표가 정확히 5유닛(대시 거리) 이동, 대시 후에도 `transform.position`이 여전히 표면 위(z=18 고정)에 유지됨을 확인. `IsDashing`이 대시 종료 후 정확히 `false`로 복귀.
- 흐름(파랑)/번쩍(노랑): 둘 다 예외 없이 시전, 대미지 배율(x1.5/x1.0)도 정확히 반영됨. 번쩍은 근처 몹 1대 명중까지 확인.
- 콘솔 에러 레벨 로그 0건.

## 남은 것

- **씬 변경 미커밋** — `CubeWalker_Player`에 `ColorSkillController`를 붙인 건 `SC_CubePrototype.unity`에만 반영돼 있고, 이 씬 파일은 유니티짱 테스트 변경들이 누적된 채로 계속 로컬 미커밋 상태라 이번에도 같이 커밋 안 됨. **다른 환경에서 씬을 새로 받으면 `CubeWalker_Player`에 `ColorSkillController`를 다시 붙여야 함.**
- 사용자가 실제 플레이로 1/2/3 키 스킬 사용감 확인 필요(자동화 테스트는 리플렉션으로 직접 메서드를 호출해 검증한 것이라 실제 키 입력 체인까지는 확인 못 함).
