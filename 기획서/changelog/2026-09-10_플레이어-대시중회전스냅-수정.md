# 플레이어 회전 관련 버그 3건 수정

## 배경

먹괴음 5종에 실제 모델+애니메이터를 연결한 뒤 사용자가 직접 플레이하며 "스킬을 쓰거나 공격을 할 때 캐릭터가 홱홱 움직인다", "A/D를 누르면 영상처럼 움직인다", "락온을 걸면 순간적으로 이동한다"는 세 가지 증상을 순서대로 리포트했다. 조사해보니 서로 다른 세 가지 원인이 얽혀있었다.

## 버그 1 — A/D 스트레이프 시 몸이 홱 돎 (근본 원인)

`PlayerController.Move()`가 캐릭터를 **이동 방향**(`moveDir`)으로 회전시키고 있었다. [[16 조작 설계]]는 "3인칭 숄더뷰 + 카메라 방향 기준 이동"으로 명시돼있는데, 이 설계에서는 캐릭터가 항상 **카메라가 보는 방향**을 향해야 하고 스트레이프는 몸을 돌리지 않고 옆으로만 이동해야 한다. 그런데 실제로는 A(왼쪽)/D(오른쪽) 스트레이프 입력이 카메라 기준 정반대 방향이라, A→D로 바꾸는 순간 캐릭터가 거의 180도를 회전 속도(720°/s) 그대로 0.25초 만에 홱 돌았다.

플레이어가 기존엔 아무 모델 없는 캡슐이라 회전이 안 보여서 아무도 몰랐다가, 먹괴음 5종에 실제 모델이 붙으면서 처음엔 "적이 이상하게 움직인다"로, 이어서 "플레이어가 이상하게 움직인다"로 리포트가 들어옴 — 두 리포트 모두 결국 이 설계 이슈의 서로 다른 측면이었다(먹괴음 쪽은 넉백 후 NavMeshAgent.Warp 회전 재정렬, 플레이어 쪽은 이동방향 기준 회전).

**수정**: 회전 타겟을 `moveDir` → `camForward`로 변경. 이제 A/D는 몸을 안 돌리고 옆으로만 이동한다.

## 버그 2 — 강타(빨강) 대시 중 락온 회전이 요동침

`PlayerController.Move()`는 강타 대시 중(`ColorSkillController.IsDashing`) 이동/회전을 전부 양보하도록 이미 돼있었는데, `LockOnController.FaceTarget()`은 그걸 모르고 매 프레임 계속 타겟을 바라보도록 회전시키고 있었다. 대시로 타겟에 빠르게 접근하며 스쳐 지나가면, 가까운 거리에서는 위치가 조금만 바뀌어도 상대 각도가 급격히 바뀌어서 회전이 요동친다.

**수정**: `LockOnController`도 `ColorSkillController.IsDashing`을 참조해서 대시 중엔 `FaceTarget()`을 건너뛰도록 수정.

## 버그(아님) — 락온을 걸면 순간 이동하는 것처럼 보임

"락온 거는 순간 위치가 튄다"는 리포트를 받고 실제로 위치가 바뀌는지부터 실측했다. Play 모드에서 `LockOnController.SetCurrentTarget()`/`Update()`를 리플렉션으로 직접 호출해 프레임을 수동으로 40번 진행시키며 `transform.position`을 매 스텝 기록:

```
시작: pos=(3.41, 1.08, 0.09) rot.y=0.00
step3:  pos=(3.41, 1.08, 0.09) rot.y=302.40
step7:  pos=(3.41, 1.08, 0.09) rot.y=244.80
step11: pos=(3.41, 1.08, 0.09) rot.y=187.21
step15~39: pos 동일, rot.y=183.49로 수렴
```

**position은 40프레임 내내 단 한 번도 안 바뀌었다.** 락온 관련 코드 어디에도 `transform.position`을 건드리는 곳이 없다는 코드 검토와도 일치 — 실제 버그가 아니었다. 대신 `rotationSpeed=720°/s`가 너무 빨라서, 락온 순간 캐릭터가 반바퀴 가까이(183도) 0.25초 안에 도는 것 + 이를 따라가는 카메라가 같이 홱 돌면서 "순간 이동"처럼 느껴진 것으로 결론.

**수정**: `LockOnController.rotationSpeed` 720 → 300으로 완화(반바퀴 도는 데 약 0.6초).

## 검증

- 3건 전부 수정 후 재컴파일 성공, 콘솔 에러 없음
- 버그 3(락온 순간이동)은 리플렉션으로 `Update()`를 프레임 단위로 강제 진행시켜 `position`이 실제로 안 바뀜을 직접 실측 — "리포트된 증상 = 실제 버그"라고 바로 믿지 않고 숫자로 재확인한 사례

## 시행착오

- Unity CLI `eval` 호출은 서로 다른 별도 호출 사이에 실제 게임 프레임이 거의 진행되지 않는 경우가 있었음(원인 미상, 이 자동화 환경의 타이밍 특성으로 추정) — `MonoBehaviour.Update()`를 리플렉션으로 직접 가져와 **한 eval 호출 안에서 반복 호출**하는 방식으로 우회해서 결정적으로 검증함(이전에 Animator.Update()로 애니메이터 전이를 검증했던 것과 같은 패턴)
- 재컴파일은 실행 중인 Play 모드를 강제로 멈춘다 — 사용자가 실제로 플레이하며 리포트하는 도중에 두 번 정도 모르고 재컴파일해서 세션을 끊었음. 다음부터는 재컴파일 전에 미리 안내할 것
