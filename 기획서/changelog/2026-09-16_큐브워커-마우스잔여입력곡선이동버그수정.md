# 큐브 워커 — Play 시작 직후/커서 잠금 풀림 시 마우스 잔여 입력으로 곡선 이동하던 버그 수정

## 배경

[[changelog/2026-09-16_큐브워커-탱크조작재설계]]의 "정정" 이후 조작 방식은 젤다/다크소울 스타일(카메라 기준 이동 + 이동 방향 자동 회전)로 확정됐는데, 사용자가 실제 플레이에서 "D만 눌러도 캐릭터가 둥글게 곡선으로 움직인다"고 계속 리포트함. 여러 차례에 걸쳐 원인을 좁혀나감:

1. **1차 원인 — Play 진입 직후 잔여 마우스 입력.** 콘솔 로그로 확인해보니 실제 마우스 델타(`rawMouseX`)는 0인데, `smoothedMouseX`(저역 통과 필터 상태값)가 -10 근처에서 시작해서 1초 넘게 걸려 서서히 0으로 줄어들며 그동안 `cameraForward`를 계속 회전시키고 있었음. Play 버튼을 누르려고 마우스를 움직인 잔여 입력이나 커서 잠금 시점의 워프가 원인으로 추정. 처음엔 "첫 5프레임만 무시"로 고쳤는데 턱없이 부족해서(감쇠에 1초 넘게 걸림), 프레임 수 대신 **실제 경과 시간 1초** 기준으로 바꿈.
2. **2차 원인 — 커서 잠금 풀림.** 사용자가 보내온 테스트 영상 프레임에 마우스 커서(흰 화살표)가 떠 있는 게 보여서 라이브로 `Cursor.lockState`를 확인해보니 `None`(풀림) 상태였음. Esc를 눌렀거나 Game 뷰 포커스를 잃으면 풀리는데, 풀린 채로는 녹화 중 손이 마우스에 살짝만 스쳐도 그 움직임이 그대로 카메라 회전에 들어감. **커서가 실제로 Locked 상태일 때만** 마우스 입력을 반영하도록 게이트를 추가.

## 검증

사용자 주장("마우스는 문제없다")과 로그 데이터가 충돌하는 상황이라, 판단을 사용자에게 맡기지 않고 직접 증명하는 쪽으로 전환:

- 이동 중 매 0.15초마다 실제 좌표에 빨간 구슬(콜라이더 없는 임시 Sphere)을 남기는 디버그 코드를 추가하고, Unity CLI로 Scene 뷰 카메라를 이동면과 정면으로 맞춰 캡처 → **여러 방향키를 번갈아 누른 구간은 실제로 꺾인 경로(사용자가 곡선으로 인지한 것)**, **진짜 D 하나만 누른 구간은 완벽한 직선**으로 명확히 구분됨.
- 콘솔 로그(`moveInput`/`rawMouseX`/`cameraForward`)를 직접 대조해서, "곡선으로 보였던" 구간은 실제로 WASD를 대각선 포함해 계속 바꿔가며 누른 입력이었고, 그 전체 구간 동안 `cameraForward`는 부동소수점 단위까지 완전히 고정돼 있었음을 확인. 반대로 순수 D 구간은 카메라·좌표 모두 흔들림 없이 직선.
- 위 두 수정(1초 무시 + 커서 잠금 게이트) 적용 후 재테스트한 순수 D 구간에서 `cameraForward=(0.00, 1.00, 0.00)` 고정, 좌표가 일정 간격으로만 변하는 것을 로그와 Scene 뷰 캡처 양쪽으로 확인.

## 한계 / 교훈

- 사용자가 "마우스는 무관하다"고 확신했지만, 실제로는 Play 세션 중 다른 시점(창 포커스 전환, Esc 등)에 커서 잠금이 풀려 있었던 게 로그로 명백히 드러난 사례 — 사용자의 주관적 확신과 실측 데이터가 어긋날 때는 어느 쪽이 옳은지 논쟁하지 말고, 반박 불가능한 실측 증거(좌표 궤적 시각화, 원본 입력 로그)를 직접 만들어서 보여주는 쪽이 훨씬 빠르고 정확했음.
- 임시 디버그 코드(콘솔 로그, 빨간 구슬 마커)는 검증 후 전부 제거하고 실제 수정 코드만 커밋함.
