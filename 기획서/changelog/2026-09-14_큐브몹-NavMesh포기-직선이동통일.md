# 큐브 면 몹 — NavMeshAgent 포기하고 직선 이동 방식으로 통일

## 배경

실제 `EnemyPyeong` 프리팹을 NavMesh 면 위에 세워 사용자가 직접 Play로 테스트했는데, "5초가 지나도 평은 가만히 있는데?"라는 리포트. 확인해보니 Console에 계속 이런 에러가 찍히고 있었음:

```
"SetDestination" can only be called on an active agent that has been placed on a NavMesh.
"IsStopped" can only be called on an active agent that has been placed on a NavMesh.
```

`NavMeshAgent`가 NavMesh에 안 붙은 상태(`isOnNavMesh=false`)였음. 실제 Play 세션에 직접 붙어서 진단:

- 그 위치가 유효한 NavMesh 지점이라는 건 `NavMesh.SamplePosition()`으로 확인됨(0.4유닛 거리)
- agentTypeID, 레이어 마스크, `navMeshData` 존재 여부 — 전부 정상적으로 일치
- `agent.Warp()`를 정확한 navmesh 지점으로 다시 호출해도 계속 실패

설정상 문제가 전혀 안 보이는데도 바인딩이 안 되는 상황 — 원인 불명. 사용자에게 "더 깊이 파볼지, NavMeshAgent 자체를 포기하고 이미 검증된 방식으로 통일할지" 선택지를 제시했고, **후자를 선택**.

## 결정 — NavMeshAgent 없이 5종 몹 AI를 통일

[[CubeFaceLockedMob]](직선 이동 + 면 경계 clamp, [[changelog/2026-09-12_면고정몹-수색복귀AI]]에서 완전히 검증됨)을 재사용 가능한 베이스로 일반화해서, 몹마다 다른 전투 상태머신(윈드업/액티브/리커버리 등)을 얹을 수 있게 함.

## 결과물

- `Assets/Scripts/Player/CubeEnemyBase.cs` 신규 — [[CubeFaceLockedMob]]의 이동/면 고정/수색·복귀 상태 머신을 그대로 가져오되, `OnChasingTick()`/`OnBusyTick()` 가상 메서드를 추가해서 서브클래스가 "사거리 안에 들어오면 공격으로 전환" 같은 로직을 얹을 수 있게 확장. Busy 상태일 땐 베이스가 이동을 멈추고 서브클래스가 전권을 가짐 — 원본 `EnemyBase`/`EnemyPyeong`의 "공용 인프라 vs 종별 전투 로직" 분리 구조와 같은 발상.
- `Assets/Scripts/Player/CubeEnemyPyeong.cs` 신규 — 원본 [[EnemyPyeong]]과 전투 타이밍(윈드업 15/60초, 액티브 4/60초, 리커버리 14/60초)·데미지·판정 반경까지 완전히 동일, 이동만 `CubeEnemyBase`로 교체.
- `Assets/Scripts/Editor/CubeEnemyPyeongTestBuilder.cs` 신규 — 고장난 NavMesh 버전(`TestRealEnemy_Pyeong`)을 지우고, `EnemyPyeong.prefab`을 인스턴스화한 뒤 NavMeshAgent/`EnemyPyeong`/`EnemyHealth` 컴포넌트만 떼어내고 `CubeEnemyPyeong`을 붙임 — 리깅된 모델/애니메이터 자식은 그대로 재사용(신규 오브젝트 `CubeTestEnemy_Pyeong`).

## 검증 — 리플렉션으로 전체 상태머신 통과 확인

`CubeEnemyBase.Update()`를 리플렉션으로 반복 호출 + 내부 필드(`phase`/`phaseTimer`) 직접 세팅해서 7단계 전부 확인:

1. Idle → Chasing (같은 면 진입)
2. Chasing 중 사거리 진입 → Busy(Windup) 전환
3. Windup 시간 초과 → Active
4. Active 시간 초과 → Recovery
5. Recovery 시간 초과 → 다시 Chasing
6. 면 이탈 → Searching (베이스 상속 로직도 정상)
7. 재등장 → Chasing

NavMeshAgent에 전혀 의존하지 않으므로, [[changelog/2026-09-14_NavMesh-면단위-장애물회피검증]]에서 겪었던 "isOnNavMesh 바인딩 실패" 문제 자체가 구조적으로 발생할 수 없음.

## 한계 / 다음 작업

- 장애물 회피가 없음(직선 이동 + clamp뿐) — 큐브 면 안에 복잡한 장애물이 있는 방은 이 방식으론 부자연스러울 수 있음. 지금까지 만든 면들은 장애물이 단순해서 우선 이 방식으로 진행, 필요해지면 재검토.
- 나머지 4종(Won/Bun/Heup/Gwang)은 아직 `CubeEnemyBase` 버전으로 안 옮김 — `EnemyPyeong`이 가장 단순한 사례라 먼저 검증. 나머지는 각자의 고유 로직(원거리 투척/분열/흡수/광역기)을 `OnChasingTick`/`OnBusyTick`에 맞게 이식하는 후속 작업.
- 실제 Play에서 움직임/공격이 자연스러운지는 사용자가 직접 확인 필요 — `SC_CubePrototype.unity`의 `CubeTestEnemy_Pyeong`(+Z 면).
- 기존 평지 던전의 `EnemyBase`/`EnemyPyeong`(NavMeshAgent 기반)은 전혀 안 건드림 — 완전히 별도 클래스 체계라 영향 없음.
