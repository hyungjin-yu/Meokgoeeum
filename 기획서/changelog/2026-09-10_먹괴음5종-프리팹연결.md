# 먹괴음 5종 실제 게임플레이 프리팹 연결

## 배경

지금까지 만든 5종 Blender 모델(+Humanoid Avatar 설정)은 raw FBX 상태로만 존재했고, 실제 게임에서 스폰되는 건 `Assets/Scenes/Enemy{Pyeong,Won,Heup,Bun,Gwang}.prefab` — `RandomEncounterBatchTool.cs`가 실제로 참조하는 라이브 프리팹 5개였다. 이 프리팹들은 여전히 Unity 기본 Capsule 프리미티브(회색 플레이스홀더)를 쓰고 있었으므로, 진짜 모델로 교체했다.

## 기존 프리팹 구조 확인

5개 프리팹 전부 동일한 패턴: 루트 GameObject에 MeshFilter(Capsule)+MeshRenderer+CapsuleCollider(`radius=0.5, height=2, center=0`)+NavMeshAgent+EnemyHealth+EnemyXXX 스크립트가 한 오브젝트에 몰려있는 구조. 플레이어의 CharacterController도 동일하게 `height=2, radius=0.5, center=0`— 이 2m 캡슐 컨벤션이 플레이어·5종 몹 전체에 일관되게 적용돼 있어서 임의값이 아니라 의도된 기준으로 판단, 유지하기로 함.

## 작업 내용

각 프리팹에 대해 `PrefabUtility.LoadPrefabContents`로 편집 모드 진입 후:

1. 루트의 플레이스홀더 MeshFilter/MeshRenderer 제거 (CapsuleCollider/NavMeshAgent/EnemyHealth/EnemyXXX 스크립트는 그대로 유지)
2. 실제 리깅된 모델(`InkGolem_*_01.fbx`)을 자식으로 부착
3. 자식의 렌더러 바운드를 측정해 스케일·위치 자동 계산: `scale = 2 / 모델실측높이`, 발이 캡슐 바닥(로컬 Y=-1)에 오도록 `childY = -1 - (로컬최소Y × scale)`
4. Animator 컴포넌트에 이미 설정해둔 Avatar 연결
5. `SaveAsPrefabAsset`으로 저장

각 캐릭터의 실측 높이가 조금씩 달라서(원 1.24m, 흡 1.21m, 분 1.26m, 광 1.22m, 평 1.19m — 장식 파츠가 바운드에 포함되기 때문) 스케일도 종별로 다르게 계산됨(1.59~1.68배). 적용 후 전부 로컬 Y 범위가 정확히 -1.000~1.000으로 캡슐과 맞아떨어짐을 재측정으로 검증.

## 버그(아님) — Gwang이 여전히 캡슐로 보임

5종을 한 화면에 나란히 배치해 스크린샷을 찍었는데, 오른쪽 끝(Gwang 자리)이 여전히 회색 캡슐로 보여서 "Gwang만 실패했나" 의심. 프리팹 에셋과 씬의 라이브 인스턴스를 재귀적으로 전부 덤프해봤지만 구조·메쉬·머티리얼 전부 정상이었음. 씬 전체를 "Capsule" 메쉬로 검색해보니 원인 파악 — **그 캡슐은 Gwang이 아니라 씬에 원래 있던 플레이어의 플레이스홀더 캡슐**이었고, Scene View 카메라 각도상 우연히 화면상 같은 자리에 겹쳐 보인 착시였음. 미리보기 오브젝트들을 플레이어와 완전히 다른 위치(Y=51)로 옮겨서 재캡처하니 5종 전부 정상적으로 보임 — 실제 버그는 없었고 카메라 원근에 의한 착시였다.

## 검증

- 콘솔 에러 없음 확인 (`get_console_logs`)
- `LockOnController`/`LockOnMarkerUI`가 루트 Transform 위치만 참조하고 자식 모델 구조에 의존하지 않음을 코드로 확인 — 구조 변경이 락온 시스템에 영향 없음
- `EnemyBun.SplitOnDeath()`가 `Instantiate(gameObject, ...)`로 루트 전체(자식 모델 포함)를 복제하고 `clone.transform.localScale`만 바꾸는 방식이라, 분열 미니언도 모델이 비례대로 같이 축소됨을 코드 검토로 확인(런타임 테스트는 별도)

## 결과물

`Assets/Scenes/Enemy{Pyeong,Won,Heup,Bun,Gwang}.prefab` 5개 갱신 — 이제 플레이스홀더가 아니라 실제 리깅된 모델을 보여줌.

## 교훈

- **`Renderer.bounds`는 항상 월드 스페이스다.** 프리팹 편집 모드에서 루트가 원점이 아닌 임의의 저장된 위치(예: (3,1,3))에 있을 수 있어서, 자식의 "로컬 위치"를 계산하려면 반드시 `월드바운드 - 루트.position`으로 변환해야 한다 — 처음에 이걸 놓쳐서 평 프리팹의 모델이 캡슐 훨씬 아래(Y=-2.62)에 배치되는 버그가 났었음, 재측정 검증으로 바로 잡음
- **Scene View 스크린샷에서 이상해 보이는 오브젝트를 발견하면, 그 오브젝트 자체를 의심하기 전에 "정말 그 오브젝트가 맞는지"부터 확인할 것.** 카메라 원근 때문에 실제로는 다른 오브젝트(이번엔 플레이어 캡슐)가 화면상 같은 자리에 겹쳐 보일 수 있다 — 헷갈리면 대상들을 서로 완전히 분리된 위치로 옮겨서 재확인하는 게 가장 확실함
- `GameObject.FindObjectsByType`로 순회하며 그 안에서 일부를 `DestroyImmediate`하면, 이미 파괴된 자식 오브젝트가 배열 뒤쪽에 남아있다가 접근 시 예외가 난다 — 순회 중 파괴가 섞이면 매번 `if (o == null) continue;` 가드를 넣을 것
