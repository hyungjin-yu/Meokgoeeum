# 유니티짱 에셋 임시 적용 테스트 — 스폰 회전 버그 발견·수정

## 배경

사용자가 테스트용으로 유니티짱(unity-chan!) 에셋을 프로젝트에 추가하고 "플레이어를 유니티짱으로 바꾸고 진행해"로 요청. **사용자 확인: 최종적으로는 다른 플레이어 모델을 쓸 예정이고, 이번 건 순수 테스트용** — 그래서 에셋 자체(218MB)는 저장소에 커밋하지 않고 `.gitignore`에 추가함(기존 "서드파티 에셋스토어 패키지는 저장소에 안 넣는다" 관례 그대로 따름).

## 진행 및 발견 사항

1. `CubeWalker_Player`(큐브 프로토타입)의 기존 캡슐 시각 표현(MeshFilter/MeshRenderer)을 제거하고, `unitychan.prefab`을 자식으로 붙임.
2. **머티리얼이 전부 마젠타(깨짐)로 렌더링됨** — 유니티짱 에셋의 기본 셰이더(`UnityChan/Skin`, `UnityChan/Hair - Double-sided` 등)가 Built-in RP 전용인데 이 프로젝트는 URP를 씀. 9개 머티리얼 전부 URP Lit로 전환(텍스처/투명도/양면 옵션 이관)해서 해결.
3. **기본 애니메이터 컨트롤러("UnityChanARPose")가 팔이 기괴하게 늘어난 포즈를 보여줌** — AR 데모용 컨트롤러라 이 프로토타입엔 안 맞음. 로코모션용 대체 컨트롤러("UnityChanLocomotions")로 교체해서 자연스러운 대기 포즈로 해결.
4. **`InvalidOperationException` 스팸** — 유니티짱 번들 스크립트 `IdleChanger.cs`/`FaceUpdate.cs`가 구식 `UnityEngine.Input`을 쓰는데, 이 프로젝트는 새 Input System 전용으로 설정돼있어서 충돌. 둘 다 키/마우스로 수동 트리거하는 데모 전용 기능(게임플레이 무관)이라 안전하게 제거.
5. **⚠️ 진짜 버그 발견 — 스폰 직후(첫 이동 전) 회전이 면 기준과 안 맞음.** 캐릭터가 옆으로 누운 것처럼 보임 — 수치로 확인해보니 발이 실제 큐브 표면보다 거의 1유닛 위에 떠 있었음(다리가 뻗은 방향이 표면 법선이 아니라 월드 Y축을 향하고 있었음). 원인: `CubeSurfaceWalker.Start()`가 `facingForward`/`CurrentSurfaceNormal` 같은 내부 추적용 상태만 계산하고 실제 `transform.rotation`은 전혀 안 건드리고 있었음 — 회전 보정은 `Update()`의 이동 로직에서만 걸리므로, 스폰 직후 첫 이동 전까지는 에디터에 저장된 회전값(보통 identity)이 그대로 노출됨. 캡슐(회전 무관하게 대칭이라 안 티남)로는 몇 주간 안 드러났던 버그가 비대칭 캐릭터 모델을 붙이자마자 바로 드러남. `Start()` 끝에 `transform.rotation = Quaternion.LookRotation(facingForward, CurrentSurfaceNormal);` 추가로 수정.

## 검증

- 발 본(`Animator.GetBoneTransform(HumanBodyBones.LeftFoot)`) 월드 좌표와 면 법선 방향 좌표를 직접 비교 — 수정 전 발이 표면보다 0.97유닛 위, 수정 후 0.08유닛 위(거의 표면에 닿음, 잔여 오차는 발목 본과 실제 신발 밑창 사이의 리깅 차이로 추정)로 확인.
- 스크린샷으로 정면/측면에서 자연스럽게 서있는 포즈, 정상 재질(마젠타 없음) 확인.
- 재확인 Play 세션에서 `InvalidOperationException` 재발 안 함 확인.

## 결과물 (커밋됨)

- **`CubeSurfaceWalker.cs`** — 스폰 회전 초기화 버그 수정. 이건 유니티짱과 무관하게 앞으로 어떤 실제 캐릭터 모델을 최종적으로 쓰든 그대로 유효한 수정.
- **`.gitignore`** — `/Assets/unity-chan!/` 제외 추가.

## 결과물 (커밋 안 함 — 로컬 테스트 상태로만 남음)

- `SC_CubePrototype.unity`의 `CubeWalker_Player`에 유니티짱 모델이 자식으로 붙어있는 상태, 머티리얼/컨트롤러 교체, 데모 스크립트 제거 — 전부 씬 파일에는 저장돼있지만(사용자가 계속 테스트할 수 있도록) git에는 커밋 안 함. 나중에 실제 플레이어 모델이 정해지면 이 씬 변경분은 그대로 새 모델로 교체될 예정.
