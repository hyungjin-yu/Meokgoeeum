# 먹괴음 흡(흡수형) 제작 완료

## 배경

[[07 UI & 아트 방향]] 계획대로 리깅된 `InkGolem_Pyeong_01`을 베이스로 한 두 번째 변형종 "흡"(흡수형) 제작. 흡은 "HP 낮을 시 색 복원 구역에 접근해 회복"하는 타입으로, 원(대포팔)과 실루엣이 확실히 구분되는 방식이 필요했다.

## 디자인 방향 결정

사용자에게 세 가지 안(① 놀랍게 커진 손/팔 ② 등·가슴의 흡수구 ③ 등에서 뻗어나온 먹물 촉수)을 제시해 ①번 "놀랍게 커진 손"으로 확정. 근접형처럼 보이지 않도록 팔 길이는 평/원과 동일하게 유지하고 손만 과장하는 방향.

## 제작 내용

- Pyeong 베이스를 새로 import해 `InkGolem_Heup_*`로 개명 (오브젝트/메쉬/머티리얼/Armature 데이터 블록 이름까지 전부 정리)
- 양손(L_Hand/R_Hand)을 손목 쪽 앵커(포워암과 맞닿는 윗면 중심)를 고정점으로 삼아 X/Y 2.6배, Z 1.8배로 확대 — 앵커를 고정하고 확대해서 손목 이음매는 그대로 유지한 채 손만 커지도록 함
- 손바닥이 향하는 쪽(앞면) 표면의 돌출량을 거리 비례로 줄여 오목한 "빨아들이는 손" 형태 구현
- 물방울 손끝(Drip)도 같은 방식으로 확대해 커진 손 바닥에 재부착 (임베드 0.015m 유지)
- 팔 전체(윗팔~손끝)를 어깨 관절 기준으로 바깥쪽 22도 회전해 골반과 겹치지 않는 포즈로 배치

## 버그 발견·수정

**"팔이 3개로 보인다" 재발 (사용자 리포트, 이전 원 때와 동일한 문구)** — [[changelog/2026-09-10_먹괴음골렘-원제작]]에서 겪은 것과 똑같은 종류의 실수가 다른 원인으로 재발했다. 이번엔 Pyeong 잔재가 아니라, **이미 export·커밋까지 끝난 Won이 원점(0,0,0)에 그대로 남아있는 상태에서, Heup을 작업 중 임시로 X+3 옮겨뒀다가 export 직전 다시 원점(X-3)으로 되돌리면서 Won과 완전히 겹쳐버린 것**이 원인. Chest/Pelvis 월드 바운딩 박스를 직접 비교해 두 캐릭터가 정확히 같은 좌표에 겹쳐 있음을 실측으로 확인.

단, 실제 export된 FBX 파일 자체는 매번 `use_selection=True`로 Heup 오브젝트 24개만 선택해서 내보냈기 때문에 문제없었다 — Won 제거 전후 재export한 파일 크기가 정확히 동일(588092바이트)함을 확인해, 이번 버그는 파일 손상이 아니라 순수하게 **뷰포트에 두 캐릭터가 겹쳐 보인 표시 문제**였음을 검증했다.

수정: Won을 씬에서 제거(이미 파일로 안전하게 저장·커밋된 상태라 삭제해도 무방). 이후 Heup 단독으로 여러 각도 재확인, 팔 2개(정상 왼팔 + 확대된 오른손)만 존재함을 확인.

**본(Armature)-메쉬 정렬 불일치 (사용자 질문 "저 다이아몬드는 팔이랑 동기화 안 해도 되는거야?"로 발견)** — Armature 선택 시 표시되는 본 오버레이(점선+다이아몬드)가 다리 쪽으로 이상하게 뻗어 보인다는 스크린샷을 받고 확인하는 과정에서, 사용자가 "저 다이아몬드는 팔이랑 동기화 안 해도 되는거야?"라고 질문. 실측해보니 **팔을 확대·회전시킬 때 메쉬 정점은 직접 회전시켰지만 그 밑의 뼈(UpperArm_L/Forearm_L/Hand_L 등)는 원래 위치(팔이 곧게 아래로 뻗은 자세) 그대로 남아있던 게 확인됨**. 레스트 포즈에서는 본 위치가 어디 있든 변형이 항상 항등(identity)이라 렌더링에 티가 안 나지만, 애니메이션을 재생하면 본이 실제 메쉬와 다른 축을 기준으로 회전해 손이 엉뚱한 지점을 중심으로 도는 문제가 생길 뻔했음. UpperArm/Forearm/Hand 본 3개(양쪽 6개)를 메쉬에 적용한 것과 똑같이 어깨 기준 22도 회전시켜 재정렬, 각 본의 head/tail이 해당 메쉬 파츠의 바운딩 박스 안에 들어오는 것을 재측정으로 확인 후 재export(파일 크기 588092→588188바이트로 변경 반영 확인).

## 교훈

- **"이전 변형종의 결과물을 씬에 남겨둔 채 다음 변형종을 원점에서 작업하면 반드시 겹친다."** 원 제작 때는 Pyeong(소스) 잔재가 원인이었고, 흡 제작 때는 Won(이미 완성된 이전 결과물)이 원인 — 겹침의 소스가 매번 다를 수 있으므로, **다음 변형종 작업을 시작하기 전에 "지금 씬에 이 캐릭터 말고 다른 InkGolem_* 오브젝트가 남아있는가"를 항상 먼저 점검**해야 한다
- 캐릭터를 임시로 오프셋해서 작업하다가 되돌리는 패턴은 편리하지만, 되돌리는 시점에 씬에 남아있는 다른 캐릭터와 겹칠 위험이 항상 따라온다 — 되돌리기 직전에 씬 전체 오브젝트 목록을 점검하는 습관이 필요
- 뷰포트에서 이상하게 보이는 문제를 리포트받았을 때, **export 파일 자체가 실제로 망가졌는지 파일 크기 비교 등으로 구분**하면 "씬 정리만 하면 되는 문제"와 "지오메트리 자체를 고쳐야 하는 문제"를 빠르게 가를 수 있다
- **메쉬 정점을 직접 world-space로 회전·확대할 때, 리깅된 캐릭터라면 그 밑의 본도 반드시 같은 변환으로 같이 옮겨야 한다.** 정점만 옮기고 본을 안 옮기면 레스트 포즈 렌더링은 멀쩡해 보여서 (변형이 항등이라) 놓치기 아주 쉽지만, 애니메이션 재생 시점에만 드러나는 잠재 버그가 된다 — 이번엔 사용자가 본 오버레이를 직접 보고 "이거 동기화 안 해도 되냐"고 질문한 덕분에 애니메이션 전에 미리 잡을 수 있었음. 앞으로 팔/다리 파츠를 포즈 변형할 때는 메쉬와 본을 항상 같은 피벗·같은 각도로 함께 회전시킬 것
