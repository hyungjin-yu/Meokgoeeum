# 원(Won) — 후퇴가 제대로 안 되는 버그 수정

## 배경

사용자가 실제 플레이 녹화 영상을 공유하며 "원거리 몹이 플레이어에서 멀어질 때, 제대로 멀어지지가 않아"라고 리포트. 프레임을 뽑아 확인해보니 원(Won)이 플레이어 바로 옆에 계속 붙어있는 게 보였음.

## 원인 — 두 가지, 둘 다 원본 EnemyWon.cs에도 있던 기존 문제

실제 Play 세션에 접속해서 값을 직접 재봄:

```
플레이어 위치 - 원 위치 거리 = 1.46
retreatTriggerRange = 1.5, attackMinRange = 2.0
state = Chasing (Retreat도 Attack도 아님!)
moveSpeed(원) = 2, moveSpeed(플레이어) = 6
```

① **후퇴 트리거(1.5)와 공격 최소 거리(2.0) 사이에 빈틈**(1.5~2.0m) — 그 구간에 끼이면 후퇴 조건(`<=1.5`)도 공격 조건(`>=2.0`)도 둘 다 안 맞아서, 아무 조건에도 안 걸리고 `else` 분기로 떨어져 다시 플레이어에게 다가가버림. 원본 [[EnemyWon]]에도 정확히 같은 임계값(1.5/2.0)이 있어서 똑같이 겪는 문제 — 큐브로 옮기면서 새로 생긴 게 아니라 원래 있던 로직 결함.

② **플레이어(6)가 원(2)보다 3배 빠름** — 설령 후퇴가 정상 트리거돼도, 일반 이동속도로는 애초에 거리를 벌릴 수 없음. 이것도 두 밸런스 수치 시트 값을 그대로 가져온 거라 원본에도 있는 특성.

사용자에게 확인 후 **둘 다 고치기**로 결정(큐브 버전만 — 원본 `EnemyWon.cs`는 안 건드림, 원본도 같은 문제가 있을 가능성이 높지만 그건 실제 던전에서 별도로 재현·수정할 사안).

## 수정

- `CubeEnemyBase.MoveToward()`에 `speedOverride` 선택 인자 추가 — 안 주면 기존처럼 `MoveSpeed`(추상 프로퍼티)를 쓰고, 주면 그 값으로 대신 이동.
- `CubeEnemyWon.attackMinRange` 기본값 2f → 1.5f로 낮춰서 `retreatTriggerRange`(1.5)와 맞춤 — 빈틈 제거. 필드에 "둘을 같게 유지하라"는 경고 주석 추가.
- `CubeEnemyWon.retreatSpeedMultiplier`(기본 1.5배) 신규 — 후퇴할 때만 `MoveToward(..., speedOverride: moveSpeed * retreatSpeedMultiplier)`로 순간적으로 더 빨리 움직이게 함.

## 검증

리플렉션으로 재현:

- 거리 1.8m(예전 빈틈 지대)에 플레이어를 두고 확인 → `state=Busy`(공격 상태)로 즉시 전환됨(예전엔 `Chasing`으로 다가갔음) ✅
- 초근접(0.5m)에서 플레이어를 고정해두고 30틱 진행 → 거리가 0.5 → 1.52로 벌어짐(후퇴가 실제로 거리를 만듦) ✅

## 한계

- 원본 `EnemyWon.cs`(평지 던전)는 그대로 뒀음 — 같은 문제가 있는지, 있다면 고칠지는 별도 판단 필요.
