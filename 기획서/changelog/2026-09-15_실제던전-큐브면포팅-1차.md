# 실제 던전(방 A~D)을 큐브 면 구조로 포팅 — 1차

## 배경

어제 세션 마지막에 남겨둔 "다음 순서 ①"을 착수. [[MultiRoomFloor1Builder]]가 `SC_Face_0.unity`에 지은 1층 멀티룸 던전(방A~D, 각 30x30, 일렬 배치)을, [[CubeSurfaceWalker]]가 걷는 실제 3D 큐브(`SC_CubePrototype.unity`) 표면 위로 옮기는 첫 시도.

## 설계 결정 (사용자와 논의)

- **"1개 방 = 큐브 1개 면"**: 방 하나를 통째로 한 면에 배치. 방 이동 = 문을 지나 연결 통로를 걷는 게 아니라 **큐브 모서리를 넘어가는 것 자체** — `CubeFaceZone`이 이미 모서리 전환을 처리해줘서 별도 연결 통로가 필요 없음.
- **큐브 크기 10→17로 확대**: 방이 30x30인데 기존 면 한 개는 20x20(half=10)이라 방 하나도 안 들어감. half=17(한 변 34)로 키워서 30x30 방 + 벽 두께 + 여유 2유닛이 딱 맞게 함.
- **면 배정(X축 링)**: 방A=+Z(기존 5종 몹 AI 테스트 자리), 방B=+Y(기존 골목 환경 아트 자리), 방C=-Z(새 면), 방D=-Y(새 면). 이 4개 면은 서로 전부 인접(수직)해서 이 순서대로 걸어서 넘어갈 수 있음. 기존 테스트 몹 5종은 삭제하지 않고 안 쓰는 +X 면으로 옮겨서 보존(AI 재검증용).

## 결과물

- `Assets/Scripts/Editor/CubeFaceRoomBuilder.cs` 신규 — 큐브 리사이즈, 기존 몹 이동, 방 A~D 벽/문/게이트/적 배치를 전부 처리.
  - `GetFaceBasis(normal)` — 면 법선 하나로부터 국소 2축(u=가로, v=세로)을 고정적으로 뽑는 헬퍼. v는 "위"에 가까운 접선(윗/아랫면은 "앞"으로 대체), u=cross(normal,v). 문/게이트는 전부 v±15 벽에 냄(그게 다음/이전 면과 실제로 맞닿는 모서리라서) — u±15 벽(안 쓰는 ±X 면과 맞닿는 쪽)은 항상 막음.
  - `BuildFaceWall()` — 면 위에 박스 하나를 세우는 범용 헬퍼. 회전을 `Quaternion.LookRotation(v, normal)`로 맞춰서 로컬 X→u, Y→normal, Z→v가 되게 하면, `localScale`이 그대로 (u크기, 높이, v크기)와 대응 — [[MultiRoomFloor1Builder]]의 월드 Y-up 전제 벽 빌더를 면 법선 기준으로 일반화한 버전.
  - 방마다 문 상태(막힘/열림/게이트잠금)를 명시적으로 지정: 방A(닫힘→B게이트), 방B(A진입 열림→C게이트), 방C(B진입 열림→D게이트), 방D(C진입 열림→닫힘, 클라이맥스).
  - `SpawnRoomPyeong()` — [[CubeEnemyPyeongTestBuilder]]와 동일한 패턴(EnemyPyeong.prefab 인스턴스화 → NavMeshAgent/EnemyPyeong/EnemyHealth 제거 → CubeEnemyPyeong 부착)으로 방마다 필요한 수만큼 배치.
- `Assets/Scripts/Level/RoomClearGate.cs` 수정 — `AnyEnemyAlive()`에 `ICubeFaceMob` 체크 추가(`CurrentHP > 0`). 기존엔 `EnemyHealth`/`BossHealth`만 봐서 큐브 면 몹은 절대 "살아있다"로 안 잡혔음(게이트가 항상 즉시 클리어로 오판했을 것). 평지 던전엔 `ICubeFaceMob` 구현체가 없어서 이 분기는 안 타고 지나감 — 기존 동작 영향 없음.

## 스코프 밖 (알고 한 단순화)

- `EncounterSpawner`의 "웨이브(시간차 등장)"는 안 씀 — 방 콘텐츠가 큐브 위로 옮겨지는지 자체를 먼저 검증하려고 각 방의 적을 처음부터 전부 배치(원본 웨이브 총원과 동일: A=2, B=2, C=3, D=4).
- 방D 클리어 후 "다음 층"은 없음 — [[CubeMapManager]]는 씬 전환 기반이라 이 리터럴 큐브 프로토타입과 아직 연결 안 됨. 방D 게이트는 stairs/doorsToOpen 둘 다 비워서 "클리어 로그만 남기는 종착점"으로 둠(경고 로그 뜨는 거 정상).
- 벽화(PaintableObject)/움직이는 장애물(MovingObstacle) 등 장식 요소는 생략 — 벽+적+게이트라는 핵심 골격만 먼저.

## 검증

- 재컴파일 에러 없음, `BuildFromCLI()` 실행 성공(콘솔에 완료 로그만, 에러 없음).
- `CubePlanet` scale=34(half=17), `CubeSurfaceWalker.cubeHalfExtent=17`, 게이트 4개 전부 올바른 `doorsToOpen`/`stairs` 배선 확인.
- **에디터 모드에서 `RoomClearGate.AnyEnemyAlive()`가 처음엔 `False`가 나와서 당황** — 원인은 실제 버그가 아니라 `CubeEnemyBase.currentHP`가 `Start()`에서만 `maxHP`로 초기화되는데, 에디터 모드에선 `Start()`가 아예 안 돌아서 새로 배치한 적들의 `CurrentHP`가 기본값 0으로 남아있었던 것(리플렉션 테스트 잔재 아니라 진짜 라이프사이클 차이). 실제 Play 모드로 진입해 재확인하니 `CurrentHP=100`, `AnyEnemyAlive()=True` 정상 확인.
- Scene View 스크린샷 2장(맞은편 대각선 두 각도)으로 4개 면 전부 벽/문 틈/적 배치 육안 확인 — 구조적으로 이상 없음.

## 다음 작업

- 실제 Play 테스트(적 처치 → 게이트 클리어 → 문 열림 → 다음 면으로 도보 이동)는 사용자가 직접 확인 필요 — 이 자동화 환경은 실시간 대기(clearGraceDuration 등)를 안정적으로 재현하기 어려움.
- 나머지 큐브 면(±X, 현재는 AI 테스트용으로만 씀) 테마/용도 배정은 여전히 미정.
- 웨이브 스포너/벽화/장애물 등 장식·페이싱 요소를 붙일지는 1차 결과 확인 후 판단.
