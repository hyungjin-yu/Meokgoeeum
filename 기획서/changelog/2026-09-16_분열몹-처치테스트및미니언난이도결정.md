# 분열 몹(EnemyBun) 처치 테스트 + 미니언 난이도 결정

## 배경

부위 색칠 처치를 5종 전체로 확산한 뒤([[changelog/2026-09-16_몹부위색칠-전종확산및검정제외]]), 분열형 `EnemyBun`이 처치 시 미니언 2마리로 분열하는 기존 로직([[13 먹괴음 AI 설계]])이 새 체계에서도 정상 작동하는지 사용자 요청으로 실측 검증.

## 검증 결과 — 분열 자체는 정상

`unity command eval`로 `EnemyBun.prefab` 인스턴스를 스폰해 999 데미지로 7회 연속 공격:
- 정확히 7번째 공격에서 처치, `EnemyHealth.OnDeath` 이벤트 → `EnemyBun.SplitOnDeath()` 정상 호출
- 미니언 2마리 정상 생성(`isMinor=True`, 크기 0.6배 정상 적용)
- 미니언에게도 동일하게 7회 공격 → 정확히 7번째에 처치, `isMinor` 가드로 재분열 안 함(무한분열 방지 정상)

## 발견한 이슈 — 미니언 체력 배율이 사실상 무효화됨

`SplitOnDeath()`가 미니언 생성 후 `cloneHealth.ConfigureMaxHP(health.maxHP * minorHpMultiplier)`(원본 체력의 50%)를 호출하는데, 실제로 미니언 인스턴스를 확인해보니 `maxHP=12.5`(정상 절반)로는 설정됐지만 `CurrentHP(파악 기준)=7`으로 나옴. **`MonsterPaintParts`가 붙어있으면 `EnemyHealth.CurrentHP`/`TakeDamage()`가 숫자 체력(`maxHP`/`currentHP`)을 완전히 무시하고 "칠 안 된 부위 수"만 보기 때문에, `ConfigureMaxHP()`가 사실상 아무 효과가 없어짐** — 미니언도 원본과 완전히 동일하게 7번 맞아야 죽음.

## 결정

사용자에게 "미니언도 원본만큼(7번) 그대로 둘지, 아니면 미니언은 보정이 적게(예: 3속) 늘리기" 물었고, **"미니언도 7번 그대로 유지(난이도 유지)"로 확정**. 분열해도 개별 미니언이 더 쉬워지진 않지만, 대신 몹 수 자체가 늘어나는 게 이미 원래 "분열"의 위협인 만큼 이대로 유지하기로 함 — **코드 변경 없음.**

## 참고 — 이 이슈가 다른 종에도 해당되는지

`CubeEnemyBun.OnDeath()`도 동일 패턴(`cloneBun.maxHP = maxHP * minorHpMultiplier; cloneBun.currentHP = cloneBun.maxHP;`)이라 큐브 던전에서도 똑같이 무효화됨 — 다만 사용자 결정이 "그대로 유지"라 이쪽도 손대지 않음. `ConfigureMaxHP`/`maxHP` 직접 대입 자체는 여전히 정상 동작하니, 나중에 다시 "미니언은 쉽게" 쪽으로 바뀌면 `MonsterPaintParts` 쪽에 "이미 N부위는 칠해진 채로 시작" 같은 초기화 옵션을 추가하는 방향이 될 것으로 보임(지금은 만들지 않음).
