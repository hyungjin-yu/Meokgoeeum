# 2026-08-16 — 색 복원 파동 "동시에 칠해짐" 조사 → 버그 아님, 타이밍 조정

## 배경

사용자 리포트: "4개 큐브가 거리 상관없이 동시에 색이 돌아온다." 진단 로그를 추가해서 실제 계산값을 확인.

## 조사 결과 — 버그 아님

로그 확인 결과 트리거 시점은 정확히 거리순으로 계산되고 있었음:

```
Test1 (2) 칠해짐 (elapsed=0.18s) ← 거리 3.63
Test1     칠해짐 (elapsed=0.21s) ← 거리 4.02
Test1 (1) 칠해짐 (elapsed=0.31s) ← 거리 6.03
Test1 (3) 칠해짐 (elapsed=0.46s) ← 거리 9.16
```

문제는 각 오브젝트의 개별 `fadeDuration`(0.5초)이 트리거 시간차 총합(0.28초)보다 길어서, 4개가 전부 "색이 스며드는 중"인 구간이 겹쳐버려 육안으로는 동시에 바뀌는 것처럼 보였던 것. 로직/코드 버그가 아니라 **파라미터 튜닝 문제**였음.

## 한 일

- `ColorWaveEffect.cs`의 임시 진단 로그 제거 (원인 확인 완료)
- `PaintableObject.fadeDuration` 기본값 0.5 → 0.2초로 조정 — 파동의 일반적인 오브젝트 간 트리거 시간차(0.2~0.5초 안팎)보다 짧아야 순서가 눈에 보임

## Unity에서 해야 할 일

**이미 씬에 배치된 4개 테스트 큐브의 `Paintable Object` → `Fade Duration`을 수동으로 0.2로 바꿔야 함** (스크립트 기본값 변경은 이미 배치된 컴포넌트에 자동 반영 안 됨 — 이전에도 반복됐던 패턴, → CLAUDE.md에 원칙으로 박아두는 걸 고려할 것)

## 다음 세션이 알아야 할 것

- 이런 "트리거는 맞는데 개별 전환 시간이 길어서 순서가 안 보이는" 패턴은 시간차를 두고 여러 대상에 순차 효과를 주는 시스템(예: 나중에 만들 큐브 회전 연출, 컷씬 연출 등)에서 또 나올 수 있음 — 비슷한 증상이면 "버그 의심" 전에 먼저 각 개별 전환 시간과 트리거 시간차의 비율부터 확인할 것
