# 히트스탑 재설계 — 코루틴 제거, timeScale이 다시 0에 갇히는 근본 원인 해결

## 배경

[[changelog/2026-09-14_히트스탑-타임스케일고정버그]]에서 "복귀값 캡처" 문제를 depth 카운터로 고쳤는데, 곧바로 사용자가 "아무리 클릭을 해도 아무 반응이 없어, 콘솔도 안 찍혀" 리포트. 라이브로 `Time.timeScale`을 다시 찍어보니 또 `0`에 고정돼있었음 — depth 카운터 자체는 정상 작동했지만 더 근본적인 문제가 남아있었음.

## 원인

[[BrushWeapon]]의 `HitStop()`이 여전히 코루틴(`WaitForSecondsRealtime`)이었음. 코루틴은 자신이 속한 GameObject/컴포넌트가 도중에 **비활성화되거나 파괴되면 재개 기회를 영영 잃음** — `yield return` 대기 중 그런 일이 생기면 `Time.timeScale = 1f`로 복구하는 마지막 줄이 절대 실행되지 않고 게임 전체가 영구히 멈춤. 실전에서 정확히 이 경로로 재현됨(직접 리플렉션으로 `PerformHit()` 호출 → 코루틴이 시작은 됐지만 재개가 안 돼 `timeScale=0`으로 고정된 것 확인). 실제 게임에서도 히트스탑 도중 씬 리로드(사망 시 `ReloadCurrentFace()` 등)가 겹치면 똑같이 발생할 수 있는 구조였음.

## 수정

코루틴을 버리고 `Update()`에서 `Time.unscaledDeltaTime`으로 직접 카운트다운하는 방식으로 교체:

```csharp
private void Update()
{
    if (hitStopTimer > 0f)
    {
        hitStopTimer -= Time.unscaledDeltaTime;
        if (hitStopTimer <= 0f) EndHitStop();
        return;
    }
    switch (phase) { /* 기존 콤보 상태머신 */ }
}

private void StartHitStop()
{
    if (hitStopTimer <= 0f) { hitStopDepth++; Time.timeScale = 0f; }
    hitStopTimer = HitStopDuration;
}

private void EndHitStop()
{
    hitStopTimer = 0f;
    hitStopDepth = Mathf.Max(0, hitStopDepth - 1);
    if (hitStopDepth == 0) Time.timeScale = 1f;
}

private void OnDisable()
{
    // 히트스탑 도중 비활성화/파괴되면 Update()가 안 돌아서 EndHitStop()이 영영
    // 안 불릴 수 있음 — 여기서 강제로 마무리해서 timeScale이 0에 갇히는 걸 막음.
    if (hitStopTimer > 0f) EndHitStop();
}
```

`Update()`는 `Time.timeScale`과 무관하게 매 프레임 호출되므로 카운트다운 자체가 코루틴보다 근본적으로 안전하고, `OnDisable()` 안전망 덕분에 중간에 컴포넌트가 꺼지거나 오브젝트가 파괴돼도 `timeScale`이 0에 갇히지 않음. depth 카운터(겹침 대응)는 그대로 유지.

## 검증

리플렉션으로 세 시나리오 직접 확인:
- `StartHitStop()` → `timeScale=0, timer=0.05, depth=1` ✅
- `EndHitStop()` → `timeScale=1, timer=0, depth=0` ✅
- 다시 `StartHitStop()` 후 `OnDisable()` 강제 호출(중간에 꺼지는 상황 재현) → `timeScale=1`로 즉시 복구 ✅ (기존 코루틴 방식이었다면 영구히 0에 갇혔을 상황)

재컴파일 에러 없음 확인. 실제 마우스 클릭으로 연속 공격해도 재발 안 하는지는 사용자 쪽 확인 필요.

## 한계

이 자동화 환경 자체가 프레임 틱이 불안정해서(`Time.frameCount`가 `eval` 호출 사이에 멈춰있는 것으로 이미 알려진 문제) 코루틴이 잘 재개되는지를 "정상적인 실시간 진행"으로는 검증할 수 없었음 — 그래서 코루틴을 아예 없애고 `Update()`/`OnDisable()` 기반으로 바꾼 것 자체가 검증 가능성과 실제 견고함을 동시에 해결한 방향. 다만 "실제 유저가 연타할 때 정말 재발 안 하는지"는 코드 리뷰+단위 시나리오로만 확인했고, 정상 실시간 플레이로 최종 확인은 사용자 몫.
