# 골목 환경 에셋 — 도로/나무/경계석

## 배경

큐브 표면 보행 프로토타입을 실제 게임에 이식하기 전, 사용자가 "골목에 사용될 환경 에셋부터 만들어. 길, 나무 이런 것들"이라고 요청. 큐브 겉면을 "걸어다니는 거리"로 만드는 설계([[changelog/2026-09-12_큐브표면보행-프로토타입]] 다음 단계)에 필요한 기초 에셋.

## 결과물

- `Assets/Models/Environment/Roads/AlleyRoad_01.fbx` — 4x4m 도로 타일. 정점을 미세하게 랜덤 변위해서 낡은 콘크리트 느낌 + 1m 간격 격자선(정점)을 살짝 눌러 만든 줄눈(포장 이음매)
- `Assets/Models/Environment/Roads/AlleyCurb_01.fbx` — 4m 길이 도로 경계석, 도로 타일 한 변에 맞춰 이어붙일 수 있음
- `Assets/Models/Environment/Vegetation/StreetTree_01.fbx` — 가로수. 트렁크(세로 수피 홈) + 가지 4개 + 잎 클러스터 12개(가지 끝 + 보조 클러스터 + 수관 중심부)로 구성, 높이 약 4.6m

## 발견 — 외부 에셋 소스 전부 비활성

사용자가 "몹 5마리랑 비슷한 수준의 환경 에셋이 필요하다"고 요청해서 확인해보니, PolyHaven·Sketchfab·Poly Pizza·Hyper3D Rodin 생성 **전부 이 세션에서 비활성 상태**(Blender MCP 패널 체크박스 + API 키 + 연결 재시작이 필요해서 에이전트가 직접 켤 수 없음). 몹 5종도 사실 외부 다운로드가 아니라 같은 프로시저럴 Blender 코드 방식으로 만들어진 것으로 확인 — 사용자가 "프로시저럴로 더 공들여 만들기"를 선택해서, 나무를 가지+불규칙 잎 클러스터+트렁크 수직 홈을 추가해 재제작.

## 버그 — Shade Smooth 누락으로 각져 보임

사용자 리포트: "먹괴음 몹들은 매끈매끈한데 나무가 저렇게 각지면 이상하지 않겠어?" — 확인해보니 트렁크/수관 메쉬에 `shade_smooth()`를 안 걸어서 저폴리 이코스피어의 면이 그대로 각지게 보이고 있었음(서브디비전 레벨과 무관하게, 부드러운 노멀 보간이 아예 없었던 것). `bpy.ops.object.shade_smooth()` 적용 후 재확인 — 몹 모델과 같은 매끈한 스타일로 통일됨.

## 나무 종 다양화

한 종류만 반복 배치하면 골목이 단조로워 보일 것 같아서, `StreetTree_01`을 만들던 절차(트렁크 콘+수피 홈, 가지, 이코스피어 잎 클러스터, `shade_smooth()`)를 함수로 뽑아 크기·비율·색을 다르게 준 두 변종을 추가로 제작했다.

- `Assets/Models/Environment/Vegetation/StreetTree_02.fbx` — 키 크고 가지 5개가 성기게 뻗은 수형, 잎이 가지 끝에만 몰려있어 트렁크가 많이 드러나는 실루엣, 짙은 잎 색(`Mat_Tree_Leaves_Dark`)
- `Assets/Models/Environment/Vegetation/StreetTree_03.fbx` — 키 작고 가지 6개가 촘촘한 수형, 살짝 기울어진 트렁크(`lean_deg=6`), 밝은 수피(`Mat_Tree_Bark_Pale`)와 밝은 잎 색(`Mat_Tree_Leaves_Light`)

Unity 재확인 결과 `StreetTree_02` size=(3.09, 5.51, 2.88), `StreetTree_03` size=(2.38, 3.57, 2.54), 둘 다 `rootRot=(0,0,0)` — 축 보정도 정상.

## 기법 개선 — export 시점에 축 보정을 메쉬에 직접 굽기

[[changelog/2026-09-11_환경아트-1층첫배치]]에서 겪었던 "Blender Z-up→Unity Y-up 보정이 루트 회전으로 남아서 배치 코드가 회전을 덮어쓰면 넘어지는" 버그를 이번엔 원천 차단 — `bpy.ops.export_scene.fbx()` 호출 시 `bake_space_transform=True` 옵션을 줘서 축 보정을 **메쉬 데이터 자체에** 구웠다. 결과: Unity에서 재확인한 3개 에셋 전부 `rootRot=(0,0,0)`, 임포트 후 별도 `bakeAxisConversion` 재설정이 필요 없었음.
