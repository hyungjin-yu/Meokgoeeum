# 2026-08-19 — 계단 & 층 구조 구현 (v0.2 마지막 항목)

## 배경

v0.2 마지막 남은 항목 "층 구조 + 계단 이동" 착수. 동시에 어제부터 보류해뒀던 미해결 질문
("색 구슬 획득 시 자동으로 큐브를 회전시킬지")도 이 작업으로 자연스럽게 해결됨.

## 발견: "회전 트리거"는 구슬 획득이 아니라 계단이었음

[[19 층별 상세 설계]]를 다시 읽어보니, 각 층마다 "계단 조건"이 따로 정의되어 있고
(대부분 "전투 클리어", 일부는 "구슬 획득 후 자동 등장" 등 층마다 다름) — **계단을 밟는 것 자체가
[[CubeMapManager]] 회전을 발동시키는 진짜 게임플레이 트리거**였습니다. 구슬 획득은 (대부분의 층에서)
계단이 열리기 위한 선행 조건 중 하나일 뿐, 회전을 직접 발동시키는 게 아니었음.

**그래서 어제 보류했던 질문이 해결됨:** [[ColorWaveEffect]]에 회전을 자동 연결하지 않은 게 맞았고,
대신 이 계단 시스템이 진짜 정답이었습니다. 이제 적을 잡을 때마다 화면이 전환되는 문제 없이,
"방을 클리어하면 계단이 나타나고, 계단을 밟아야 다음 층으로 간다"는 원안 그대로의 흐름이 됩니다.

## 한 일

- **`Stairs.cs` 신규** — 평소엔 꺼져있다가(콜라이더 비활성 + 렌더러 숨김) `Activate()` 호출로 켜지는 계단. 플레이어가 밟으면(트리거) `CubeMapManager.RotateRandomAxis()`를 호출해서 다음 면으로 회전
- **`RoomClearGate.cs` 신규** — [[19 층별 상세 설계]]에서 가장 흔한 계단 조건인 "전투 클리어"의 기본 구현. 손으로 적 목록을 등록하는 대신 **지정한 박스 범위 안에 `EnemyHealth`가 남아있는지 주기적으로 검사**하는 방식 채택 — `EnemyBun`처럼 처치 시 미니언이 새로 생기는 경우도 자동으로 걸러짐(고정 목록이면 놓쳤을 케이스)

## 의도적으로 단순화한 부분

- **계단 조건은 "전투 클리어" 하나만 구현.** [[19 층별 상세 설계]]엔 "구슬 획득 후 자동 등장", "특정 순서로 처치" 같은 층별 특수 조건도 있지만, 그건 레벨 콘텐츠 제작 시점에 필요한 것들이라 지금은 안 만듦. `Stairs.Activate()`가 공개 메서드라 나중에 다른 조건의 게이트 스크립트를 새로 만들어도 `Stairs` 쪽 코드는 안 건드려도 됨(단일 책임 분리)
- **위치/개수는 레벨 디자인 몫**: `Stairs`/`RoomClearGate`는 재사용 가능한 컴포넌트만 제공 — 각 면 씬에 몇 개를 어디에 배치할지는 실제 레벨을 만들 때 결정

## Unity에서 해야 할 일

각 면 씬(`SC_Face_N`)에 대해:
1. 계단 역할을 할 오브젝트 만들기 (예: Cube를 계단 모양으로 배치하거나, 지금은 임시로 아무 도형이나) → `Stairs.cs` 부착, Collider를 **Is Trigger 체크**
2. 방 클리어를 감지할 빈 오브젝트 만들기 → `RoomClearGate.cs` 부착 → `Bounds Size`를 그 방을 덮도록 조절(기즈모로 파란 박스가 보임) → `Stairs` 필드에 위에서 만든 계단 연결
3. 플레이테스트: 방의 적을 전부 처치 → 계단이 나타나는지(로그 `RoomClearGate ... 클리어! 계단 활성화.`) → 계단을 밟으면 회전하는지(`Stairs 사용! 다음 층으로 이동합니다.` → 기존 회전 로직 그대로 이어짐) 확인
