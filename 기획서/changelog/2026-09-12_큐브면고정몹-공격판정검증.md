# 큐브 표면 — 면 고정 몹 + 같은 면 공격 판정 검증

## 배경

사용자 요구사항: "던전도 큐브 겉면 거리 같이 큐브 뷰의 느낌이야. 대신 몹들은 면과 면을 이동할 수 없고, 캐릭터도 다른 면에 있는 몹은 공격이 불가능해." 즉 기존 멀티룸 던전(SC_Face_0 방A~D)도 문 뒤 별도 공간이 아니라, 큐브 겉면을 걷는 이 프로토타입과 같은 방식으로 만들되 — 각 "방"이 큐브의 한 면에 대응하고, 몹은 자기 면을 못 벗어나고, 전투 판정도 같은 면끼리만 성립해야 함.

이 규칙을 실제 던전에 바로 적용하기 전에, 지금 프로토타입 씬(`SC_CubePrototype.unity`)에서 먼저 검증하기로 함(사용자 선택 — "프로토타입에서 먼저 검증").

## 결과물

- `Assets/Scripts/Player/CubeFaceLockedMob.cs` 신규 — 스폰 시 `faceNormal`이 고정되고 [[CubeFaceZone]] 트리거를 아예 구독하지 않아서, 구조적으로 다른 면으로 못 넘어감(AI 판단이 아니라 애초에 수단이 없음). 플레이어가 같은 면에 있을 때만 접선 방향으로 접근하되, [[CubeSurfaceWalker]]와 동일한 clamp 패턴으로 자기 면 경계를 못 벗어남.
- `Assets/Scripts/Player/CubeFaceAttackTester.cs` 신규 — F키로 공격, 사거리 안이어도 `Vector3.Dot(내 면, 몹 면) > 0.999f`가 아니면 무시 + 로그. 3D 거리만 보면 모서리 너머 몹이 가까워 보이는 함정을 피하려고 면 일치 여부를 거리 판정과 별도로 체크.
- `Assets/Scripts/Editor/CubeFaceMobTestBuilder.cs` 신규 — 기존 `CubePrototypeBuilder`와 달리 씬을 통째로 안 지우고 테스트 몹(`TestMob_PlusZ`)만 추가/갱신 — 이미 배치된 [[changelog/2026-09-12_큐브골목환경-실배치]] 결과물을 보존.

## 버그 발견 — 캐릭터가 표면에 "파묻히는" 문제 (사용자가 리포트한 "플레이어 키가 작다"의 진짜 원인)

리플렉션 스텝 테스트로 몹 위치를 검증하던 중, `CubeSurfaceWalker`/새 `CubeFaceLockedMob` 둘 다 표면 클램프가 `cubeHalfExtent`로 피벗을 정확히 고정한다는 걸 발견 — 캡슐 피벗은 중심에 있으므로, 이러면 캡슐 높이의 절반이 큐브 속에 파묻힌 반구 모양으로만 보임. 카메라 줌 기능을 추가했던 지난 세션([[changelog/2026-09-12_큐브카메라-줌기능]])에서 사용자가 "플레이어 키가 작아서 나무가 안 보인다"고 한 게, 실은 스케일 문제가 아니라 **매 프레임 표면에 파묻히는 클램프 버그**였을 가능성이 높음.

`surfaceOffset`(기본 1 — 캡슐 반높이) 필드를 두 스크립트 모두에 추가해서, 클램프가 `cubeHalfExtent + surfaceOffset`로 피벗을 표면 위로 띄우도록 수정. 리플렉션 검증: 수정 전엔 클램프 후 y/z가 정확히 `cubeHalfExtent`(=10)로 떨어졌지만, 수정 후엔 `cubeHalfExtent + 1`(=11)로 정확히 유지됨.

## 검증 결과 (Console 로그로 확인)

- 다른 면 + 사거리 안(거리 1.41) → `"TestMob_PlusZ — 사거리 안이지만 다른 면이라 공격 무시"` ✅
- 같은 면 + 사거리 안(거리 1.00) → `"TestMob_PlusZ 명중!"` ✅
- 같은 면 + 사거리 밖(거리 50) → 로그 없음(무시), 정상 ✅
- 몹 이동: 플레이어가 다른 면일 때 60프레임 동안 이동량 0.0000 ✅ / 같은 면으로 넘어오면 접근하되 자기 면 좌표(z=11)를 벗어나지 않음 ✅
