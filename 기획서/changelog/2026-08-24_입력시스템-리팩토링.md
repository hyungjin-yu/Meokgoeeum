# 2026-08-24 — PlayerInputActions 인스턴스 4개 → 1개 공유

## 배경

`/graphify`로 프로젝트 전체를 지식 그래프로 만들어본 뒤, God Node/커뮤니티 구조 분석 중
`@PlayerInputActions.Enable()`이 서로 무관한 4개 스크립트(`PlayerController`, `BrushWeapon`,
`ColorSkillController`, `PlayerDodge`)의 `Start()`에서 각각 호출되고 있다는 게 그래프 구조로 드러남
— 4개 스크립트가 각자 독립적인 `PlayerInputActions` 인스턴스를 만들고 있었음(중복 생성).

## 변경

- `PlayerController.cs`: 인스턴스 생성/구독/`Enable()`을 `Start()`에서 `Awake()`로 이동, `public PlayerInputActions InputActions` 프로퍼티로 공개. `OnDestroy()`의 `Disable()`은 그대로 유지(유일한 소유자).
- `BrushWeapon.cs` / `ColorSkillController.cs` / `PlayerDodge.cs`: 각자 만들던 `new PlayerInputActions()` + `Enable()`/`OnDestroy() Disable()` 제거. `Start()`에서 `GetComponent<PlayerController>().InputActions`로 공유 인스턴스를 받아 자기 액션만 구독. `[RequireComponent(typeof(PlayerController))]` 추가(안전장치).
- Unity가 "모든 컴포넌트의 `Awake()`가 끝난 뒤에야 `Start()`가 실행된다"를 보장하므로, 컴포넌트 순서와 무관하게 안전.

## 검증

Unity 실행 확인 — 이동/구르기(i-frame 포함)/붓 공격/색 스킬 3종(강타·흐름·번쩍) 전부 정상 작동, 콘솔 로그로 확인 완료.
