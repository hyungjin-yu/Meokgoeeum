# 던전 전투 게이팅 강화 (방마다 20초 미만 → 전 구간 강제 전투)

## 배경

[[changelog/2026-09-11_방A바닥구멍버그-수정]] 직후 사용자가 다시 플레이하고 "각 방당 20초도 안 걸린다"고 리포트 — [[changelog/2026-09-11_플레이타임-확장-스코프결정]] 목표(층당 26~30분)와 완전히 동떨어진 결과.

## 원인 진단 — 구조적 문제 2가지

1. **방A/C 서쪽 문이 애초에 잠겨있지 않았음.** [[changelog/2026-09-11_1층-멀티룸던전-파일럿]] 설계 당시 "처음 겪는 실수를 용서하는 여유"([[28 레벨 디자인]] 체크리스트)를 이유로 방A/C는 전투 없이 그냥 통과 가능하게 뒀는데, 결과적으로 전투 자체를 건너뛸 수 있는 문이 됐다.
2. **`ColorWaveEffect.maxRadius`가 30인데 방이 30x30이다.** 몹 하나만 잡아서 구슬을 얻어도 색 복원 파동이 반경 30 안의 `PaintableObject`를 전부 칠해버려서, 방B의 "벽화 3개 복원 퍼즐"이 사실상 무의미했음(첫 킬 하나로 사실상 즉시 풀림).

## 수정

**모든 방을 전투 클리어 게이트로 강제 잠금.** `RoomClearGate.cs`에 `doorsToOpen`(GameObject[]) 필드 추가 — 기존 `stairs`(면 전환용)와 별개로, 클리어 시 비활성화할 문 막음 오브젝트 배열을 추가로 지원(하위 호환 유지, 기존 5개 면의 `RoomClearGate` 사용처는 안 건드림).

- 방A: 기존 튜토리얼 전투(평×2) 그대로, 서쪽 문에 `DoorBlocker_A_West` 추가하고 기존 `RoomClearGate`에 연결
- 방B: 벽화 3개는 순수 장식으로 격하(파동 반경 문제로 진짜 게이트로 못 씀), 실제 게이트는 웨이브 전투(평 1+1, 2웨이브)로 교체
- 방C: 정적 배치 3마리 → 웨이브 전투(평 2+1, 2웨이브)로 교체, 서쪽 문 게이트 추가
- 방D: 정적 배치 4마리 → 웨이브 전투(평 2+2, 2웨이브)로 교체

`BuildWaveSpawner()` 신규 헬퍼 — 지정한 중심점 주변에 원형으로 스폰 지점을 배치하고 `EncounterSpawner`에 웨이브 배열을 채워 넣음. 한꺼번에 다 나오는 대신 순차 등장(웨이브 간격 2.5초)이라 실제 소요 시간이 늘어남.

## 버그 — 스크립트 재실행 시 게이트 유실(소프트락 위험)

`GameObject.Find("RoomClearGate")`로 원본 게이트를 찾았는데, **이전 실행에서 이미 이 오브젝트를 "RoomClearGate_D"로 개명해서 방D로 옮겨놨던 상태라 두 번째 실행부터 항상 null**이 나왔음 — 결과: 방A에 문 막음 큐브(`DoorBlocker_A_West`)는 생기는데 그걸 열어줄 게이트가 없어서 **영구 소프트락**이 될 뻔했다. 게다가 방D에는 "원본이 개명된 것"과 "이번 실행이 새로 만든 것" 두 개의 `RoomClearGate_D`가 중복 생성됨.

수정: 이름 대신 **"부모가 없는(=내가 만든 `MultiRoom_Generated` 밑이 아닌) `RoomClearGate`"**로 원본을 찾도록 변경 — 몇 번을 재실행해도 항상 같은 원본 오브젝트를 안정적으로 재사용. 재실행 2회 테스트로 게이트 개수가 항상 4개(A/B/C/D 각 1개)로 유지됨을 확인.

## 검증

- 컴파일 에러 0
- `Physics.Raycast` 스윕(X=25~-126) 재검증 — 구멍 0개(게이트 로직 변경이 바닥에 영향 없음을 재확인)
- 재실행 2회 후 `RoomClearGate` 컴포넌트 정확히 4개(`RoomClearGate_A/B/C/D`), 중복 없음, `doorsToOpen`/`stairs` 배선 정상 확인
- NavMesh 재베이크 완료
