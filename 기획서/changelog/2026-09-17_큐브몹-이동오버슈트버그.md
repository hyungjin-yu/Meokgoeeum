# 큐브 몹 이동 오버슈트 버그 — "흡한테 꼈다" 리포트의 진짜 원인

## 배경

사용자가 "플레이어가 흡한테 꼈어"라고 반복 리포트. 처음엔 [[CubeEnemyHeup]]의 흡수-해제 로직(1.5유닛 이상 벌어지면 놓아줌) 자체를 리플렉션으로 검증해서 정상 동작을 확인했지만, "그럼 실제 플레이 중 정말 그만큼 벌어졌는지" 서로 말로만 우기는 상황이 되어 [[changelog/2026-09-17_디버그스폰패널]]에 실시간 이동 거리 HUD(`DebugMovementHUD.cs`)를 추가해서 눈으로 직접 확인하기로 함.

## 발견 과정

HUD로 실제 플레이 영상을 다시 보니, 흡과의 거리가 시간이 지날수록 **1.20 → 1.19 → 1.00으로 계속 줄어들고 있었음** — 벌어지긴커녕 점점 더 가까워지는 중이었음. 콘솔 로그를 같이 보니 정확히 그 시점에 디버그 패널의 색 구슬 지급 개수 입력창에 "901"을 넣고 지급 버튼을 눌러서, `ColorSystemManager.AddOrb()`가 **한 프레임 안에 900번 넘게 동기 호출**되며 콘솔에 로그 900줄이 찍히는 게 확인됨 — 이게 그 프레임을 심하게 버벅이게 만듦.

## 원인

[[CubeEnemyBase]].`MoveToward()`가 한 스텝(`speed * Time.deltaTime`)을 `arriveThreshold`(흡의 경우 `minApproachToPlayer`=1.2, 또는 `absorbRadius`=1.5) 안쪽으로 못 들어가게 클램프하지 않고 있었습니다. 평소 프레임(deltaTime ≈ 0.016초)에서는 스텝 크기가 워낙 작아서(흡 speed=2.5 기준 한 프레임에 0.04유닛) 전혀 안 드러났는데, 위 900줄 로그 처리로 그 한 프레임의 `Time.deltaTime`이 크게 튀자, 같은 프레임에 "speed × 커진 deltaTime"만큼 한 번에 이동해버려서 정지 거리를 훌쩍 넘어 플레이어 코앞까지 파고들었습니다. 그 뒤로 정지 거리(1.2)보다 더 가까운 곳에 있으니 항상 "달라붙은 것처럼" 보였던 것.

## 결과물

- `CubeEnemyBase.MoveToward()` — 스텝을 `Mathf.Min(speed * Time.deltaTime, remaining)`으로 클램프(`remaining = 남은 거리 - arriveThreshold`, 0 미만 방지) — 어떤 극단적인 `Time.deltaTime`이 와도 `arriveThreshold`보다 더 가까이는 절대 못 파고들도록 함. 평지 던전 이동 로직은 안 건드림(이 클래스는 큐브 면 전용).
- `DebugSpawnPanel.GiveOrbs()` — 지급 개수를 20개로 상한(원인이 된 "큰 값 입력 → 한 프레임 동기 반복 호출" 자체도 막음). 20 초과 시 경고 로그 남기고 20으로 캡.

## 검증

리플렉션으로 두 가지 직접 확인:
1. 극단적인 버벅임 프레임을 흉내내기 위해 `MoveToward()`를 `speedOverride=10000`으로 강제 호출(15유닛 떨어진 상태에서) — 결과: 정확히 `arriveThreshold`(1.2)에서 멈추고 더는 안 파고듦(수정 전이었다면 순식간에 플레이어를 통과했을 상황).
2. 지급 개수 입력창에 "901" 입력 → 실제 반영은 20개로 캡됨(`lifetime=20`) 확인.

## 한계

- 이 오버슈트 버그는 디버그 패널이 아니어도, 에디터/기기 성능 문제로 프레임이 크게 버벅이는 어떤 상황에서도 재현될 수 있었던 근본적인 문제였음 — 이번에 클램프로 고쳐서 원인이 무엇이든(디버그 패널, 실제 성능 저하 등) 다시는 몹이 플레이어를 파고들 수 없게 됨.
