# 먹괴음 골렘 — Unity Humanoid 리깅 검증 및 스키닝 버그 수정

## 배경

Blender에서 뼈대(Armature)를 넣은 직후, 사용자가 "유니티에서 에셋 같은거로 리깅 넣을 수는 없어?"라고 질문. 확인 결과 Unity 자체엔 빈 메쉬에 뼈를 심는 기능이 없고, 대신 사용자가 이미 보유한 에셋스토어 패키지 [Kevin Iglesias의 Human Melee Animations](https://assetstore.unity.com/packages/3d/animations/human-melee-animations-151650)가 Humanoid 리타겟팅용 애니메이션 클립 팩이라는 것을 확인 — 우리 뼈대를 Unity Humanoid 규격에 맞추면 직접 애니메이션을 만들지 않고도 이 팩의 클립을 그대로 재생할 수 있음을 확인하고 실제로 시도.

## 작업 내용

1. **Human Melee Animations 임포트 확인** — 사용자가 Package Manager에서 임포트 완료, `find_assets`로 클립 목록 확인(남/여, 무기 종류별 폴더 구조). 먹괴음은 맨손 근접형이라 `Male/Combat/Unarmed/HumanM@AttackPunch01_R.fbx` 선택
2. **Humanoid Avatar 설정** — `unity command eval`로 C# 스크립트 실행해 `ModelImporter.humanDescription.human[]`을 우리 본 이름(Hip/Waist/Chest/Neck/Head, UpperArm/Forearm/Hand_L·R, Thigh/Calf/Foot_L·R)에 매핑, `animationType = Human`, `avatarSetup = CreateFromThisModel`로 재임포트. `avatar.isHuman=true isValid=true` 확인
3. **첫 테스트에서 심각한 버그 발견** — `AnimationMode.SampleAnimationClip()`으로 펀치 클립을 중간 시점에 샘플링해봤더니, **뼈대는 정상적으로 움직이는데 실제 메쉬 블롭들은 전혀 안 움직이고 원래 레스트 포즈 위치에 고정**돼 있었음. 좌표를 찍어보니 메쉬 오브젝트들의 Transform이 Blender에서의 원본 Location 값을 그대로 가진 채(Y/Z축이 뒤바뀐 상태로) 박혀있었음
4. **원인과 수정** — 블롭 오브젝트들을 `bpy.ops.mesh.primitive_uv_sphere_add(location=...)`로 만들면서 오브젝트 자체에 위치값이 남아있었던 것(Transform 미적용)이 원인으로 추정. Armature 모디파이어로 스키닝된 메쉬가 자체 Transform까지 남아있는 상태로 FBX 내보내기를 거치며 축 변환이 꼬인 것. Blender에서 전체 메쉬에 `transform_apply(location, rotation, scale)`를 적용해 오브젝트 위치를 전부 (0,0,0)으로 베이크한 뒤 재수출 → Unity에서 재확인하니 정상적으로 렌더러 바운즈가 합리적인 크기(1.24m 키)로 나오고, 펀치 자세가 실제로 팔다리에 반영됨을 확인
5. **앞/뒤 방향 검증** — 사용자가 "눈이 있는 쪽을 뒤로 판단한 것 같다"고 재확인 요청. 회전 없는 레스트 포즈를 정측면(카메라가 -X에서 바라보는 직교 뷰, 화면 오른쪽=Unity +Z)으로 캡처해 턱 밑 물방울이 +Z 쪽으로 튀어나온 것을 확인 — **얼굴이 Unity의 기본 정면 방향(+Z, `transform.forward`)과 정확히 일치함을 확인, 버그 아니었음**. 앞서 헷갈렸던 펀치 스크린샷은 애니메이션이 캐릭터를 회전시킨 상태를 임의의 대각선 각도에서 찍어서 오해를 준 것

## 교훈

- **Armature 모디파이어로 스키닝한 메쉬는 반드시 Transform을 적용(location/rotation/scale = identity로 베이크)한 뒤 FBX로 내보낼 것.** 오브젝트 자체에 위치값이 남아있으면 스키닝된 메쉬의 좌표 변환이 꼬일 수 있음 — Blender→게임엔진 리깅 파이프라인의 표준 관행인데 이번에 직접 버그로 겪고 확인함
- Blender에서 뼈대 포즈 테스트로 "잘 움직인다"고 확인해도, 그건 Blender 내부에서 모디파이어가 실시간으로 적용된 결과일 뿐이라 **FBX로 내보낸 뒤 실제 대상 엔진(Unity)에서 다시 검증해야 진짜로 통하는지 알 수 있다** — 이번 세션에서 실제로 export 전엔 안 보이던 버그를 export 후 Unity 테스트에서 발견
- 앞/뒤 방향 같은 좌표계 관련 의심은 회전이 없는 레스트 포즈를 정확한 축 방향의 직교 뷰로 캡처해서 확인하는 게 가장 확실함. 애니메이션이 적용된 임의 각도 스크린샷만으로는 오해하기 쉬움
