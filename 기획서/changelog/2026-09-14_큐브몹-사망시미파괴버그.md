# 큐브 몹 — HP 0이 돼도 안 죽고 "유령"으로 남던 버그

## 배경

사용자가 같은 경로의 새 영상을 보며 "공격을 하다가 무빙을 하면 몹 하나가 가만히 서있기만 해"라고 리포트. 라이브 세션을 직접 확인해보니 광(Gwang)이 `HP=0/60`인데도 계속 씬에 남아서 `state=Busy`로 공격 사이클을 계속 돌고 있었고, 평(Pyeong)/원(Won)/흡(Heup)도 전부 HP 0인데 사라지지 않고 있었음. `GwangWarningIndicator`가 42개나 쌓여있던 것도 재확인.

## 원인

`CubeEnemyBase.OnDeath()`의 기본 구현이 **빈 채**였음 — HP가 0이 되면 `isDead` 플래그만 세팅하고 아무 것도 안 함. `TakeDamage()`는 `isDead`일 때 재호출을 막을 뿐, `Update()` 자체는 계속 정상 실행돼서 죽은 몹이 계속 추격/공격을 이어감. 5종 중 [[CubeEnemyBun]]만 자기만의 `OnDeath()`를 오버라이드해서 실제로 `Destroy(gameObject)`를 호출했기 때문에 유일하게 제대로 사라지고 있었음.

덤으로 `CubeEnemyBun.OnDeath()`에도 같은 계열의 버그 발견 — `if (isMinor) return;`으로 조기 종료하면 맨 아래 파괴 호출까지 건너뛰어서, **미니언은 죽어도 절대 안 사라졌음**(무한분열 방지 자체는 의도대로 됐지만, 죽었을 때 사라지는 것 자체가 스킵됨).

## 수정

- `CubeEnemyBase.OnDeath()` 기본 구현을 `Destroy(gameObject)`로 변경 — 종별 특수 처리가 필요하면(예: Bun의 분열) 오버라이드에서 처리 후 `base.OnDeath()`를 마지막에 호출하는 패턴으로 문서화.
- `CubeEnemyBun.OnDeath()`를 `if (isMinor) return;` 조기 종료 대신 `if (!isMinor) { ...분열... }` 형태로 바꿔서, 분열 여부와 무관하게 항상 `base.OnDeath()`(파괴)까지 도달하게 함.
- `CubeEnemyBase.Update()` 맨 앞에 `isDead` 체크 추가 — `Destroy()`가 다음 프레임에야 실제 반영되는 지연 특성이 있어서, 그 사이 한두 프레임 계속 움직이는 것도 방어.

## 검증

라이브 세션에서 재컴파일(Play 유지) 직후 확인 — HP 0이던 `CubeTestEnemy_Gwang`이 실제로 씬에서 사라짐(`없음(정상적으로 죽음)`). 나머지(평 HP=40/원 HP=100/분 HP=10/흡 HP=25)는 아직 안 죽은 상태로 정상 존재.

## 한계 / 참고

- 42개 쌓여있던 `GwangWarningIndicator`는 재컴파일만으로는 안 없어짐(런타임 오브젝트라 Play를 실제로 정지해야 사라짐) — Play를 끄고 다시 확인하니 정상적으로 정리됨. **재컴파일은 Play 세션을 유지할 수 있지만, 그 세션에서 이미 쌓인 런타임 잔재까지 지워주진 않는다**는 걸 다시 확인.
- "공격 후 이동하면 몹 하나가 가만히 서있는다"는 증상이 정확히 이 버그였는지는 100% 확정은 아니지만(죽은 몹도 코드상 계속 움직이려 시도하긴 함), HP 0인 좀비 상태 자체가 명백한 버그였고 지금 고쳤음 — 다시 확인 필요.
