# 방A 바닥 구멍 버그 수정 (실제 플레이로 발견)

## 배경

사용자가 [[changelog/2026-09-11_1층-멀티룸던전-파일럿]] 직후 직접 플레이하다가 "지형이 제대로 되어있지 않아서 전진하면 바닥으로 떨어진다"고 스크린샷과 함께 리포트.

## 원인

`MultiRoomFloor1Builder.BuildFromCLI()`에서:

```csharp
Scene scene = EditorSceneManager.OpenScene(ScenePath, OpenSceneMode.Single);
GameObject ground = GameObject.Find("Ground");
if (ground != null) ground.transform.localScale = new Vector3(3f, 1f, 3f); // ← 여기서 키움
Floor1CorridorBuilder.BuildFromCLI(); // ← 근데 이 안에서 씬을 디스크에서 "다시" 엶
```

`Floor1CorridorBuilder.BuildFromCLI()`가 내부적으로 `EditorSceneManager.OpenScene()`을 다시 호출해서 씬을 디스크에서 새로 불러오는데, 그 직전에 저장하지 않은 `Ground` 리스케일이 통째로 날아갔다. 결과: 벽·복도·연결통로는 새 크기(half=15, 30x30)로 정상 생성됐는데, 실제 바닥(`Ground`)만 옛 10x10 그대로 남아서 **벽은 멀리 있고 바닥은 중앙의 작은 정사각형뿐인 상태** — 그 사이 전부가 뚫린 구멍이었다.

## 진단

라이브 씬(사용자가 방금 플레이한 바로 그 Unity 인스턴스, 같은 PID)에서 `Physics.Raycast` 스윕으로 X=25(복도 끝)부터 X=-126(방D)까지 1m 간격으로 바닥 콜라이더 존재 여부를 실측:

```
x=14 ~ x=6   NO HIT (구멍) — 방A 동쪽 절반
x=-6 ~ x=-14 NO HIT (구멍) — 방A 서쪽 절반
```

정확히 옛 Ground 경계(±5) 바로 바깥부터 새 벽 경계(±15) 안쪽까지가 통째로 뚫려있었음 — 원인 가설과 정확히 일치.

## 수정

Ground 리스케일을 `Floor1CorridorBuilder.BuildFromCLI()` 호출 **이후**로 옮김(그 함수가 씬을 다시 여는 걸 이제는 먼저 끝내놓고, 그다음에 리스케일). 재검증: 같은 레이캐스트 스윕으로 X=25~-126 전 구간 구멍 0개 확인(단, 에디터 모드에서 콜라이더를 막 옮긴 직후엔 `Physics.SyncTransforms()`를 명시적으로 호출해야 레이캐스트가 최신 상태를 보는 것도 같이 확인함 — 안 그러면 방금 옮긴 콜라이더가 물리 엔진에 아직 반영 안 된 상태로 조회돼서 오탐이 남).

## 덤 — NavMesh 재베이크

콘솔에 "Failed to create agent because it is not close enough" 경고가 반복되던 것도 확인 — 방A가 커지고 방B/C/D가 새로 생겼는데 NavMesh는 옛 10x10 기준으로 구워진 채였음. `bake_navmesh` 커맨드로 재베이크 완료(베이크 성공, 3ms).

## 교훈

- **여러 에디터 스크립트를 이어서 호출할 때, 그중 하나라도 `EditorSceneManager.OpenScene()`으로 씬을 다시 여는지 반드시 먼저 확인할 것** — 저장 안 된 이전 변경사항이 조용히 사라짐(에러도 안 남음)
- **에디터 모드에서 콜라이더를 코드로 옮긴 직후 `Physics.Raycast`로 검증할 땐 `Physics.SyncTransforms()`를 먼저 호출할 것** — 안 그러면 방금 옮긴 결과가 아니라 이전 상태를 보고 오탐/오검증하게 됨
- 지형을 새로 만들 때마다 NavMesh 재베이크를 체크리스트에 넣을 것
