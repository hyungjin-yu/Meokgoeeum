# 2026-08-25 — 설정 UI(마우스 감도 슬라이더) 신규 + 감도 미적용 버그 수정

## 배경

`CLAUDE.md`에 오래 남아있던 "설정 UI를 실제로 만들 때 `MouseSensitivitySetting.SetSensitivity()`를
슬라이더에 연결" 항목 진행. 프로젝트에 설정 UI 자체가 아예 없었음(Canvas/EventSystem도 없음).

## 한 일

### SettingsMenu.cs 신규

[[NarrationManager]]/[[ColorOrbPool]]과 같은 이유(아트 에셋 없음)로 UI를 손으로 만들지 않고
`Awake()`에서 코드로 직접 생성. Esc로 열고 닫는 오버레이 패널 + 마우스 감도 슬라이더(0.1~3.0)
하나뿐인 최소 버전. 프로젝트가 New Input System 전용(`activeInputHandler: 1`)이라 uGUI
상호작용에 필요한 `EventSystem`+`InputSystemUIInputModule`이 씬에 없으면 같이 생성.
일시정지(`Time.timeScale`)나 플레이어 입력 차단은 스코프 밖(오늘은 "슬라이더 연결"까지) — 진짜
일시정지 메뉴로 키우려면 별도 작업 필요.

Unity에서 `SC_Game`에 빈 GameObject + `SettingsMenu` 컴포넌트 부착으로 배치, 정상 렌더링 확인.

### ⚠️ 심각한 기존 버그 발견·수정: 감도 슬라이더가 카메라에 전혀 안 먹히던 문제

슬라이더는 정상 작동(드래그되고 값도 바뀜)하는데 실제 마우스 룩 감도가 전혀 안 바뀌는 증상 발견.

**원인**: `MouseSensitivitySetting`이 `new PlayerInputActions()`로 **자기 혼자만의 인스턴스**를
만들어서 그 위의 Look 액션에 `ApplyParameterOverride`로 배율을 걸고 있었음. 하지만 실제로 카메라를
돌리는 건 [[Cinemachine]]의 `CinemachineInputAxisController`인데, 이건 **자기 자신의
`InputActionReference`로 원본 `.inputactions` 에셋을 직접 읽음** — `MouseSensitivitySetting`이
만든 인스턴스도, `PlayerController`가 만든 인스턴스도 전부 서로 다른 별개의 복제본이라 카메라가
실제로 읽는 값과 완전히 무관했음. ([[changelog/2026-08-24_입력시스템-리팩토링]]의 "PlayerInputActions
4중 생성" 버그와 같은 계열의 문제지만, 이번엔 Cinemachine이 자체적으로 별도 인스턴스를 갖는
다른 메커니즘이라 그때 리팩토링으로는 못 잡았음)

**수정**: Input Action 인스턴스를 건드리는 대신, Cinemachine이 매 프레임 실제로 곱하는
`CinemachineInputAxisController.Controllers[i].Input.Gain` 값(Look Orbit X/Y 컨트롤러의 기준
감도 20/-20) 자체를 "기준 Gain × 배율"로 직접 갱신하는 방식으로 재작성. 이건 카메라가 읽는
최종 값이라 인스턴스 불일치가 원천적으로 발생할 수 없음.

## 검증

Unity 컴파일 에러 없음 확인, 슬라이더 드래그 시 실제 마우스 룩 감도가 체감상 바뀌는 것까지
사용자 확인 완료.

## [2026-08-25 추가] 일시정지 기능

사용자 피드백: "설정 만지는 동안 적한테 맞아서 게임오버 되면 UX가 너무 불쾌함". `SettingsMenu`가
열리는 순간 `Time.timeScale = 0`으로 바꾸도록 수정 — 프로젝트의 모든 전투/이동 타이머가 스케일드
`Time.deltaTime`/`Time.time` 기반이라(오늘 만든 [[BossHealth]] DPS 계측 포함) 이것만으로 적
AI/공격/이동이 전부 같이 멈춤, 별도로 `PlayerController` 입력을 잠글 필요 없음. `SettingsMenu`
자신의 Esc 폴링은 `Time.deltaTime`을 안 써서 멈춘 동안에도 계속 동작(안 그러면 못 닫힘).
싱글턴이 파괴될 때 `timeScale=0`이 박제되지 않도록 `OnDestroy()` 방어 코드도 추가.

**[2026-08-25]** Unity 컴파일 에러 없음 확인, Esc로 멈추면 적 AI/공격/이동이 실제로 전부 멈추는 것까지 사용자 확인 완료.
