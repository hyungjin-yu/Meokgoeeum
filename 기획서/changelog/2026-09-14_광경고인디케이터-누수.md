# 광(Gwang) 경고 인디케이터 누수 — Busy 강제 중단 시 정리 안 되던 버그

## 배경

몹 겹침 수정 확인 중 사용자가 스크린샷 공유 — Hierarchy에 `GwangWarningIndicator`가 수십 개 쌓여있는 것을 보고 "옆에 하이그로시는 뭐야"(그 반투명 빨간 원판들이 뭐냐)라고 질문. 실제로 세보니 **42개**가 쌓여있었음.

## 원인

`CubeEnemyBase.Update()`의 Busy 상태 처리:

```csharp
case MacroState.Busy:
    if (!sameFace) { EnterSearching(); break; } // ← OnBusyTick()을 완전히 건너뜀
    OnBusyTick();
```

플레이어가 면을 벗어나면 Busy 상태를 그 즉시 강제로 Searching으로 전환하는데, 이 경로가 `OnBusyTick()`을 아예 건너뛰어버림. [[CubeEnemyGwang]]은 정상적으로는 `EnterAttackActive()`(Active 단계 진입 시점)에서만 `DespawnWarningIndicator()`를 호출하는데, Windup 도중 면 이탈로 강제 중단되면 `EnterAttackActive()`를 아예 못 거치고 넘어가서 경고 인디케이터가 참조를 잃은 채(다음 공격 때 `warningIndicator` 필드가 새 오브젝트로 덮어써짐) 영원히 남게 됨. 오늘 세션 내내 플레이어를 이 면 저 면으로 옮기며 테스트한 게 누적된 것.

## 수정

`CubeEnemyBase`에 `protected virtual void OnBusyInterrupted() { }` 훅 신규 — 면 이탈로 Busy가 강제 중단될 때 `EnterSearching()` 직전에 호출. `CubeEnemyGwang`이 이걸 오버라이드해서 `DespawnWarningIndicator()`를 호출하도록 연결.

## 검증

임시 오브젝트로 재현: Busy(Windup) 상태로 강제 진입 + 인디케이터 스폰 → 플레이어를 다른 면으로 이동(`sameFace=false` 유발) → `Update()` 1회 호출 → `state`가 `Searching`으로 정상 전환됨과 동시에, 콘솔에 `Destroy()` 호출 로그(에디터 모드 경고)가 실제로 찍히는 것 확인 — `OnBusyInterrupted()`가 정상적으로 발동해서 `Destroy()`까지 이어짐.

## 한계

- Play 세션이 끝나면 런타임 전용 오브젝트라 42개는 자동으로 사라짐(씬 파일엔 저장 안 됨) — 별도로 수동 정리는 필요 없었음.
- 다른 종(원의 투사체 등)도 비슷하게 "Busy 도중에만 존재하는 임시 오브젝트"가 있는지 재검토가 필요할 수 있음 — 원은 투사체를 Windup이 끝나는 순간(EnterAttackRecovery)에 1회 생성하고 자체 lifetime으로 사라지는 구조라 이 문제와는 무관함을 코드로 확인.
