# 히트스탑 — Time.timeScale이 0에 고정돼서 화면이 안 움직이던 버그

## 배경

큐브 프로토타입을 플레이하던 사용자가 화면이 완전히 멈춘 스크린샷을 공유("화면이 여기서 안움직여") — Play는 진행 중이고 콘솔에 에러/경고도 0개인데 게임 화면만 정지된 상태.

## 원인

`eval`로 `Time.timeScale`을 직접 찍어보니 실제로 `0`으로 고정돼있었음. [[BrushWeapon]]의 히트스탑 연출이 원인:

```csharp
private System.Collections.IEnumerator HitStop()
{
    float original = Time.timeScale; // 이 순간 이미 0이면?
    Time.timeScale = 0f;
    yield return new WaitForSecondsRealtime(0.05f);
    Time.timeScale = original; // 이미 0이었던 값으로 "복귀"
}
```

타격 판정마다 `StartCoroutine(HitStop())`을 부르는데, 히트스탑 코루틴 두 개가 겹치면(연속 타격이 0.05초 실시간 안에 또 들어오는 등) 두 번째 코루틴이 "복귀할 값"으로 이미 `0`이 된 `timeScale`을 캡처해버림 — 첫 번째 코루틴이 끝나 `1`로 되돌려도, 그 직후 두 번째 코루틴이 자기가 캡처해둔 `0`으로 다시 덮어써서 영원히 멈추는 구조. `WaitForSecondsRealtime`이라 `timeScale`과 무관하게 흐르는 실시간 기준이라 코루틴 자체는 정상 종료되지만, "복귀값 캡처" 방식 자체가 겹침에 취약했음.

## 수정

캡처한 "원래 값"으로 복귀하는 대신, 진행 중인 히트스탑 개수(`hitStopDepth`)를 세서 그게 0이 될 때만 `1`로 되돌리도록 변경:

```csharp
private static int hitStopDepth;

private System.Collections.IEnumerator HitStop()
{
    hitStopDepth++;
    Time.timeScale = 0f;
    yield return new WaitForSecondsRealtime(0.05f);
    hitStopDepth--;
    if (hitStopDepth <= 0)
    {
        hitStopDepth = 0;
        Time.timeScale = 1f;
    }
}
```

이 게임에서 히트스탑을 거는 곳은 여기 하나뿐이라 "기본값은 항상 1"이라는 전제가 안전함(일시정지 메뉴 `SettingsMenu`/`TutorialSkipManager`도 캡처 없이 리터럴 0/1을 직접 대입하는 같은 패턴).

## 검증

`eval`로 `Time.timeScale = 1f` 즉시 되돌려서 화면 멈춤 우선 해제. 코드 수정 후 재컴파일 성공(`recompile_status` → `completed`, 에러 없음). 실전에서 연속 타격 시 재발 안 하는지는 사용자 쪽 확인 필요.

## 한계

겹침이 정확히 어떤 조작(연타 타이밍? 프레임 드랍?)으로 발생했는지 실시간 재현은 못 함 — 발견 당시 이미 멈춰있는 상태였음. 원인은 코드 리뷰로 확정(겹침에 취약한 유일한 지점), 카운터 방식으로 겹쳐도 안전하게 만들어서 재현 조건과 무관하게 해결됨.
