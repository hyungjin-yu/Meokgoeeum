#changelog #먹괴음 #v0.2 #전투

# 2026-08-18 — 색 스킬 3종 구현 (강타/흐름/번쩍) — v0.2 착수

## 배경

v0.1 완성 + 구르기로 밸런스 이슈 해결 후, [[09 개발 마일스톤]] v0.2 항목 중 "색 스킬 3종 구현(빨강, 파랑, 노랑)"부터 착수. 이미 완성된 [[04 색 구슬 시스템]] 위에 바로 얹을 수 있어서 v0.2 중 가장 리스크가 낮은 항목으로 판단해 먼저 진행 (큐브 좌표계+Addressables 면 전환처럼 무거운 항목은 이후로 미룸).

## 한 일

- **`ColorSystemManager.cs`** — `TryConsumeOrb(OrbColor)` 추가. 보유량 있으면 1개 소모하고 true, 없으면 false. FIFO 순번용 `acquisitionOrder` 큐도 같이 정리해야 해서(안 그러면 나중에 AddOrb의 FIFO 교체가 이미 소모된 항목을 또 지우려다 음수가 남) `RemoveOneFromAcquisitionOrder()` 헬퍼 동반 추가
- **`IKnockbackable.cs` 신규** — 대미지(`IDamageable`)와 같은 이유로 넉백도 별도 인터페이스로 분리
- **`EnemyPyeong.cs`** — `IKnockbackable` 구현. 넉백 중엔 `NavMeshAgent`를 꺼서 경로 이동과 충돌 안 하게 하고, 끝나면 `agent.Warp()`로 NavMesh 위치 재동기화 + 공격 상태 리셋. 넉백 시간(0.25초)은 프레임 데이터 문서에 없어서 v0.2 초안값으로 임의 지정
- **`Assets/Input/PlayerInputActions.inputactions`** — `Skill1`(빨강)/`Skill2`(파랑)/`Skill3`(노랑) 버튼 액션 신규, 키보드 1/2/3 바인딩
- **`ColorSkillController.cs` 신규**:
  - **강타(빨강)**: Startup 후 전방 대시(5f/0.15초) → 도착 지점에서 `공격력×2.0` 광역 히트. 쿨타임 8초
  - **흐름(파랑)**: Startup 후 전방 직선 박스 범위(길이6×폭2) 안 전체에 `공격력×1.5` 관통 히트(다수 적). 쿨타임 6초
  - **번쩍(노랑)**: Startup 후 주변 반경 4에 `공격력×1.0` + 넉백(힘 12). 쿨타임 10초
  - 공통 Startup은 [[27 전투 프레임 데이터]] 기준 10f(≈0.167초)
  - "공격력" 기준값은 `BrushWeapon.attackPower`를 그대로 참조(값 이중 관리 방지)

## 의도적으로 단순화한 부분

- **슬롯 매핑**: 원안은 "1~6 슬롯"이 FIFO로 계속 바뀌는 구조지만, 아직 슬롯을 보여줄 UI가 없어서 "1=빨강/2=파랑/3=노랑 고정, 해당 색 구슬 보유 중이면 그 키로 즉시 사용"으로 단순화. UI가 생기면 실제 동적 슬롯 매핑으로 교체 필요
- **콤보 캔슬 연동**: [[27 전투 프레임 데이터]]는 "콤보 중 스킬 캔슬(Recovery 어느 시점이든 가능)"을 명시하지만, 이번엔 `BrushWeapon`과 완전히 독립적으로 동작하게만 구현. 나중에 붙일 것
- **넉백 값**: 힘/지속시간 모두 프레임 데이터 문서에 없는 v0.2 초안값 (실측 후 조정 대상)

## Unity에서 해야 할 일

- `Player` 오브젝트에 **`ColorSkillController.cs` 부착**
- 에디터를 열면 `PlayerInputActions.inputactions` 변경사항이 자동 리임포트되며 `Skill1/2/3`이 생성 파일에 채워짐 — 리임포트 전 잠깐 컴파일 에러가 보여도 정상
- 플레이테스트: 각 색 구슬을 보유한 상태에서 1/2/3 키로 스킬 발동 확인, 구슬 없을 때 실패 로그 확인, 번쩍의 넉백으로 평이 실제로 밀려나는지 확인
