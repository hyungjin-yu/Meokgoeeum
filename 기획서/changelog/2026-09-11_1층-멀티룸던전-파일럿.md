# 1층 멀티룸 던전 파일럿 (맵 크기 3배 + 방 4개 체이닝)

## 배경

[[changelog/2026-09-11_플레이타임-확장-스코프결정]]에서 세운 블루프린트를 실제로 Unity에 지었다. 사용자 추가 요청: "맵 바닥의 크기는 3배로 늘려".

## 구조

`Floor1CorridorBuilder.cs` 수정 — `RoomEdgeX` 5f→15f(방A 10x10→30x30, 3배), `BuildRoomABoundaryWalls()`에 서쪽 문 옵션 추가(기존엔 서쪽이 통짜 벽이었음). `MultiRoomFloor1Builder.cs` 신규 — 방A 서쪽으로 연결 통로 + 방B/C/D(전부 동일 30x30)를 체이닝:

```
[입장 복도] (기존 유지, RoomEdgeX만 15로 확장 반영)
  --문--
[방A: 정육점 광장, X=0] 기존 튜토리얼 평×2 전투 그대로 + 곁가지 벽화→숨겨진 구슬(빨강) 추가
  --연결 통로(8m)--
[방B: 뒷골목 퍼즐, X=-38] 벽화 3개 색 복원 → PaintCountGate가 서쪽 문 막음 큐브 제거, 매복 평×2
  --연결 통로--
[방C: 상점가, X=-76] 평×3 전투 + 이동 장애물 2개(MovingObstacle 재사용)
  --연결 통로--
[방D: 클라이맥스, X=-114] 평×4 최종 웨이브 + 색 복원 연출용 벽화 2개 + 실제 계단(방A에서 이전)
```

방 중심 간 거리 38(30 + 연결통로 8), 총 4개 방 + 연결통로 3개 + 기존 복도 — [[28 레벨 디자인]]의 "3~5개 노드" 기준 안에 듦.

## 설계 결정 — 계단(면 전환 트리거) 재배치

기존엔 방A 클리어 → `Stairs`(면 전환 발동)가 바로 열렸음. 멀티룸이 되면서 이건 방D의 역할이어야 해서, 기존 `RoomClearGate`+`Stairs` 오브젝트를 그대로 방D로 옮겨 재사용했다(새로 안 만듦 — 이미 테스트된 컴포넌트라 위치·참조만 바꿈). 방A는 이제 튜토리얼 전투만 계속하고 "다음 방 잠금"은 없음(서쪽 문이 처음부터 열려있음) — [[28 레벨 디자인]] 체크리스트 "처음 겪는 실수를 용서하는 여유" 원칙에 맞춰 방A/C는 전투를 강제로 막지 않고, 방B만 퍼즐로 확실히 게이팅했다.

## 신규 컴포넌트 — PaintCountGate.cs

`Assets/Scripts/Level/PaintCountGate.cs`. `PaintableObject` 여러 개(순서 무관)를 등록해두고 전부 복원되면 지정한 오브젝트(문 막음 큐브)를 비활성화한다. 기존 `HiddenOrbSpawner`("복원 1개 → 구슬 1개")와 다른 패턴("복원 N개 → 문 1개")이라 별도로 만들었고, 둘 다 `PaintableObject.OnPainted` 이벤트를 그대로 재사용해서 `PaintableObject` 자체는 안 건드렸다.

## 발견 — 기존 씬에 비활성 상태의 미사용 콘텐츠 존재

`SC_Face_0`에 `BossPo`, `Wave1~3SpawnPoint`, `EnemyWon`/`EnemyBun`/`EnemyHeup`가 전부 비활성(inactive) 상태로 남아있는 걸 발견 — 과거 보스 밸런싱 테스트([[changelog/2026-09-02_보스밸런스-1차조정]] 등) 때 쓰인 흔적으로 보인다. 이번 작업에서 전혀 건드리지 않았고(비활성이라 안전), 새 방들은 전부 이들과 겹치지 않는 서쪽(-X) 방향으로 이어붙였다.

## 검증

- 컴파일 에러 0, 실행 후 콘솔 에러 0
- 좌표 실측으로 확인: 방B/C/D 중심 X=-38/-76/-114, 문 막음 큐브 X=-53(방B 서쪽 경계와 일치), 계단 X=-126(방D 서쪽 끝), Pyeong 개수(정적 배치분) 9마리(방A 튜토리얼분은 EncounterSpawner가 런타임에 생성해서 에디터 타임엔 0마리 — 정상)
- Scene View 스크린샷 3장 — 직교 투영 탑다운(4개 방이 일렬로 이어진 전체 구조 확인), 방A 내부(커진 규모 확인), 방D 내부(클라이맥스 웨이브 배치 확인)
- 아트 드레싱(건물+등불)을 서쪽 벽(이제 문이 생김)에서 남쪽 벽(여전히 통짜)으로 재배치 — 실측 후 역산으로 좌표 계산, 축 보정 회전 유지 패턴 그대로 적용
