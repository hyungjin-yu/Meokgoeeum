# 2026-08-20 — 3층 콘텐츠 준비 (전봇대 거리)

## 배경

2층 검증 완료 후 [[19 층별 상세 설계]] 순서대로 3층으로 이어감. 3층은 평×2+원×1, **첫 원거리 적 등장**, 계단 조건은 다시 "전투 클리어"라 1층에서 쓴 `RoomClearGate`+`Stairs` 패턴 그대로 재사용 가능 — 새 코드는 필요 없었습니다.

## 한 일

- **코드 변경 없음** — 기존 `RoomClearGate`/`Stairs`/`EnemyPyeong`/`EnemyWon` 스크립트를 그대로 재사용
- **[[logic/3층 콘텐츠 - 전봇대 거리 씬 설정]] 신규** — 3층은 `SC_Face_2`가 아예 새 씬이라, [[logic/큐브 좌표계 씬 설정]]의 면 추가 절차(Addressable 등록 + `CubeFaceData_2` + `GameState.faceData[2]` 연결)부터 다시 필요함을 정리. 추가로 `EnemyWon` 프리팹이 아직 없다는 걸 발견해서(지금까지 `EnemyPyeong`만 프리팹화함) 0단계로 만드는 절차 포함

## Unity 검증 완료 (2026-08-20)

[[logic/3층 콘텐츠 - 전봇대 거리 씬 설정]] 0~5단계 그대로 진행 — `EnemyWon` 프리팹 최초 생성, `SC_Face_2` 신규 씬, Addressable 등록, `CubeFaceData_2`(Face Index 2) → `GameState.faceData[2]` 연결(회전 경로: 0면 --Y축--> 4면 --Z축--> 2면), 평×2/원×1 배치, `RoomClearGate`+`Stairs`까지 전부 정상 동작 확인. 평×2+원×1 전멸 → `RoomClearGate 클리어! 계단 활성화.` → `Stairs` 사용 → 정상 회전.

### 부수 발견 — "반복 층에서 EncounterSpawner가 재발동"은 버그가 아니라 의도한 동작

3층 테스트 도중 `EnemyPyeong(Clone)`이라는 예상 밖의 개체가 죽는 로그가 보여서 처음엔 의심했으나, 곧이어 계단으로 1층(면 0)에 재방문했을 때 `[EncounterSpawner] "1웨이브" 시작!`이 `[CubeMapManager] 0면 첫 재방문! (나레이션: Hint)`와 함께 또렷이 재현되는 걸 보고 원인이 확정됨: **`EncounterSpawner.autoStart`는 씬이 로드될 때마다(재방문 포함) 다시 발동**하고, 이건 [[19 층별 상세 설계]]의 "반복 층 — 같은 면을 다시 방문하면 전투/연출이 다시 일어난다" 설계와 정확히 맞아떨어지는 의도된 동작입니다. 별도 수정 불필요 — 오히려 나레이션 시스템(`MarkVisited`)과 자연스럽게 맞물려서 작동한다는 걸 확인한 셈.
