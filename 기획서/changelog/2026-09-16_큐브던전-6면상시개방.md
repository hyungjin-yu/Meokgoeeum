# 큐브 던전 — 선형 경로 폐기, 6면 전부 상시 개방 + "전체 클리어" 조건

## 배경

방금 완료한 6면 확장([[changelog/2026-09-16_큐브던전-6면확장및마무리]])이 A→B→E→C→D→F 순서로 문이 하나씩 열리는 **선형** 구조였는데, 사용자가 즉시 "꼭 A~F가 아니라 각 면마다 문을 추가해서 층 클리어 조건을 모든 면의 몹 처치로 해"로 요청 — 순서 강제를 없애고 6개 방 전부를 자유롭게 오갈 수 있게, 층 클리어 조건도 "6개 방 전부 클리어"로 바꿈.

## 핵심 통찰

정육면체 각 면은 정확히 4개의 이웃(반대편 면 1개만 빼고)을 가지므로, **방의 4면(±U/±V)이 그 4개 이웃과 정확히 1:1 대응** — 남는 면도 부족한 면도 없음. 그래서 "모든 방의 4면을 전부 상시 개방"하기만 하면 자동으로 "인접한 어느 방으로든 자유롭게 오갈 수 있는" 구조가 완성됨. 문을 잠그는 로직(`GatedExit`/`doorBlocker`) 자체가 필요 없어짐.

## 결과물

- **`CubeDungeonRoomKit`**: `BuildOpenRoom()` 신규(4면 전부 `WallMode.Open`으로 여는 헬퍼). `PopulateRoomA~F` 전부 `doorBlocker` 매개변수 제거 + 전부 `RoomClearGate`를 반환하도록 통일(전엔 D/F만 반환). `BuildRoomGate()`도 `doorBlocker` 매개변수 제거(`doorsToOpen`은 항상 빈 배열). `BuildFullFloor()`가 이제 `RoomClearGate[]`(6개 전부)를 반환.
- **`RoomClearGate.OnCleared`**: `System.Action` → `System.Action<RoomClearGate>`로 변경 — 게이트 6개를 동시에 구독할 때 "어느 게이트가 클리어됐는지" 알아야 진행률을 셀 수 있어서, 클리어되는 순간 자기 자신을 인자로 넘기도록 함.
- **`CubeDungeonProgressionManager`**: 단일 게이트 구독(`HookGate`)에서 다중 게이트 구독(`HookGates`)으로 재작성. `clearedGates`(HashSet)로 몇 개나 클리어됐는지 추적, `advancing` 플래그로 중복 트리거 방지. `Start()`가 이제 `RoomClearGate_A`~`F` 6개 전부를 찾아서 구독.

## 검증

- 재컴파일 에러 없음, 재빌드 성공.
- Play 모드에서 6개 게이트 전부 `doorsToOpen=0`, `DoorBlocker_` 오브젝트 0개(전부 안 쓰임) 확인.
- 방A의 4면(±U/±V) 전부 문 틈에서 `WouldCollide()=False`(자유롭게 통과 가능) 확인.
- **6개 게이트의 `OnCleared`를 순서대로 5개만 먼저 발동 → `currentFloor` 그대로 1(안 넘어감) 확인 → 6번째(F)까지 발동 → 콘솔에 "방 클리어 진행 1/6" ~ "6/6" 정확히 순서대로 로그, "1층 전체 클리어!"가 정확히 6/6 시점에만(5/6에선 안 뜸, 중복도 없음) 발동함을 확인.** 다만 이 자동화 환경이 Play 중 실제 프레임 진행이 불안정한 기존 한계 때문에, 트리거된 페이드 코루틴이 실제로 층 전환을 완료하는 것까지는 이번엔 확인 못 함(로직 자체는 위에서 완전히 검증됨).

## 한계

- 실제로 사용자가 6개 방을 자유 순서로 돌며 전부 클리어했을 때 화면상 정상적으로 다음 층으로 넘어가는지는 직접 플레이로 최종 확인 필요.
- 방A의 좌클릭 공격 힌트(`showFirstAttackHint`)는 여전히 A에만 붙어있음 — 자유 순서 구조에서 사용자가 A를 제일 나중에 들어가면 힌트가 늦게 뜰 수 있음(경미한 문제, 필요하면 나중에 조정).
