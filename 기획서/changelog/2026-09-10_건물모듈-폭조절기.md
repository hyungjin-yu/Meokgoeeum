# 건물 모듈 폭 조절기 — ModularPanelWidth

## 배경

건물 모듈 1차 제작 직후, 사용자가 "창문 길이나 벽 길이도 건물 특성에 따라서 조절이 가능하면 좋겠는데"라고 요청. 기존 방식(그리드 2m 단위로 통짜 모듈을 반복 배치)은 2m 배수 길이만 가능해서, 임의의 폭도 지원하는 방법이 필요했다.

## 확인 사항

Window_Cell_01.fbx를 Unity에 인스턴스화해서 실제 계층구조를 확인한 결과, 프레임 4조각·문살 2개·유리·벽 위/아래가 전부 별도 GameObject로 분리되어 있음을 확인 — 위치·재질을 CLI로 개별 조작하는 것 자체는 이미 가능했다. 다만 형태(폭) 자체를 조절하려면 프레임 두께까지 같이 늘어나는 문제(단순 스케일)를 피할 방법이 필요했다.

## 구현

`Assets/Scripts/Level/ModularPanelWidth.cs` — UI의 9-slice와 같은 원리:

- **Stretch**: 유리, 문살, 벽면(위/아래). 폭이 늘어난 만큼 그대로 커진다
- **Reposition**: 좌우 세로 프레임. 두께(스케일)는 고정, 바깥쪽으로만 밀린다
- **Fixed**: 중앙 세로 문살. 폭과 무관하게 그대로

기준 폭과 원하는 폭의 차이(delta)를 **비율이 아니라 덧셈**으로 반영하는 게 핵심 — 곱셈(비례) 방식이면 프레임 두께 같은 "고정돼야 할 값"까지 같이 늘어나 버린다. 각 파츠의 기준 배치는 처음 한 번만 캡처해서 직렬화 필드에 저장(에디터 재시작에도 유지).

## 진행 중 발견한 버그

1차 구현·테스트 시 `Apply()`가 코드로 나중에 추가한 규칙의 기준값을 캡처하지 않고 건너뛰는 버그 발견 — 테스트 로그가 "정상"처럼 보였지만, 실은 컴포넌트가 아무 일도 안 하고 원본 좌표를 그대로 출력한 것이었다(직접 비교 없이 "그럴듯한 숫자"만 보고 넘어갈 뻔함). `Apply()` 시작 시 `CaptureMissing()`을 항상 호출하도록 수정해서 해결.

이 과정에서 모듈 export 좌표 자체의 문제도 발견 — 처음 export한 모듈들이 로컬 원점이 아니라 데모 조립 당시의 절대 좌표(예: 창문 x=-3)를 그대로 갖고 있어서, "좌우 어느 쪽으로 밀어야 하는지" 판단하는 부호 계산이 틀어질 뻔했다. Blender에서 각 모듈을 X 중심 0으로 재정렬해서 재출고.

## 검증

`Window_Cell_01`에 폭 2.0 → 3.0m로 실제 적용:
- 프레임 두께(0.05m) 그대로 유지
- 유리·문살·벽면 정확히 delta(1.0m)만큼 커짐
- 좌우 프레임 대칭으로 0.5m씩 바깥으로 이동

좌표값 로그와 정면 직교 스크린샷 양쪽으로 확인 완료.

## 교훈

- 테스트 로그의 숫자가 "그럴듯해 보인다"고 실제로 코드가 그 값을 만들어냈다는 보장은 없다 — 이번처럼 원본 좌표와 우연히 비슷한 값이 나오면 버그를 놓치기 쉽다. 변경 전/후 값을 직접 비교하거나, 명백히 다른 값을 넣어 델타가 실제로 반영되는지 확인할 것
- 조립식 모듈을 개별 파일로 export할 때는 "이 모듈만 놓고 봤을 때 원점이 어디인지"를 export 시점에 항상 재정렬해야 한다 — 데모 조립 안에서의 위치를 그대로 들고 나오면 재사용 시 좌우/방향 판정이 꼬일 수 있다
