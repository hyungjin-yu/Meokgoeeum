## [2026-08-25 추가] CLI로 씬 배치 자동화

가이드 문서(`logic/1층 콘텐츠 - 입장 복도 & 방B 씬 설정.md`)의 0~3단계를 손으로 하는 대신
`Floor1CorridorBuilder.cs`(`Assets/Scripts/Editor/`, 에디터 전용)를 새로 작성해서 자동화했습니다.

- **알고리즘**: "복도 세그먼트 목록을 방 경계(`RoomEdgeX=5`)에서부터 바깥으로 이어붙이는"
  단순 마칭(marching) 방식. 세그먼트 배열(`1단계-직선복도` 폭4·길이6, `2단계-장애물구간`
  폭1.6·길이4)을 게임플레이 순서(입구→방A)대로 적어두고, 배치는 방 경계에서 역순으로 순회하며
  누적 X좌표(`cursorX`)를 밀어내는 식 — 세그먼트 폭이 바뀌어도(장애물 구간에서 좁아짐) 자동으로
  바닥/벽이 이어집니다.
- 세그먼트마다 바닥(얇은 Cube, 기존 Ground 상단 y=0에 맞춤) + 좌우 벽(Cube, `WallHeight=3`)을
  생성하고, 세그먼트 경계에 `TutorialCheckpoint`(`Checkpoint_CorridorEnd`/`Checkpoint_ObstaclePassed`)를,
  장애물 구간 중앙에 `MovingObstacle`(Y축 90도 회전으로 `transform.right`가 복도 폭 방향을
  향하게 만들어 "좌우로 오가며 막는" 느낌을 냄)을 배치합니다.
- 기존 `SpawnPoint`(이름 규칙으로 `CubeMapManager.TeleportPlayerToSpawnPoint()`가 찾음)를
  복도 입구로 옮기고 방 쪽을 보도록 회전까지 맞춥니다. 방B 간판(`Signboard_Floor1`,
  `PaintableObject` 부착)도 같이 생성.
- **실행**: `Unity.exe -batchmode -quit -nographics -projectPath <경로> -executeMethod
  Floor1CorridorBuilder.BuildFromCLI` — Unity 에디터가 꺼져 있는 상태에서 실행(둘 다 켜져
  있으면 씬 파일 충돌 위험이 있어 미리 `tasklist`로 Unity.exe 미실행 확인 후 진행).
- 재실행해도 안전 — 이전에 만든 `Floor1_Corridor_Generated` 그룹을 지우고 다시 생성(단,
  `Signboard_Floor1`은 이미 있으면 건드리지 않음 — 색칠 진행 상태 보존).

## [2026-08-25 추가] 장애물 통과 불가 버그 발견·수정

사용자 Play 테스트 결과: 장애물 구간에서 **아예 지나갈 수 없음**(구르기를 해도 막힘) 확인.
계산해보니 감으로 튜닝할 문제가 아니라 진짜 수치 버그였음 — 플레이어 `CharacterController`
반지름이 0.5(지름 1.0m, `SC_Game.unity`에서 확인)인데, 원래 값(장애물구간 폭 1.6m + 장애물
폭 1.0m + 진폭 1.2m)으로는 장애물이 가장 많이 비켜난 순간조차 열리는 틈이 **최대 0.9m** —
플레이어 지름보다 항상 좁아서 물리적으로 통과 불가능했음.

값 재계산해서 수정(`Floor1CorridorBuilder.cs`):
- 장애물구간 폭: 1.6m → **3.0m**
- 장애물 폭(막는 방향): 1.0m → **1.2m**(`ObstacleBlockWidth` 상수로 분리)
- 진폭(`travelDistance`): `narrowWidth - ObstacleBlockWidth - 0.2` 공식으로 역산 → 1.6
- 결과: 가장 비켜난 순간 틈 ≈ 1.7m(플레이어 지름 1.0m 대비 여유 0.7m), 장애물이 중앙에
  있을 때는 양쪽 다 0.9m로 막힘(의도대로 타이밍 유도) — 벽과 겹치지도 않음(여유 0.1m)

Unity 에디터를 닫은 상태에서 CLI(`-executeMethod Floor1CorridorBuilder.BuildFromCLI`)로
재실행 — 재실행 안전성 덕분에 씬 전체를 다시 열 필요 없이 `Floor1_Corridor_Generated`
그룹만 지우고 새 값으로 재생성됨. 컴파일 에러 0, exit code 0, 씬 diff로 `Obstacle_Slow`
scale=(1.2, 1.8, 1.5)/`travelDistance=1.6` 반영 확인.

## [2026-08-25 추가] 장애물+벽 사이에 낀 순간 바닥을 뚫고 떨어지는 버그 발견·수정

사용자 재테스트 결과: "장애물과 벽에 끼었을 때, 플레이어가 바닥을 뚫고 내려간다" 확인.

**원인**: `MovingObstacle`은 `Rigidbody` 없이 매 프레임 `transform.position`을 직접 옮기는
방식이라, 플레이어가 장애물과 벽 사이에 낀 순간 CharacterController를 물리적으로 밀어내지
못하고 그냥 겹쳐버릴 수 있음. 그 상태에서 `PlayerController`의 중력 처리(`cc.Move()`)가
큰 보정값을 내려보내면, Unity CharacterController는 연속 충돌 감지(continuous collision)가
아니라 매 `Move()` 호출마다의 스윕 검사라서, 순간적으로 큰 보정 이동은 얇은(0.1m) 바닥
콜라이더를 그냥 통과해버릴 수 있음(터널링).

**수정**: 근본 원인(장애물이 플레이어를 겹치는 것 자체)을 없애는 대신, 결과(바닥 뚫림)를
물리적으로 불가능하게 막는 쪽을 택함 — 복도 바닥 콜라이더 두께를 0.1m → **2m**로 키움
(`Floor1CorridorBuilder.FloorThickness`). 윗면은 그대로 y=0에 맞춰져서 시각적으로는 차이
없음. Unity 에디터 닫은 상태에서 CLI 재실행, 컴파일 에러 0·exit code 0, 씬에서
`Floor_1단계-직선복도` scale.y=2/position.y=-1 반영 확인.
