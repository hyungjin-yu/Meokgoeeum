## [2026-08-25 추가] 장애물 통과 불가 버그 발견·수정

사용자 Play 테스트 결과: 장애물 구간에서 **아예 지나갈 수 없음**(구르기를 해도 막힘) 확인.
계산해보니 감으로 튜닝할 문제가 아니라 진짜 수치 버그였음 — 플레이어 `CharacterController`
반지름이 0.5(지름 1.0m, `SC_Game.unity`에서 확인)인데, 원래 값(장애물구간 폭 1.6m + 장애물
폭 1.0m + 진폭 1.2m)으로는 장애물이 가장 많이 비켜난 순간조차 열리는 틈이 **최대 0.9m** —
플레이어 지름보다 항상 좁아서 물리적으로 통과 불가능했음.

값 재계산해서 수정(`Floor1CorridorBuilder.cs`):
- 장애물구간 폭: 1.6m → **3.0m**
- 장애물 폭(막는 방향): 1.0m → **1.2m**(`ObstacleBlockWidth` 상수로 분리)
- 진폭(`travelDistance`): `narrowWidth - ObstacleBlockWidth - 0.2` 공식으로 역산 → 1.6
- 결과: 가장 비켜난 순간 틈 ≈ 1.7m(플레이어 지름 1.0m 대비 여유 0.7m), 장애물이 중앙에
  있을 때는 양쪽 다 0.9m로 막힘(의도대로 타이밍 유도) — 벽과 겹치지도 않음(여유 0.1m)

Unity 에디터를 닫은 상태에서 CLI(`-executeMethod Floor1CorridorBuilder.BuildFromCLI`)로
재실행 — 재실행 안전성 덕분에 씬 전체를 다시 열 필요 없이 `Floor1_Corridor_Generated`
그룹만 지우고 새 값으로 재생성됨. 컴파일 에러 0, exit code 0, 씬 diff로 `Obstacle_Slow`
scale=(1.2, 1.8, 1.5)/`travelDistance=1.6` 반영 확인.

## [2026-08-25 추가] 장애물+벽 사이에 낀 순간 바닥을 뚫고 떨어지는 버그 발견·수정

사용자 재테스트 결과: "장애물과 벽에 끼었을 때, 플레이어가 바닥을 뚫고 내려간다" 확인.

**원인**: `MovingObstacle`은 `Rigidbody` 없이 매 프레임 `transform.position`을 직접 옮기는
방식이라, 플레이어가 장애물과 벽 사이에 낀 순간 CharacterController를 물리적으로 밀어내지
못하고 그냥 겹쳐버릴 수 있음. 그 상태에서 `PlayerController`의 중력 처리(`cc.Move()`)가
큰 보정값을 내려보내면, Unity CharacterController는 연속 충돌 감지(continuous collision)가
아니라 매 `Move()` 호출마다의 스윕 검사라서, 순간적으로 큰 보정 이동은 얇은(0.1m) 바닥
콜라이더를 그냥 통과해버릴 수 있음(터널링).

**수정**: 근본 원인(장애물이 플레이어를 겹치는 것 자체)을 없애는 대신, 결과(바닥 뚫림)를
물리적으로 불가능하게 막는 쪽을 택함 — 복도 바닥 콜라이더 두께를 0.1m → **2m**로 키움
(`Floor1CorridorBuilder.FloorThickness`). 윗면은 그대로 y=0에 맞춰져서 시각적으로는 차이
없음. Unity 에디터 닫은 상태에서 CLI 재실행, 컴파일 에러 0·exit code 0, 씬에서
`Floor_1단계-직선복도` scale.y=2/position.y=-1 반영 확인.

## [2026-08-31 추가] 팝업 힌트 UI 시스템 착수 (튜토리얼 폴리시 1/4)

[[15 튜토리얼 설계]] "키 안내 팝업" 6종 중 스코프 컷됐던 항목의 첫 단계. 전체(마우스 좌클릭/

- **`HintPopupManager.cs` 신규** — [[NarrationManager]](재방문 나레이션)의 "페이드 인 → 유지 →
  페이드 아웃" 코루틴 구조를 재활용한 재사용 가능 팝업. 글리치 연출 없이 화면 하단 토스트로

  `GameSystems`에 컴포넌트로 설치(`HintPopupManagerInstaller.cs`, 다른 전역 시스템들과 같은

- **`Floor1CorridorBuilder.cs`**: 스폰 지점에 새 체크포인트(`Checkpoint_CorridorStart`) 추가 →
  "WASD — 이동"(문서 타이밍: 게임 시작 직후). 기존 `Checkpoint_CorridorEnd`(장애물 구간 진입
  경계)에 "Space — 구르기" 연결(문서 타이밍: 장애물 구역 진입 시).

**버그 발견·수정**: 1차 테스트에서 "Space" 힌트가 설계 의도(장애물 접촉 1m+ 전)보다 훨씬 늦게,
실제로 장애물에 닿아야만 뜨는 것 확인 — 원인은 바닥/벽 뚫림과 같은 종류. 체크포인트 트리거
박스가 진행 방향(X)으로 0.5m뿐이라 플레이어가 한 프레임에 그 얇은 구간을 그냥 지나쳐버릴 수
있었음(트리거는 스윕 경로 전체가 아니라 매 프레임 위치 기준 판정). `CheckpointDepth` 상수로
분리해 0.5→**2m**로 키워서 해결 — **사용자가 재테스트로 "닿기 전에 뜨네" 확인 완료**.

**추가 버그 발견·수정 (좌클릭 공격 힌트 연결 중)**: 좌클릭 힌트를 붙이고 보니 "1웨이브 시작"
자체가 `EncounterSpawner.autoStart=true`라서 **씬 로드와 동시에**(플레이어가 아직 복도 저 끝에
있어도) 이미 일어나고 있었음 — "방 진입 직후 전투 시작"이라는 튜토리얼 의도와 어긋났고, 그
순간 뜬 좌클릭 힌트가 같은 프레임에 뜨는 WASD 힌트("HintPopupManager"는 새 힌트가 오면 이전
걸 즉시 교체) 때문에 안 보이는 부작용까지 있었음. `TutorialCheckpoint`에
`encounterSpawnerToStart` 필드 추가(도달 시 `StartEncounter()` 호출) → `autoStart`를 끄고
"장애물 통과" 체크포인트(`Checkpoint_ObstaclePassed`)에서 대신 시작하게 변경. CLI 재빌드,
컴파일 에러 없음, **사용자가 재테스트로 좌클릭 힌트 정상 표시 확인 완료**(Console 로그 순서도
WASD→Space→장애물통과→1웨이브 시작→좌클릭 힌트 순으로 의도대로 나옴).

이 테스트 중 세이브 파일(`playerHP: 15`)로 방A 진입 직후 사망하는 것도 확인 — 오늘 작업과
무관한 기존 저장값이라 `playerHP: 15→100`으로 복구(백업: `save_slot_0.backup_hp15.json`).

## [2026-08-31 추가] 락온 카메라 프레이밍 — 시도 후 보류

기획서 스펙(`CinemachineTargetGroup`으로 적 중심 재프레이밍)까지 마저 구현해봤지만, 실제로
플레이하면서 튜닝해야만 풀리는 문제가 연속으로 나와서 포기했습니다. 시행착오:

1. 기존 카메라를 `Object.Instantiate`로 복제해 `LockOnCamera`(`Follow`=새로 만든
   `LockOnTargetGroup`) 생성, 마우스 입력(`CinemachineInputAxisController`)은 꺼서 "적 중심
   고정" 컨셉대로 구현 → **평소엔 안 뜨게 `SetActive(false)`로 꺼둔 게 진짜 원인**: `GameObject.Find`가
   비활성 오브젝트를 못 찾아서(런타임/에디터 스크립트 공통) `LockOnController`가 이 카메라
   참조를 아예 못 얻어 전환 로직 자체가 죽어있었음 — "처음 만들 때와 전혀 달라진 게 없다"는
   증상으로 나타남.
2. 원인 파악 후 오브젝트는 항상 활성 상태로 유지하고 `Priority`(기본 -10/락온 시 20)로만
   전환하게 수정 → 카메라 전환 자체는 정상 동작하게 됐지만, 벽 쪽으로 궤도가 잡히면 마우스로
   못 돌리니 시야가 벽에 낀 채 못 빠져나옴(몬스터 안 보이고 공격도 못 피함) — 실제로 더 나쁜
   버그가 됨.
3. 마우스 입력을 다시 켜서 수동으로 빠져나올 수 있게 했더니 → 이번엔 마우스로 다 덮어쓸 수
   있어서 "고정 카메라"라는 컨셉 자체가 무의미해짐.
4. `CinemachineDeoccluder`(벽 충돌 회피)를 추가하고 마우스를 다시 끄는 "제대로 된" 방향으로
   갔더니 → 방A가 좁아서(10x10, 기존 궤도 반경 5m) 카메라가 거의 항상 "막혔다"고 판단해
   지나치게 확대되면서 플레이가 안 되는 새 문제 발생.

네 번의 라운드 모두 "고쳤더니 다른 게 깨짐"이 반복돼서, 이 이상은 CLI/코드만으로 수렴이 안
된다고 판단하고 **`LockOnController`가 카메라를 아예 안 건드리도록 롤백** — 회전/마커/타겟
전환(간소화 버전)만 유지. `LockOnCamera`/`LockOnTargetGroup`/`CinemachineDeoccluder`는
`SC_Game.unity`에 그대로 남겨둠(Priority -10, 절대 안 뜸) — 나중에 직접 플레이하며 궤도
반경/높이/Deoccluder 민감도를 눈으로 튜닝할 사람을 위한 밑작업.
