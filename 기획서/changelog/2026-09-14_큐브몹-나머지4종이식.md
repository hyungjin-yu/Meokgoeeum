# 큐브 면 몹 — 나머지 4종(원/분/흡/광) 이식

## 배경

[[changelog/2026-09-14_큐브몹-NavMesh포기-직선이동통일]]에서 `EnemyPyeong`을 `CubeEnemyBase`/`CubeEnemyPyeong`으로 옮긴 데 이어, 나머지 4종(원/분/흡/광)도 같은 패턴으로 이식.

## 결과물

- `Assets/Scripts/Player/CubeEnemyWon.cs` — 원본 [[EnemyWon]]과 전투 타이밍(윈드업 20/60초, 리커버리 16/60초)·투사체 로직 동일. 원본은 추격/후퇴/투척을 별도 top-level 상태로 뒀지만, 후퇴도 결국 "같은 면 위에서 반대 방향 이동"일 뿐이라 `OnChasingTick()` 안에서 거리 조건으로 분기(너무 가까우면 후퇴 이동, 사거리 안이면 투척, 아니면 추격) — 정지가 필요한 윈드업/리커버리만 Busy로 분리.
- `Assets/Scripts/Player/CubeEnemyBun.cs` — [[CubeEnemyPyeong]]과 전투 상태머신이 사실상 동일(원본도 "평과 완전히 같은데 복제로 남겨둠" 판단을 유지). 차이는 사망 시 분열 — [[CubeEnemyBase]]에 새로 추가한 `OnDeath()` 훅(HP 0 도달 시 정확히 1회 호출)에서 자기 자신을 복제해 미니언 2마리 생성(HP 절반, 크기 0.6배, `isMinor`로 무한분열 방지), 스폰 위치는 면 접선 방향으로만 흩어지도록 법선 축 성분 제거.
- `Assets/Scripts/Player/CubeEnemyHeup.cs` — 원본 [[EnemyHeup]]과 동일하게 **비공격 유닛**. HP 50% 밑으로 떨어지면 [[RestoredAreaRegistry]](월드 좌표 기반이라 큐브 면이든 평지든 그대로 재사용 가능)로 가장 가까운 색 복원 구역을 찾아가 흡수 회복, 회복 히스테리시스(한 번 시작하면 100%까지)도 그대로. 흡수 중은 Busy 상태(제자리 정지+회복)로 구현.
- `Assets/Scripts/Player/CubeEnemyGwang.cs` — 원본 [[EnemyGwang]]과 텔레그래프(25/60·8/60·20/60초, 5종 중 최장)·바닥 경고 인디케이터 동일. Pyeong과 차이대로 사거리 조건 없이 쿨다운만으로 공격 트리거.
- `CubeEnemyBase.cs`에 `OnDeath()` 가상 메서드 추가 — `TakeDamage()`가 HP 0 도달을 감지해서 정확히 한 번 호출(원본의 `EnemyHealth.OnDeath` 이벤트와 같은 역할, 여긴 별도 컴포넌트 없이 베이스가 직접 처리).

## 검증 — 리플렉션으로 4종 전부 핵심 동작 확인

임시 GameObject(씬에 저장 안 함)에 각 컴포넌트를 붙여서 확인:

- **원**: 근접 시 후퇴 이동(Chasing 유지), 사거리(2~5) 진입 시 Busy 전환
- **분**: `TakeDamage(9999)`로 즉사 → 미니언 2마리 생성 확인(`isMinor=True`, `maxHP=50` — 원본 100의 절반)
- **흡**: 70 피해로 저HP(30/100) → 회복구역 방향으로 이동(위치 변화로 확인) → 구역 도착 시 Busy 전환 + 회복(HP 상승 확인)
- **광**: `Start()` 후 `maxHP=60`(14 밸런스 수치 시트 반영) 확인, 쿨다운 0 도달 시 Busy+경고 인디케이터 생성, Windup→Active→Recovery→Chasing 전이 + 쿨다운 재설정(3초) 확인

`Destroy()`/경고 인디케이터 제거처럼 Unity의 지연 파괴(end-of-frame)에 의존하는 부분은 이 환경의 에디터 모드 리플렉션 테스트에서는 즉시 반영 안 됨(실제 프레임 틱이 없어서) — 기존에 이미 알려진 한계와 같은 종류라 별도 버그로 안 취급함, 실제 Play에선 정상 작동할 것으로 판단.
