# 먹괴음 5종 Unity Humanoid Avatar 설정·검증 완료

## 배경

원/흡/분/광 4종의 Blender 제작·머리 장식까지 끝난 뒤, 기본형 평에서만 되어 있던 Unity Humanoid Avatar 설정을 나머지 4종에도 적용하고 실제로 애니메이션 리타겟팅이 되는지 검증했다.

## 작업 내용

### Avatar 설정

4종 모두 평(Pyeong)과 동일한 17개 본 구조(Hip/Waist/Chest/Neck/Head, 팔다리 각 3본씩)를 공유하므로, 평에서 이미 검증된 매핑을 그대로 재사용:

| Humanoid 본 | 실제 본 이름 |
|---|---|
| Hips | Hip |
| Spine | Waist |
| Chest | Chest |
| Neck / Head | Neck / Head |
| Left/RightUpperLeg~Foot | Thigh_L/R → Calf_L/R → Foot_L/R |
| Left/RightUpperArm~Hand | UpperArm_L/R → Forearm_L/R → Hand_L/R |

Unity CLI `eval`로 각 FBX의 `ModelImporter.animationType = Human`, `avatarSetup = CreateFromThisModel`, `humanDescription.human[]`을 위 매핑으로 설정 후 `SaveAndReimport()`. 4종 모두 `Avatar.isValid = True`, `isHuman = True` 확인.

### 리타겟팅 실제 동작 검증

Avatar가 valid하다고 해서 실제로 메쉬가 뼈를 따라 움직인다는 보장은 없다는 게 이 세션 초반(평 제작 당시)에 이미 겪은 교훈이라, 이번에도 숫자로 재확인했다.

사용자가 보유한 에셋스토어 패키지(Kevin Iglesias)의 `HumanM@AttackPunch01_R.fbx` 펀치 클립을 각 캐릭터에 임시로 붙인 뒤 `AnimationMode.SampleAnimationClip()`으로 클립 40% 지점을 샘플링, 레스트 포즈와 비교:

| 캐릭터 | Hand_L 위치 이동량 | UpperArm_L 회전량 |
|---|---|---|
| 평 | 0.522m | 140.5° |
| 원 | 0.522m | 140.5° |
| 흡 | 0.615m | 121.4° |
| 분 | 0.522m | 140.5° |
| 광 | 0.522m | 140.5° |

5종 전부 손 위치가 0.5m 이상 이동하고 팔이 120도 이상 회전 — 레스트 포즈에서 벗어나 실제로 애니메이션을 따라 움직인다는 확실한 증거. (흡만 수치가 다른 건 손을 2.6배로 확대·재배치한 형태 차이 때문으로, 비정상이 아님)

추가로 원 캐릭터에 같은 포즈를 적용한 채 Scene View를 프레이밍해 스크린샷을 찍어 시각적으로도 확인 — 다리가 굽혀지고 대포팔이 휘둘러진 역동적인 포즈가 실제로 렌더링됨을 확인.

## 시행착오

- 검증용 임시 GameObject에 무조건 `AddComponent<Animator>()`를 호출했다가 `Object reference not set` 런타임 에러 발생 — FBX를 Humanoid로 설정하면 Model Prefab 루트에 Animator가 이미 자동으로 붙어있어서, 중복 추가 시도가 예외 없이 `null`을 반환하고 그 다음 줄에서 NullReferenceException이 난 것. `GetComponent<Animator>() ?? AddComponent<Animator>()` 패턴으로 수정
- `unity command eval`은 매 호출이 완전히 독립된 게 아니라 **같은 라이브 Editor 프로세스 상태를 그대로 이어받는다** — 이전 eval 호출에서 생성한 임시 GameObject가 다음 eval 호출에서도 `GameObject.Find()`로 그대로 조회됨. 여러 단계(포즈 적용 → 스크린샷 캡처 → 정리)를 별도 CLI 호출로 나눠서 처리할 때 유용하게 활용
