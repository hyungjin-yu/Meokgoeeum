# 큐브 워커 — 방향 전환 시 미끄러지는 느낌 제거 (가속/감속 + 빠른 회전)

## 배경

[[changelog/2026-09-16_큐브워커-마우스잔여입력곡선이동버그수정]]으로 곡선 이동 버그를 해결한 직후, 사용자가 새 리포트: "플레이어 캐릭터가 다른 방향으로 이동할 때 너무 심하게 조잡해보이는데.. 플레이에 방해되는 심각한 정도야." 확인 질문 결과 원하는 참고 기준은 **몬스터헌터 스타일의 캐릭터 움직임**.

## 원인

두 가지가 겹쳐서 "미끄러짐"으로 체감됨:

1. **이동 방향이 입력 즉시 순간 반전됨.** `moveDir`이 카메라 기준으로 매 프레임 바로 계산되고, 그걸 그대로 `moveSpeed`를 곱해 위치에 더했음 — A/D를 급하게 바꾸면 속도 벡터가 감속 없이 순간적으로 반대 방향으로 뒤집힘.
2. **몸 회전이 너무 느리게 따라옴.** `characterForward`(이동 방향)는 순간 스냅되는데, 실제 시각적 회전(`transform.rotation`)은 `Quaternion.Slerp(..., reorientSpeed * Time.deltaTime)`로 "남은 각도의 일정 비율만" 매 프레임 따라잡는 방식이었음 — 180도에 가까운 급반전은 다 도는 데 실측상 0.5~0.7초 걸림. 그동안 몸은 옛 방향을 본 채로 이미 새 방향으로 이동 중이라 미끄러지는 것처럼 보였음.

## 작업 범위 결정

전용 회전/피봇 애니메이션까지 있는 진짜 몬스터헌터급 손맛을 만들려면 방향 전환용 애니메이션이 따로 필요한데, 지금 테스트용 유니티짱 모델엔 그런 애니메이션이 없고(걷기/뛰기만 있음) 최종 플레이어 모델도 아직 안 정해짐. 사용자에게 범위를 확인: **"지금은 미끄러짐만 없애기(추천)"** 선택 — 애니메이션 추가 없이 코드만으로 미끄러짐을 우선 제거하고, 진짜 몬스터헌터급 전환 애니메이션은 최종 모델이 정해지면 나중에.

## 결과물

`CubeSurfaceWalker.cs`:
- `acceleration`(신규, 기본 30) — 목표 속도(`moveSpeed` 방향)로 즉시 점프하지 않고 `Vector3.MoveTowards`로 서서히 따라감. 방향을 급히 바꾸면 먼저 감속(6→0)했다가 새 방향으로 재가속(0→6)하는 자연스러운 궤적이 나옴.
- `characterForward`(실제로 바라보는 방향)의 기준을 입력 방향(`moveDir`, 순간 반전)에서 **실제 가속/감속을 거친 속도(`currentVelocity`)**로 변경 — 감속 중(속도 거의 0)엔 마지막 방향을 유지하다가, 새 방향으로 속도가 붙기 시작해야 비로소 돎.
- 몸 회전을 `Quaternion.Slerp`(비율 기반, 회전 각도가 클수록 오래 걸림)에서 `Quaternion.RotateTowards`(초당 각도 상한 기반, 각도 크기 무관하게 항상 일정 속도)로 교체, `reorientSpeed` 기본값을 4(옛 비율값)에서 720(초당 각도)으로 대폭 상향.
- 애니메이터 `Speed` 파라미터도 `moveInput.magnitude`(항상 0 또는 1, 즉시 스냅) 대신 `currentVelocity.magnitude / moveSpeed`(0~1 정규화, 가감속 램프가 그대로 반영)로 변경 — 걷기 애니메이션도 속도에 맞춰 자연스럽게 블렌드됨.

## 검증

리플렉션으로 직접 시뮬레이션(D 1초 유지 → A로 급반전, 4초간 60fps 기준 240프레임):
- 반전 시점(1.0초)부터 속도가 6→5.5→...→0.5→(반대 방향)2→4.5→6으로 감속 후 재가속하는 것 확인, 순간 반전 없음.
- 몸 회전은 반전 직후 잠깐(0.05~0.1초) 각도 차이가 벌어졌다가 약 0.25초 안에 완전히 0으로 수렴 — 이전엔 같은 시나리오에서 0.5~0.7초 동안 85~94도 차이가 거의 안 줄어들었음.

**⚠️ 씬에 저장된 `reorientSpeed` 값이 예전 기본값(4)으로 이미 직렬화돼 있어서, 코드의 기본값만 바꿔서는 반영이 안 됨을 발견** — 실측 시뮬레이션에서 각도가 전혀 안 줄어드는 걸로 처음 발견, `CubeWalker_Player`의 `CubeSurfaceWalker` 컴포넌트 `reorientSpeed`를 720으로 직접 갱신. **이 씬 변경은 `SC_CubePrototype.unity`가 계속 로컬 미커밋 상태(유니티짱 테스트 변경 누적)라 코드와 별도로 커밋 안 됨 — 다른 환경에서 씬을 새로 받으면 이 값을 720으로 다시 맞춰야 함.**

사용자가 실제 플레이로 확인: "그래 많이 나아졌네."

## 한계

- 진짜 몬스터헌터급 전환 애니메이션(피봇 턴 등)은 여전히 없음 — 최종 플레이어 모델이 정해지면 재검토.
- `SC_CubePrototype.unity`의 `reorientSpeed=720` 값이 코드 기본값과 별개로 씬에만 존재 — 씬을 새로 만들거나 리셋하면 이 값도 같이 720으로 맞춰야 함(위 경고 참고).
