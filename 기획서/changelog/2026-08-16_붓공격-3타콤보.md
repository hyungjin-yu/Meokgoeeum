# 2026-08-16 — 붓 기본 공격 3타 콤보 (v0.1 목표 ②)

## 배경

v0.1 목표 순서 중 ②. 사용자 요청으로 이번 작업부터 "알고리즘/최적화도 같이 고려"하는 원칙을 CLAUDE.md에 반영한 뒤 착수.

## 한 일

- **`IDamageable.cs` 신규** — 대미지 받는 대상이 구현할 인터페이스. `BrushWeapon`은 이것만 보고 판정하므로, ③ 먹괴음 구현 시 이 인터페이스만 붙이면 바로 맞을 수 있음
- **`BrushWeapon.cs` 신규** — 3타 콤보 상태머신 (Idle → Startup → Active → Recovery)
  - [[27 전투 프레임 데이터]]의 프레임 수치(60fps 기준)를 그대로 초 단위로 환산해 사용
  - [[14 밸런스 수치 시트]] "기본 콤보 대미지" 배율(1타×0.6/2타×0.7/3타×1.0) 그대로 적용
  - 캐릭터 모델/애니메이션이 아직 없어서(Player=캡슐) Animation Event 대신 타이머 기반 — 나중에 모델 생기면 타이머를 Animation Event로 교체 가능하도록 상태머신 구조로 분리해둠
  - 히트스탑(0.05초) 구현
- **`PlayerInputActions.inputactions`에 `Attack` 액션 추가** (마우스 좌클릭)

## 최적화 원칙 적용 (CLAUDE.md 신규 원칙 첫 적용 사례)

- Active 프레임 "진입 시점"에 딱 1번만 `OverlapSphere` 판정 (Active 구간 내내 매 프레임 판정하면 한 번 휘둘러서 여러 번 맞는 버그가 됨)
- 프레임 수치를 static readonly 배열로 미리 초 단위 환산해둬서 매 프레임 나눗셈 없음
- 히트스탑 코루틴은 "적중했을 때만" 실행 — 매 프레임 도는 게 아니라 드문 이벤트라 GC 부담 무시 가능 수준
- Update()에서 매 프레임 `new` / LINQ 없음 (배열 인덱싱과 단순 필드만 사용)

## 설계 결정: 콤보 입력 버퍼를 문서보다 관대하게 구현

27 문서는 "1타 Recovery 4~10f 사이 입력 시 콤보 연계"라고 엄격한 윈도우를 명시했지만, 실제 구현은 **Startup부터 Recovery 끝까지 언제 클릭해도 입력을 큐에 담아뒀다가 버퍼 구간(Recovery 마지막 6프레임)에서 확정**하는 방식으로 좀 더 관대하게 만들었음. 너무 엄격한 입력 윈도우는 "분명히 눌렀는데 안 나감" 프러스트레이션의 흔한 원인이라 판단. 플레이테스트 후 너무 쉽게 콤보가 이어진다는 피드백이 나오면 엄격한 윈도우로 되돌릴 것 — → [[30 플레이테스트 & 밸런싱 검증 계획]] 대상에 추가.

## 아직 안 된 것 / 다음 세션이 할 일

- **Unity에서 `BrushWeapon.cs`를 `Player`에 컴포넌트로 붙여야 함** — 새 스크립트라 `.meta`가 없어서 씬에 미리 못 심어둠
- 맞을 대상(먹괴음)이 아직 없어서 판정 자체는 미검증 상태 — **③ 먹괴음 구현이 끝나야 실제 테스트 가능**
- `slashEffect`(파티클), 애니메이션, 카메라 흔들림 연출은 전부 비어있음 — 지금은 로직만 있고 비주얼 피드백 없음. 다음에 VFX 붙일 때 참고
- 콤보 입력 버퍼가 문서보다 관대한 건 의도적 결정 — 다음 세션이 "왜 27 문서랑 다르지"라고 헷갈리지 않도록 여기 기록해둠
