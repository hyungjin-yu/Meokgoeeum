# 2026-08-25 — DamageZone/EnemyGwang 인디케이터/EnemyWon 투사체 씬 소속 정리

## 배경

[[changelog/2026-08-24_재방문-랜덤인카운터]]에서 발견한 "런타임 생성 오브젝트가 활성 씬이 아니라
영구 씬(`SC_Game`)에 쌓이는" 버그를, `Instantiate()` 호출부(`EncounterSpawner`, `EnemyBun`,
`RandomEncounterSpawner`)는 그때 바로 고쳤지만, `GameObject.CreatePrimitive()`로 만드는 나머지
3곳(`DamageZone`, `EnemyGwang` 경고 인디케이터, `EnemyWon`의 `InkProjectile`)은 "자체 타이머로
소멸돼서 심각하지 않음" 판단으로 낮은 우선순위 남겨뒀던 것을 마저 정리.

## 왜 `Instantiate(parent)`가 아니라 `SceneManager.MoveGameObjectToScene`인가

`CreatePrimitive()`는 `Instantiate()`와 달리 parent 인자를 받지 않아서, 만든 직후
`transform.SetParent()`로 부모를 붙이는 방식도 고려했지만 — 이 셋은 전부 **생성 주체가 이후에도
계속 움직이는 오브젝트**(장판 시전자=보스, 경고 인디케이터/투사체=적)라서, 만약 시전자의
transform을 부모로 붙이면 원래는 고정되어야 할 장판/투사체가 시전자를 따라 같이 움직이는
버그가 새로 생김(`EnemyBun.SplitOnDeath()`가 죽는 개체 자신이 아니라 `transform.parent`(스포너)를
부모로 쓴 것과 같은 이유). 그래서 부모-자식 관계는 만들지 않고, `SceneManager.MoveGameObjectToScene()`으로
씬 소속만 생성 주체(`gameObject.scene`) 기준으로 맞춰서 완전히 독립적인 최상위 오브젝트로 유지.

## 수정한 곳

- `DamageZone.Create()`: `Scene targetScene` 매개변수 추가, 호출부(`BossPo.CastZone()`)에서
  `gameObject.scene` 전달
- `EnemyGwang.SpawnWarningIndicator()`: 생성 직후 `SceneManager.MoveGameObjectToScene(warningIndicator, gameObject.scene)`
- `EnemyWon.ThrowInk()`: 생성 직후 `SceneManager.MoveGameObjectToScene(projectileObj, gameObject.scene)`

`ColorOrbPool`은 별도 오브젝트 풀 패턴(풀 관리자 아래 계속 보관/재사용)이라 이번 정리 대상이 아님 —
씬 소속 문제와는 다른 종류.

## 검증

**[2026-08-25]** Unity 컴파일 에러 없음 확인 완료. 런타임 검증(보스 장판/광 경고 인디케이터/원
투사체가 정확히 해당 면 씬에 소속되는지)은 아직 안 함 — 셋 다 자체 타이머로 금방 사라지는
오브젝트라 Hierarchy에서 눈으로 확인하기 까다로움. 필요하면 Play 중 Hierarchy에서 잠깐이라도
캡처해서 `SC_Face_X`/보스룸 씬 밑에 뜨는지 확인 (낮은 우선순위 — 이미 자체 타이머로 소멸돼서
씬을 나가도 안 남으므로, 안 고쳐도 게임플레이에 영향 없었던 버그).
