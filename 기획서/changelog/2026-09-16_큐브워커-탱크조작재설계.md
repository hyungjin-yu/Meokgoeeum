# 큐브 워커 — A/D를 탱크식 제자리 회전으로 재설계

## 배경

바로 전 changelog([[changelog/2026-09-16_큐브워커-이동방향자동회전]])에서 "이동하는 방향을 자동으로 바라보게" 재설계했는데, 사용자가 곧바로 리포트: "나는 좌/우 키를 누르면 제자리에서 회전하기를 원하는데, 이상하게 회전해." 원인은 A/D가 여전히 "카메라 기준 스트레이프"로 처리되고 있어서, 누르는 순간 그 스트레이프 방향으로 캐릭터가 스냅 회전하면서 **동시에 옆으로 미끄러지듯 이동**해 어색해 보였던 것 — 사용자가 원한 건 순수하게 제자리에서만 도는 고전적인 "탱크 조작" 방식.

## 결과물

- **A/D(`moveInput.x`)를 스트레이프에서 완전히 분리** — 이제 매 프레임 `characterForward`를 `turnSpeed`(신규 필드, 초당 각도, 기본 180도)만큼 표면 법선 축으로 직접 회전시키기만 함. 이동량은 전혀 없음.
- **W/S(`moveInput.y`)는 `characterForward` 기준 전진/후진만** — `moveDir = characterForward * moveInput.y`로 단순화(카메라 기준 계산 제거).
- **마우스(`cameraForward`)는 여전히 [[CubeSurfaceCamera]] 궤도 전용** — 이동/회전 입력 해석에는 이제 전혀 안 쓰임. 최종 조작감: **마우스=카메라만, A/D=캐릭터 제자리 회전, W/S=그 방향 전진/후진.**
- 걷기 애니메이션(`Speed` 파라미터)도 전진/후진 크기만 반영하도록 단순화 — A/D는 순수 회전이라 걷는 모션이 재생되지 않음(제자리 회전 전용 애니메이션은 아직 없어서 나중에 필요하면 추가).

## 검증

리플렉션으로 핵심 공식 두 가지 직접 검증:
1. D 입력만 있을 때: `characterForward`는 `turnSpeed`만큼 회전하지만 이동량은 정확히 (0,0,0).
2. W 입력만 있을 때: 이동 방향이 정확히 `characterForward`와 일치(회전 변화 없음).

실제 `Update()`를 통한 종단 검증은 이 자동화 환경이 `Keyboard.current`를 통해 매 프레임 진짜 키보드 상태로 `moveInput`을 덮어써서(주입한 값이 곧바로 되돌아감) 불가능 — `ReadKeyboardInput()` 자체는 이번에 안 건드린 기존 코드라 위험은 낮다고 판단.

## 한계

- 사용자가 실제 플레이로 "A/D = 제자리 회전, W/S = 전진/후진"이 의도대로 체감되는지 최종 확인 필요.
- 제자리 회전 중 재생할 전용 애니메이션은 없음(현재는 Idle 유지) — 필요하면 나중에 추가.
