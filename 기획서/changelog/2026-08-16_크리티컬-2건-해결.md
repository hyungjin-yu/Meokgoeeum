# 2026-08-16 — QA Critical 2건 해결 (LVL-1, SYS-1)

## 배경

[[32 QA 리뷰 - 기획자 3인]]에서 발견한 🔴 Critical 2건을 v0.1 코드 착수 전에 결정.

## LVL-1 — 12층 vs 6면 매핑 불일치 해결

**결정:** "층(Floor)"과 "면(Face)"을 서로 다른 개념으로 분리.

- **면(Face):** 물리적으로 고정된 3D 공간, 정확히 6개, 절대 변하지 않음
- **층(Floor):** 화면에 표시되는 진행 카운터, 회전할 때마다 +1, 특정 면과 고정 대응 안 됨
- 1~6층은 "미방문 면 우선 가중치" 회전 규칙으로 항상 신규 콘텐츠 보장
- 7층부터 완전 랜덤 전환 → 재방문 발생 가능 (몇 층에 정확히 어떤 면이 재등장할지는 매 플레이마다 다름 — 리플레이성 확보)
- 각 면은 `visitCount`(방문 횟수)를 가지며, 2회차=약한 데자뷰 내레이션, 3회차 이상=강한 확신 내레이션으로 트리거 (기존 "5층/8층" 하드코딩 텍스트를 "재방문 횟수" 기준 이벤트로 전환)
- 12층(큐브 노출)과 최종층(보스)은 6면 순환 밖의 특수 씬(`SC_CubeReveal`, `SC_Boss`)

**수정한 문서:** [[05 맵 시스템 - 큐브 구조]] (핵심 결정 위치), [[12 큐브 좌표계 설계]] (C# 구현: `SelectWeightedAxis()`, `UpdateVisitCount()`, `visitCount` 필드), [[10 씬 구조 & 기술 스펙]] (씬 목록에 `SC_CubeReveal` 추가), [[19 층별 상세 설계]] (표 전체를 "대표 예시"로 재정의하는 안내문 추가 — 개별 층 서술은 그대로 두되 의미를 재해석)

**다음 세션이 알아야 할 것:** [[19 층별 상세 설계]]의 "8층 = 1층과 동일" 같은 개별 서술은 더 이상 "정확히 그 층 번호"를 의미하지 않는다. 실제 콘텐츠 제작(간판 디자인, 오브젝트 배치)은 층 번호가 아니라 "면 + 방문 횟수" 조합 기준으로 만들어야 한다.

## SYS-1 — 구슬 "획득" vs "보유" 정의 모순 해결

**결정:** 완전히 분리된 두 값 도입.

| | 보유 구슬 | 누적 색 기록 |
|---|---|---|
| 상한 | 5개 (합산) | 없음 (색상별) |
| 스킬 사용 시 | 감소 | 불변 |
| 용도 | 전투 자원 | 보스 등장 조건, 도감 |

**수정한 문서:** [[04 색 구슬 시스템]] (핵심 결정 위치, "두 개의 다른 숫자" 절), [[06 보스 설계]] (등장 조건이 누적 기록 기준임을 명시), [[18 세이브 & 로드 기획]] (`SaveData`에 `orbLifetimeCollected[6]` 필드 추가)

**다음 세션이 알아야 할 것:** 앞으로 "구슬을 몇 개 가지고 있다"는 표현이 나오면 반드시 어느 카운터를 말하는지 문맥으로 확인할 것. 헷갈리면 [[04 색 구슬 시스템]] 표를 기준으로 판단.
