# 실제 BrushWeapon에 큐브 면 검사 반영

## 배경

큐브 면 몹 5종 검증이 끝나서, 이제 실제 게임의 [[BrushWeapon]](좌클릭 3콤보)도 큐브 면 프로토타입에서 "같은 면인지" 검사가 통하게 만들 차례. 지금까지는 [[CubeFaceAttackTester]](F키, 단순 거리+면 체크)로만 검증해왔음.

## 결과물

- `Assets/Scripts/Player/CubeFaceLockedMob.cs`/`CubeEnemyBase.cs`에 `IDamageable` 인터페이스 추가 — 둘 다 이미 `public void TakeDamage(float amount)`를 갖고 있어서(시그니처 완전 일치) 인터페이스 선언 한 줄만 추가하면 됨. `BrushWeapon`의 `Physics.OverlapSphere` → `GetComponent<IDamageable>()` 판정 경로에 큐브 몹들이 이제 정상적으로 걸림(전엔 `ICubeFaceMob`만 구현해서 `BrushWeapon` 기준으론 아예 안 보였음).
- `BrushWeapon.cs`:
  - `[RequireComponent(typeof(PlayerController))]` 제거 — 큐브 프로토타입 플레이어([[CubeSurfaceWalker]]만 있고 `PlayerController`는 없음)에도 붙일 수 있게 함.
  - `Start()`에서 `PlayerController`가 있으면 기존처럼 그 `InputActions`를 공유하고, 없으면 자체 `PlayerInputActions`를 새로 만들어 씀(`OnDestroy()`에서 정리).
  - `PerformHit()`에 같은 면 검사 추가 — `cubeWalker`(자기 `CubeSurfaceWalker`)가 있을 때만, 맞은 대상이 `ICubeFaceMob`이면 `IsSameFaceAs()`로 같은 면인지 확인 후 다르면 무시. 평지 던전(`cubeWalker == null`)에서는 이 블록 자체가 안 돌아서 기존 동작에 전혀 영향 없음.
- `Assets/Scripts/Editor/CubeBrushWeaponSetup.cs` 신규 — `SC_CubePrototype.unity`의 `CubeFaceAttackTester`를 떼고 실제 `BrushWeapon`을 부착(좌클릭 3콤보로 전환).

## 검증

리플렉션으로 `PerformHit()`을 직접 호출해서 확인 — 처음엔 "같은 면인데도 안 맞는" 것처럼 보여서 당황했는데, 원인은 실제 버그가 아니라 **테스트 세팅 실수**였음: 이전 사망 처리 검증에서 이 Pyeong 인스턴스의 `isDead` 플래그가 이미 `true`로 남아있었는데(에디터 모드라 `Destroy()`가 실제로 반영 안 됨), `currentHP`만 리셋하고 `isDead`는 안 건드려서 `TakeDamage()`가 매번 조용히 무시되고 있었음. `isDead`까지 리셋한 뒤 재검증:

- 다른 면 → HP 100 → 100 (무시됨) ✅
- 같은 면 → HP 100 → 94 (콤보 1타 데미지 6 정상 적용, `attackPower(10) × DamageMultiplier[0](0.6)`) ✅

## 한계

- 평지 던전(`SC_Face_0` 등)에서 기존 동작이 안 깨졌는지는 코드 리뷰로만 확인(`cubeWalker == null`이면 검사 블록 자체가 스킵되는 구조라 논리적으로 안전) — 실제로 그 씬을 열어 재검증은 안 함, 필요하면 별도로 확인.
