# 큐브 워커 — 벽/문 막음이 애초에 아무것도 안 막던 버그

## 배경

사용자 리포트: "방A부터 몹을 잡지 않고 게이트를 뚫고 D까지 갈 수 있어." — 오늘 지은 방A~D의 벽/문 막음 큐브가 전부 눈속임이었고, 실제로는 아무 저항 없이 그냥 통과되고 있었음.

## 원인

[[CubeSurfaceWalker]]는 애초에 **콜라이더 충돌 검사를 전혀 안 하는 구조**였음(코드 자체 주석에 이미 명시돼 있었음: "콜라이더 충돌 없이(이 프로토타입은 CharacterController를 안 씀)"). `CharacterController`를 버리고 `transform.position`을 직접 옮기는 방식으로 짠 이유는 면을 넘어갈 때 임의 축으로 재정렬하는 걸 `CharacterController`가 못 버텨서였는데([[changelog/2026-09-12]] 계열 기록), 그 대가로 "표면 접지"와 "면 경계 클램프"만 좌표 계산으로 흉내내고 **벽에 부딪히는 것 자체는 아예 구현이 없었음**. 오늘 지은 `CubeFaceRoomBuilder`/`CubeDungeonRoomKit`의 벽·문 막음 큐브들은 전부 시각적으로만 존재했고, 플레이어는 그 사이를 그냥 뚫고 지나갈 수 있었던 것.

## 수정

`CubeSurfaceWalker.Update()`에서 이번 프레임 접선 이동(WASD 입력 방향, `moveDir`)의 목적지가 막혀있으면 그 성분만 취소하는 단순한 차단을 추가:

```csharp
Vector3 tangentialMotion = moveDir * moveSpeed * Time.deltaTime;
Vector3 verticalMotion = normal * verticalSpeed * Time.deltaTime;

if (tangentialMotion.sqrMagnitude > 0.0001f && WouldCollide(transform.position + tangentialMotion))
    tangentialMotion = Vector3.zero;

transform.position += tangentialMotion + verticalMotion;
```

`WouldCollide()`는 `Physics.OverlapSphere`로 자기 자신과 트리거(`CubeFaceZone` 등 면 전환 트리거)는 건너뛰고, 단단한(non-trigger) 콜라이더만 있으면 막힌 것으로 판정. 완전한 collide-and-slide는 아니고 "막히면 그냥 그 자리에 멈춤" 수준의 단순한 차단 — 벽을 따라 미끄러지진 않지만, 뚫고 지나가는 것 자체는 확실히 막힘.

**부수 효과**: 벽/문 막음 큐브 외에 [[MovingObstacle]](왕복 장애물, 원래도 물리적으로 막게 설계된 것)과 실제 몹(`CubeEnemyPyeong` 등, 전투 판정에 필요한 콜라이더가 이미 있음)도 이제 플레이어를 물리적으로 막음 — 둘 다 의도와 부합하는 자연스러운 부수 효과로 판단, 별도 처리 안 함.

**놓칠 뻔한 부작용**: [[PaintableObject]] 벽화(`CubeDungeonRoomKit.BuildMural()`)도 `CreatePrimitive(Cube)`라 기본 콜라이더가 있어서, 이 수정만 하면 바닥 장식일 뿐인 벽화까지 덩달아 막혀버림. `Collider.isTrigger = true`로 바꿔서 플레이어는 그냥 통과하되, [[ColorWaveEffect]]의 `Physics.OverlapSphere` 색칠 판정(트리거도 잡음)은 그대로 유지되게 함.

## 검증

- 재컴파일 에러 없음, 씬 재빌드 성공.
- Play 모드에서 `WouldCollide()`를 리플렉션으로 직접 호출해 3가지 경우 확인:
  - 문 막음 큐브 위치 → `True`(막힘) ✅
  - 벽화 위치(플레이어 실제 보행 높이 기준) → `False`(안 막힘) ✅ — 벽화 자체 높이(표면에서 0.1)로 잘못 검사했을 땐 큐브 자체(CubePlanet) 콜라이더에 걸려 `True`가 나와서 처음엔 당황했는데, 플레이어의 실제 보행 높이(표면에서 1.0)로 다시 검사하니 정상적으로 `False` — 검사 위치를 잘못 잡은 테스트 실수였고 실제 게임플레이 경로(접선 이동만 검사, 높이 불변)에선 문제 없음.
  - 문 막음 큐브를 `SetActive(false)`로 비활성화(게이트가 클리어 시 하는 일과 동일) 후 재검사 → `False`(안 막힘, 문이 정상적으로 열림) ✅

## 한계

- 완전한 "벽 따라 미끄러지기"가 아니라 "막히면 정지"라서, 벽에 대각선으로 다가가면 살짝 뻑뻑하게 느껴질 수 있음 — 체감이 나쁘면 나중에 슬라이드 로직으로 보강할 것.
- 실제 사용자 플레이로 "이제 진짜 못 뚫고 지나가는지"는 아직 확인 안 됨 — 리플렉션으로 각 조건만 개별 검증했음.
