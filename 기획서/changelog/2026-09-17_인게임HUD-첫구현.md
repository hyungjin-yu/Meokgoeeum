# 인게임 HUD 첫 구현 — 캐릭터 부위 피격 표시 + 스킬 구슬 슬롯

## 배경

"이제 슬슬 UI를 해도 될거 같은데"로 시작해서, 바로 코드로 만들기 전에 사용자가 "어떤 느낌으로 나올지 보고 싶은데"라고 요청해서 Artifact로 HTML/CSS 목업을 5차례 다듬은 뒤 "이제 이대로 유니티에 실제로 만들어줘"로 확정. 목업 단계에서 사용자가 직접 낸 피드백들이 그대로 최종 스펙이 됨:

- 캐릭터 아이콘 없애고, 숫자 HP바 대신 캐릭터 전신이 부위별로 검게 물드는 방식으로.
- 캐릭터는 기본 풀컬러, 대기 자세, 고퀄(최종 캐릭터 모델링 나오면 그걸로 교체할 placeholder라고 명시).
- 스킬 슬롯은 구슬처럼 구 형태, 쿨타임은 숫자 표기 금지.
- 보유 구슬 인벤토리 줄은 따로 안 둠 — "구슬이 없으면 스킬 자체를 비활성화하면 되니까" 라는 이유로 중복 제거.
- 우측 상단 층 수, 캐릭터 옆 "부위 피격 X/7" 텍스트 라벨 모두 삭제.

## 구현

`Assets/Scripts/UI/PlayerHUD.cs` 신설. [[HintPopupManager]]가 세워둔 컨벤션 그대로 — 아직 UI 아트 에셋이 없어서 `Awake()`에서 코드로 `Canvas`/`Image`/`Text`를 직접 만듦(TextMeshPro 아님, `UnityEngine.UI` legacy).

- 좌상단 바디 HUD: [[PlayerPaintParts]]의 7부위(Head/Chest/Waist/LeftArm/RightArm/LeftLeg/RightLeg)를 도형 조합으로 대략적인 사람 실루엣 배치. 새로 추가한 `PlayerPaintParts.IsRegionDrained(region)`을 매 프레임 읽어서, 맞은 부위만 검은색(#141414류)으로, 나머지는 기본색(피부/파랑 상의/짙은 하의) 유지.
- 하단 중앙 스킬 6슬롯: `ColorSkillController`의 `GetCooldownTimer`/`GetCooldownDuration`(이번에 private → public으로 공개)과 `ColorSystemManager.GetHeld()`를 읽어서 상태 3가지로 렌더 — 준비완료(펄스 글로우), 쿨타임 중(숫자 없이 원형 쐐기가 어둡게 걷힘), 구슬 없음/미구현(회색 잠금). 초록/보라/검정 3색은 아직 스킬 자체가 미구현이라 항상 잠금으로 고정.
- 원형/둥근 사각형 스프라이트: 처음엔 에디터 내장 리소스(`Resources.GetBuiltinResource<Sprite>("UISprite.psd")` 등)를 재사용하려 했는데, 이 유니티 버전 런타임에서는 로드가 안 됨(콘솔에 "Failed to find UISprite.psd" 에러) — 에디터 전용 리소스라 런타임 경로로는 못 불러오는 것으로 확인. 대신 `Texture2D`를 코드로 직접 구워서 `Sprite.Create()`로 만드는 방식으로 교체(원/둥근사각형 둘 다).

## 검증

- 컴파일 클린, Play 진입 후 콘솔 에러 없음(에디터 내장 스프라이트 에러는 수정 전 시도였고, 수정 후 재확인 시 새 에러 없음).
- `capture_game_view`(source=screen)로 게임 뷰 실제 스크린샷 촬영 — 바디 HUD 7부위가 사람 형태로 잘 배치되고(팔/머리는 피부색, 상의는 파랑, 하의는 짙은색으로 구분), 스킬 6슬롯이 전부 회색 잠금(구슬 하나도 없는 기본 상태이므로 정상)으로 보임을 육안 확인.
- `PlayerPaintParts.DrainRandomPart()`를 리플렉션으로 직접 호출해서 `IsRegionDrained()`가 해당 부위에 대해 정확히 `true`로 바뀌는 것 확인 — 로직 자체는 검증됨.

## 한계

- **부위 피격 시 실제로 검게 변하는 모습은 스크린샷으로 눈으로 확인 못함** — 이 자동화 환경 특유의 "실사용자 입력 없이는 `Time.frameCount`/렌더 루프가 멈춰있는" 문제([[changelog/2026-09-17_큐브몹-이동오버슈트버그]]에서도 겪은 것과 같은 제약) 때문에, `IsRegionDrained()` 값을 바꾼 뒤 `capture_game_view`로 다시 찍어도 화면이 갱신 안 됨(합성 백버퍼 자체가 안 새로 그려짐). 코드 로직(`색상 = 맞았으면 검정 : 기본색` 한 줄짜리 삼항식)이 단순해서 크게 걱정할 부분은 아니지만, 실제 플레이로 몹에게 맞았을 때 부위가 진짜 검게 변하는지는 사용자의 직접 플레이 확인이 필요함.
- 바디 실루엣은 도형 조합 placeholder — 사용자가 이미 "나중에 최종 캐릭터 모델링 넣으면 그거 연동해서 넣으면 될 듯"이라고 확인함.

## 추가 — 미구현 스킬 물음표 아이콘 (같은 날)

사용자가 검정 구슬을 실제로 먹었는데 스킬 슬롯이 안 켜지는 걸 보고 "스킬이 없어서지?"로 원인을 정확히 짚음 — 맞음(`ColorSkillController.TryCast()`에 Red/Blue/Yellow 3개 케이스만 있고 Green/Purple/Black은 아예 없음, 의도된 동작). 다만 "구슬 없음"과 "스킬 자체가 없음"이 똑같이 회색이라 구분이 안 된다는 지적 → `AskUserQuestion`으로 표시 방식 확인(물음표 아이콘 선택). 각 스킬 슬롯에 `UnimplementedMark`(물음표 `Text`) 자식을 추가해서 `!implemented`일 때만 보이게 처리(구슬만 없어서 잠긴 경우엔 아이콘 없이 그냥 회색). `capture_game_view`로 스크린샷 확인 — 4~6번 슬롯(초록/보라/검정)에만 물음표가 뜨고 1~3번(구슬 없는 빨강/파랑/노랑)은 아이콘 없이 회색인 것 확인. 커밋 `25d2924`.

## 추가 — 디버그 이동 거리 HUD 기본 숨김 (같은 날)

사용자가 Play 눌렀을 때 우측 상단에 뜨는 디버그용 이동 거리 표시([[changelog/2026-09-17_큐브몹-이동오버슈트버그]] 조사용으로 만든 [[DebugMovementHUD]])를 없애달라고 요청. 그 버그는 이미 고쳐졌고 이제 실제 게임 HUD가 그 자리를 쓰므로, 상시 표시를 끄고 `DebugSpawnPanel`(F5)과 동일한 패턴으로 토글 키(F6)를 추가 — 기본은 숨김, 필요할 때만 켬. `capture_game_view`로 스크린샷 확인 — 우측 상단 표시 사라지고 좌상단 캐릭터 HUD/하단 스킬 슬롯만 남는 것 확인. 커밋 `02899b6`.
