# 2026-08-20 — 4층 콘텐츠 준비 (흐린 상점가) + 게임 오버 최소 버전

## 배경

3층 검증 완료 후 4층으로 이어감. 4층은 [[EnemyHeup]](흡수형)이 처음 등장하고, 계단 조건이 "흡이 색 복원 구역에 접근하기 전에 처치"라는 특수 문구라 미리 검토가 필요했습니다.

## 1차 판단 → 사용자 요청으로 변경

처음엔 "흡이 접근하면 그냥 전투가 길어지는 정도"로 소프트하게 해석하려 했으나(소프트락 방지 목적), 사용자가 **"놓치면 벽이 터져서 플레이어 사망으로 하면 안돼?"**라고 요청. 확인해보니 **"플레이어 사망" 자체가 그동안 구현이 안 되어 있었음**(`PlayerHealth`는 HP가 0에서 멈추기만 하고 아무 일도 안 일어남 — `TODO(17 게임오버 & 리트라이)`로 남아있던 부분). 그래서 이번에 **[[GameOverManager]] 최소 버전을 같이 구현**하기로 함.

## 한 일

- **`PlayerHealth.cs`** — HP 0 도달 시 `OnDeath` 이벤트 발동 + `isDead` 가드(중복 발동 방지) 추가, 리스폰용 `ResetHealth()` 메서드 추가
- **`CubeMapManager.cs`에 `ReloadCurrentFace()` 신규** — 회전 없이 지금 있는 면을 그대로 다시 로드(페이드/언로드/로드/텔레포트는 기존 회전 코드 재사용, `MarkVisited`/`floorNumber` 증가는 안 함 — 새 방문이 아니라 재시작이므로)
- **`GameOverManager.cs` 신규** — `PlayerHealth.OnDeath` 구독 → "게임 오버" 문구(`NarrationManager` 재사용) → `ReloadCurrentFace()` → 체력 회복. **[[17 게임오버 & 리트라이]] 원 기획("처음부터 재시작")과 다르게, 사용자 요청으로 "죽은 층에서 다시 시작"으로 구현** — 레벨 콘텐츠를 층마다 만들어가는 지금 단계에서 매번 1층부터 다시 하면 테스트 흐름이 심하게 끊기기 때문. 나중에 "처음부터"로 바꾸려면 이 매니저의 재시작 호출부만 바꾸면 됨
- **`EnemyHeup.cs`에 `OnAbsorbStart` 이벤트 추가** — 회복 구역에 도달해서 흡수를 시작하는 순간 1회 발동 (상태 전이 시점에만, 매 퍼셉션 틱마다 X)
- **`WallExplosionHazard.cs` 신규 (4층 전용)** — `EnemyHeup.OnAbsorbStart`를 구독해서, 짧은 경고 유예 시간(기본 1.5초, 기획서에 없는 추가 설계 — [[27 전투 프레임 데이터]] 텔레그래프 원칙에 맞춘 공정성 보강) 뒤에도 흡이 살아있으면 벽 오브젝트 파괴 연출 + 플레이어 즉사(`TakeDamage(maxHP)`). 유예 시간 안에 흡을 처치하면 취소됨(Unity의 파괴된 오브젝트 참조가 자동으로 null 처리되는 걸 이용)
- **[[logic/4층 콘텐츠 - 흐린 상점가 씬 설정]] 갱신** — `GameOverManager` 최초 부착(게임 전체 공용, 4층 전용 아님) + `WallExplosionHazard` 씬 설정 단계 추가

## 2026-08-21 추가 — Wall과 ShopSign 통합

Unity 설정 중 사용자가 "ShopSign이랑 Wall이랑 하나로 합치면 안 돼?"라고 질문. `WallExplosionHazard`는 `Wall Visual`에 연결된 오브젝트의 위치를 코드상 전혀 참조하지 않고 "폭발 시 파괴"만 하기 때문에, `ShopSign`을 그대로 `Wall Visual`에 넣어도 문제없음을 확인 → **별도 `Wall` 오브젝트를 안 만들고 `ShopSign` 하나가 회복 구역+폭발 벽을 겸하도록 단순화**. [[logic/4층 콘텐츠 - 흐린 상점가 씬 설정]] 5단계 갱신.

## 2026-08-21 추가 — 세이브된 HP 0 버그 발견·수정 + 최종 검증 완료

Unity 테스트 중 벽 폭발이 플레이어를 죽이지 않는 증상 발견 → 진단 로그로 원인 확정: **세이브 파일에 `playerHP: 0`이 저장돼 있었음**(추정: `GameOverManager`를 붙이기 전에 한 번 죽어서 `OnDeath`가 허공에 발동됐고, 그 뒤로도 계속 플레이하면서 HP=0 상태가 층 입장 자동 저장에 계속 찍혀온 것 — 세이브가 41층까지 쌓여있었음). `PlayerHealth.SetHP()`가 HP<=0을 그대로 받으면 `isDead=true`로 로드되고, 그 뒤로 `TakeDamage()`가 영구히 무시되는 상태가 되는 게 근본 원인.

**수정**: `CubeMapManager.ApplySavedPlayerHP()`에서 로드된 HP가 0 이하면 `ResetHealth()`(최대 체력)로 대신 시작하도록 방어 코드 추가 — 기존 세이브 파일도 따로 안 지워도 다음 로드부터 자동 복구됨.

**최종 검증**: 흡을 늦게 처치 → `벽 폭발!` → `진단: CurrentHP=24/100`(정상 값) → `플레이어 사망!` → `게임 오버! 리트라이 시작.` → 화면에 "게임 오버... 다시 도전!" 문구 → 현재 면 재시작 → 스폰 위치 복귀까지 전체 흐름 정상 확인. **4층 벽 폭발 페널티 + 게임 오버 시스템 완전히 끝남.**

## 2026-08-21 추가 — "정상 클리어" 시나리오 최종 검증 완료

`BrushWeapon` 자해 버그([[changelog/2026-08-21_붓공격-자해버그]]) 수정 후 재테스트 — 평×2+흡×1 전부 처치 → `RoomClearGate` 클리어! 계단 활성화 → 계단 사용 → 5면→0면 정상 회전까지 자해 데미지 없이 안정적으로 진행됨. **4층 완전히 끝남 (벽 폭발 페널티 + 정상 클리어 두 시나리오 다 검증 완료).**
