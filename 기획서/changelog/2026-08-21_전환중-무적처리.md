# 2026-08-21 — 화면 전환/컷씬 중 플레이어 무적 처리

## 배경

4층 정상 클리어 테스트 전, 사용자가 "면 이동하거나 재시작을 하면 검은 화면이 3초 정도 지속되는데, 적들은 공격을 하고 있어"라고 리포트. 확인해보니 페이드는 화면 위에 검은 이미지를 덮는 연출일 뿐 `Time`이나 적 AI/공격 판정을 멈추지 않아서, 안 보이는 채로 맞을 수 있는 불공평한 상황이었음.

## 한 일

- **`CubeMapManager.cs`** — `SetPlayerInvulnerable()` 헬퍼 추가, `RotateRoutine()`(면 회전)과 `ReloadCurrentFaceRoutine()`(게임 오버 리트라이) 양쪽 다 FadeOut 시작 직전 무적 ON, FadeIn 완료 직후 OFF
- **`CubeRevealSequence.cs`** — 12층+ "큐브 구조 노출" 컷씬도 같은 이유로 무적 처리 추가 (같은 헬퍼 패턴 자체 구현)
- **`BossPo.cs`** — `CastDisplace()`(2페이즈 위치 교란)도 같은 이유로 무적 처리 추가
- 셋 다 `Time.timeScale`을 멈추는 대신 **`PlayerHealth`의 기존 `isInvulnerable` 플래그를 재사용** — `PlayerDodge` 구르기 i-frame과 같은 스위치. `timeScale`을 멈추면 페이드 애니메이션 자체도 같이 멈춰버려서 이 방식을 택함

## 부수 발견 — 세이브된 HP 0 버그

테스트 도중 벽 폭발 페널티가 플레이어를 안 죽이는 증상을 발견 → 진단 로그로 **세이브 파일에 `playerHP: 0`이 저장돼 있었다는 걸 확인**(`GameOverManager`를 붙이기 전에 죽은 적이 있어서, 그 뒤로 HP 0 상태가 계속 저장돼온 것으로 추정). `PlayerHealth.SetHP()`가 HP<=0을 그대로 받으면 `isDead=true`로 로드되어 그 뒤 `TakeDamage()`가 영구히 무시되는 상태가 됨 — `CubeMapManager.ApplySavedPlayerHP()`에 방어 코드 추가(로드 HP<=0이면 최대 체력으로 대신 시작)로 해결. 기존 세이브 파일도 따로 안 지워도 다음 로드부터 자동 복구됨.

## 알려진 한계 (수용)

면 회전이 끝나는 시점과 "첫 12층 도달" 연출이 우연히 겹치면, 두 개의 독립적인 페이드/무적 시퀀스가 동시에 돌면서 아주 짧은 무보호 창이 생길 수 있음. 실전 테스트로 실제로 재현됐지만(이전 changelog 참고), 한 판에 딱 한 번(첫 12층 도달 시점)만 발생 가능한 드문 케이스라 지금은 완전히 막지 않기로 함. 완전히 막으려면 "지금 어떤 연출이든 하나만 실행되게" 하는 전역 트랜지션 락이 필요한데 지금 단계에서는 과한 리팩터링.

## Unity 검증 완료 (2026-08-21)

12층 노출 컷씬 4초 동안 적 공격 6회가 전부 `무적 중이라 피격 무시됨!`으로 막히는 것 확인. 컷씬 종료 직후(무적 해제 시점)에 정당하게 피격사 — 이건 불공평한 게 아니라 정상 전투 결과. 리포트했던 "안 보이는 채로 맞는" 문제 해결 확인.

## 다음 세션이 알아야 할 것

- `PlayerHealth.SetInvulnerable()`의 로그 문구가 항상 "(구르기 i-frame)"으로 찍힘 — 실제로는 면 전환/컷씬 때문에 켜진 것도 이 문구로 뜸. 기능엔 문제없고, 사용자가 "그냥 둬도 된다"고 확인함 — 나중에 헷갈리면 문구만 일반화하면 됨
- 4층 "정상 클리어"(평×2+흡×1 전멸 → 계단 → 5층) 시나리오는 아직 확인 안 함 — 다음에 이어서 테스트
