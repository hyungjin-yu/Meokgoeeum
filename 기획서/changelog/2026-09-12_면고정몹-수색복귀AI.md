# 면 고정 몹 — 수색/복귀 AI 상태 머신

## 배경

사용자 요청: "몹도 갑자기 시야에서 플레이어가 사라지면 당황하다가, 다시 플레이어가 보이면 쫓아가는 느낌으로 가면 좋을 것 같아. 플레이어가 다른 면으로 가면 몹은 주변을 둘러보면서 플레이어를 찾고, 5초 이상 안 보이면 원래 자리로 되돌아가면서 HP 회복, 5초 안에 플레이어가 보이면 다시 추적." [[changelog/2026-09-12_큐브면고정몹-공격판정검증]]에서 만든 단순 접근 AI를 4단계 상태 머신으로 확장.

## 결과물

`Assets/Scripts/Player/CubeFaceLockedMob.cs`에 상태 머신 추가:

- **Idle** — 대기, 계속 HP 회복. 플레이어가 자기 면에 나타나면 즉시 Chasing.
- **Chasing** — 플레이어 추적(기존 로직). 플레이어가 면을 떠나면 Searching으로 전환.
- **Searching** — `searchDuration`(기본 5초) 동안 제자리에서 `faceNormal` 축 기준 좌우로 두리번거림(`Quaternion.AngleAxis` + 사인파, 시각적으로 "당황한" 느낌). 그 안에 플레이어가 같은 면에 다시 나타나면 즉시 Chasing, 시간이 다 되면 Returning.
- **Returning** — 스폰 지점(`spawnPosition`, `Start()`에서 1회 기록)으로 복귀하며 `returnRegenPerSecond`(기본 25/초)로 HP 회복. 복귀 도중에도 플레이어가 다시 나타나면 즉시 Chasing(복귀 포기). 도착하면 Idle.

`CubeFaceAttackTester.cs`도 같이 확장 — 공격 명중 시 `mob.TakeDamage()` 호출, 로그에 남은 HP 표시. `CubeFaceLockedMob`에 `maxHP`/`currentHP`/`TakeDamage()` 신규 추가(이전엔 체력 개념 자체가 없었음).

## 검증 방법 — 리플렉션 스텝 + 필드 직접 조작

에디터 모드에서 `Time.deltaTime`이 호출마다 극히 작고 불안정해서(실측: 5회 호출에 이동량 0.09 — 프레임당 dt가 예상보다 훨씬 작음), "400프레임 방치"처럼 실제 프레임 수로 5초를 채우려는 시도는 신뢰할 수 없었음(400프레임을 넣어도 Searching 상태를 못 벗어남). **타이머/상태 필드를 리플렉션으로 직접 세팅**한 뒤 `Update()`를 한 번씩 호출해서 전이 조건 자체를 검증하는 방식으로 전환:

- Idle → Chasing (같은 면 등장) ✅
- Chasing → Searching (면 이탈) ✅
- Searching → Chasing (5초 전 재등장) ✅
- Searching(timer=5.1) → Returning (시간 초과) ✅
- Returning → 이동하며 HP 회복(50프레임에 40→49.34) ✅
- Returning(스폰에서 6m 거리) → 재등장 시 Chasing으로 즉시 전환(복귀 포기) ✅
- Returning → Idle (스폰 지점 도착) ✅
