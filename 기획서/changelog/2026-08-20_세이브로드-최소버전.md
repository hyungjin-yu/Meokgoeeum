# 2026-08-20 — 세이브 & 로드 최소 버전

## 배경

사용자가 "세이브 포인트는 없는 것 같은데 만들어줘"라고 요청. [[18 세이브 & 로드 기획]]을 확인해보니 원래 설계 자체가 "수동 세이브 포인트"가 아니라 **자동 저장(층 입장 시 / 보스 처치 후)**이라, 그 스펙 그대로 최소 버전을 구현했습니다.

## 한 일

- **`SaveData.cs` 신규** — 문서의 저장 항목 표를 그대로 따르는 직렬화 가능 클래스. `faceColorRestored`(면 전체 색 복원 여부)만 뺐음 — 개별 `PaintableObject` 칠해짐 상태가 중앙에서 추적되지 않고 있어서 지금 범위에선 만들 수 없음(대신 "면 방문 여부"만 저장)
- **`SaveManager.cs` 신규** — `JsonUtility` + `Application.persistentDataPath`로 저장/로드 (문서의 Unity 구현 방식 그대로). `Save()`/`Load()`/`HasSaveFile()`/`DeleteSave()`
- **`ColorSystemManager.RestoreState()` 추가** — 보유/누적 구슬 배열을 세이브에서 복원. FIFO 소모 순서(`acquisitionOrder`)는 세이브에 없어서 색 인덱스 순으로 근사 재구성(보유 상한 5개라 체감상 무시할 수준)
- **`PlayerHealth.SetHP()` 추가** — 임의 값으로 체력 복원(기존 `ResetHealth()`는 항상 최대치라 로드 복원엔 안 맞음)
- **`GameState.totalKills` 필드 추가**, **`EnemyHealth.Die()`에서 증가** — 지금까지 처치 수를 아무도 안 세고 있었어서 새로 추가
- **`CubeMapManager`**:
  - `CurrentFaceIndex` public getter 추가
  - `LoadInitialFace()`가 시작할 때 세이브 파일이 있으면 그 지점(층/면/구슬/방문기록)을 복원하고 이어서 시작 — 이때는 "새 방문"이 아니므로 `MarkVisited()`(재방문 나레이션 트리거)를 건너뜀
  - 면 진입(최초 시작 + 회전 도착) 시마다 `SaveManager.Instance?.Save()` 호출 — "층 입장 시 자동 저장"
- **`BossHealth.Die()`에서 `SaveManager.Instance?.Save()` 호출** — "보스 처치 후 자동 저장"
- **[[logic/세이브 로드 설정]] 신규** — `GameSystems`에 `SaveManager` 부착 1단계짜리 절차 + 테스트 방법 + 세이브 파일 위치/삭제 방법

## 스코프 컷 (문서 대비 뺀 것 — 이유는 SaveManager.cs 주석에도 기록)

- **슬롯 3개 → 1개만.** 슬롯을 고르는 타이틀/메뉴 화면 자체가 없어서 여러 슬롯을 만들 이유가 아직 없음
- **Steam Cloud 연동** — 문서 자체도 "도입 예정"으로 미확정
- **뉴게임+/도감 회차 유지 로직** — `SaveData`에 필드(`newGamePlusCount`, `orbCollected`)는 만들어뒀지만 그 시스템 자체가 없어서 지금은 저장/로드만 되고 게임플레이에 영향 없음

## 다음 세션이 알아야 할 것

- Unity 작업 아직 안 함 — `GameSystems`에 `Save Manager` 부착만 하면 끝 ([[logic/세이브 로드 설정]] 참고)
- [[GameOverManager]](어제 만듦, "죽은 층에서 다시 시작")와는 별개 시스템 — 게임 오버 리트라이는 세이브 파일을 안 건드림(재시도 중 사망 상태로 저장되는 사고 방지)
- 나중에 "처음부터 재시작"이 필요해지면 `SaveManager.DeleteSave()` + `GameOverManager`의 재시작 로직을 1층 이동으로 바꾸면 됨
