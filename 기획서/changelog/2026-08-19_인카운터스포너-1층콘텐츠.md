# 2026-08-19 — 인카운터 웨이브 스포너 + 1층 콘텐츠 착수

## 배경

v0.2/v0.3의 "시스템 코드"가 마무리되면서, 이제 그 시스템들을 실제로 쓰는 **레벨 콘텐츠**로 전환. [[28 레벨 디자인 - 인카운터 페이싱과 블록아웃]]을 보니 1층은 단순 배치가 아니라 **웨이브 기반 전투**(1웨이브: 평×1 HP 절반 고정 → 처치 후 2초 인터벌 → 2웨이브: 평×1 정상 HP → 클리어 시 계단)로 설계돼 있어서, 기존 `RoomClearGate`+`Stairs`만으로는 부족한 조각(웨이브 스포너)을 먼저 추가.

## 한 일

- **`EncounterSpawner.cs` 신규** — 웨이브 목록을 순서대로 진행하는 범용 스포너:
  - 각 웨이브는 적 프리팹 배열 + 스폰 위치 배열 + **체력 배율**(예: 0.5=절반)로 정의
  - 한 웨이브의 모든 적이 죽어야 다음 웨이브(대기시간 후) 시작
  - **`RoomClearGate`와 별도 이벤트 연동 없이 자연스럽게 맞물림** — RoomClearGate는 "지금 범위 안에 살아있는 적이 있는가"만 주기적으로 재검사하므로, 마지막 웨이브까지 다 죽어야 계단이 열림. 두 스크립트를 그냥 같이 두면 됨(설계 시너지)
  - 체력 배율은 이미 있던 `EnemyHealth.ConfigureMaxHP()`(EnemyBun 미니언용으로 먼저 만들어둔 것) 재사용

## Unity에서 해야 할 일 — 1층 콘텐츠 구성

1. **적을 프리팹으로 만들기**: `SC_Face_0`의 `EnemyPyeong`을 Hierarchy에서 Project 창(`Assets/Prefabs` 등)으로 드래그 → 프리팹 에셋 생성
2. **웨이브별 스폰 위치 2개** 만들기: 빈 오브젝트 2개(`Wave1SpawnPoint`, `Wave2SpawnPoint`) 배치
3. 빈 오브젝트에 **`EncounterSpawner.cs` 부착** → Inspector에서:
   - `Waves` 배열 크기 2
   - Element 0: `Wave Name`="1웨이브", `Enemy Prefabs`=[EnemyPyeong 프리팹], `Spawn Points`=[Wave1SpawnPoint], `Hp Multiplier`=0.5
   - Element 1: `Wave Name`="2웨이브", `Enemy Prefabs`=[EnemyPyeong 프리팹], `Spawn Points`=[Wave2SpawnPoint], `Hp Multiplier`=1
   - `Wave Interval`=2
4. **`RoomClearGate`**를 이 전투 공간을 덮도록 배치 (이미 [[logic/계단 & 방 클리어 게이트 씬 설정]] 절차대로 만들어뒀다면 위치/크기만 조정)
5. **`Stairs`**를 출구 쪽에 배치, `RoomClearGate`에 연결
6. 플레이테스트: 씬 시작 시 1웨이브(HP 절반 평) 자동 스폰 → 처치 → 2초 후 2웨이브(정상 HP 평) 스폰 → 처치 → 계단 활성화 → 밟으면 회전

## 버그 조사 — "2웨이브 시작하자마자 모든 웨이브 클리어" (원인 확인 완료)

플레이테스트에서 1웨이브 없이 곧바로 2웨이브가 시작되고 즉시 "모든 웨이브 클리어!"가 뜨는 증상 발견.

### 조사 과정
1. `TrueForAll()`은 빈 리스트에서 무조건 `true`라는 함정을 의심해 방어 로그 추가 → 실제로 `"2웨이브"의 Enemy Prefabs[0]가 비어있어 건너뜁니다` 로그가 떠서 **런타임엔 Wave 2의 프리팹 참조가 실제로 비어있음**을 확인
2. Inspector 스크린샷은 Wave 1/Wave 2 둘 다 정상 채워진 걸로 보여서 모순 → 씬 중복(`SC_Face_0`/`SC_Face_1`에 각각 별도 `Spawner`) 의심, 진단 로그 추가했지만 씬 중복은 아닌 것으로 확인(`Spawner` 1개만 존재)
3. 프리팹을 통째로 다시 만들고 Element를 재설정해도 동일 증상 재현 → 단순 오조작이 아님을 확인
4. **`GameObject.scene.IsValid()`로 참조가 "프리팹 에셋"인지 "씬에 남아있는 오브젝트"인지 구분하는 로그**를 추가해서 결정적 증거 확보:
   - 1웨이브 스폰 시점 로그: `EnemyPyeong[⚠씬 오브젝트(SC_Face_0)]` — Waves가 **Project 프리팹이 아니라 Hierarchy의 씬 오브젝트를 직접 참조** 중이었음
   - `EnemyPyeong 정화 완료!` (**"(Clone)" 접미사 없음** — 스폰된 게 아니라 원본 그 자체가 죽었다는 뜻)이 먼저 찍히고, 그 다음 `EnemyPyeong(Clone) 정화 완료!`(1웨이브가 실제로 스폰한 개체)가 찍힘
   - 즉 **Hierarchy에 살아있는 원본 `EnemyPyeong`을 Waves 배열이 그대로 참조**하고 있었고, 1웨이브 스폰 때는 원본이 아직 살아있어 정상 복제(Instantiate)됐지만, 전투 중 플레이어가 그 원본 자체를 잡아버려서 파괴되자 참조가 Unity의 fake-null이 됨 → 2웨이브 스폰 시점엔 참조가 비어있어서 즉시 클리어 처리

### 원인
`Enemy Prefabs` 필드에 **Project 창의 프리팹 에셋이 아니라 Hierarchy의 씬 오브젝트**가 잘못 들어가 있었음 (Hierarchy에서 드래그 vs Project 창에서 드래그의 차이 — 겉보기엔 Inspector에서 똑같이 보여서 구분이 안 됨).

### 해결
1. `SC_Face_0` Hierarchy에 남아있는 원본 `EnemyPyeong`을 삭제(또는 전투 범위 밖으로 이동)
2. `Spawner`의 `Waves` → 각 Element → `Enemy Prefabs` 필드를 비우고, **Project 창의 프리팹 에셋을 다시 드래그**해서 재할당
3. (참고) 필드에 든 게 프리팹 에셋인지 씬 오브젝트인지 헷갈릴 때는 필드를 클릭했을 때 **Project 창에서만 반짝이면 정상, Hierarchy에서도 반짝이면 씬 오브젝트 참조**로 구분 가능

`EncounterSpawner.cs`에 조사용으로 추가했던 상세 진단 로그는 원인 확인 후 다시 걷어내고, 필수 로그(웨이브 시작/클리어, 빈 웨이브 경고)만 남김. 조사 중 콘솔이 너무 시끄럽다는 피드백도 있어서 `EnemyHealth`/`PlayerHealth`의 매 피격마다 찍히던 HP 로그도 제거함(죽음/회복 로그는 유지).
