# 큐브 워커 — 캐릭터가 이동 방향을 자동으로 바라보도록 재설계

## 배경

사용자 리포트: "유니티짱이 플레이어가 조작하는 방향에 따라 회전을 했음 좋겠는데, 지금은 마우스를 회전하든 좌/우로 움직이든 한 방향만 보고 있어." 확인 질문 결과 원하는 동작은 **"이동하는 방향을 자동으로 바라보는" 방식** — 마우스가 캐릭터를 직접 돌리는 지금 방식이 아니라, WASD로 움직이면 그 방향을 향해 캐릭터가 자동으로 도는 흔한 3인칭 액션 게임 방식.

## 원인 조사

기존 `CubeSurfaceWalker`는 `facingForward` 벡터 하나가 "마우스로 도는 방향"이자 "캐릭터가 실제로 보는 방향"을 동시에 담당했음(2026-09-12 설계). 좌우 스트레이프(A/D)는 애초에 `facingForward`를 안 건드리므로 방향 전환이 안 됐고, 마우스 회전은 원래 작동해야 하는 코드였지만(리플렉션으로 직접 값을 바꿔보면 캐릭터가 정상적으로 도는 것 확인) 사용자가 원한 조작 방식 자체가 이거였다는 게 핵심 — 버그가 아니라 설계 방향을 바꾸는 요청.

## 결과물

`facingForward` 하나를 두 개로 분리:
- **`cameraForward`** — 마우스로 도는 "카메라 기준 방향". WASD 입력을 해석하는 기준(예: W = 이 방향으로 전진).
- **`characterForward`** — 캐릭터가 실제로 보는(=`transform.rotation`이 향하는) 방향. **이동 방향이 결정** — 움직이는 순간 그 방향으로 스냅되고, 안 움직이면 마지막으로 보던 방향을 그대로 유지(카메라 쪽으로 되돌아가지 않음).

`CubeSurfaceCamera`도 `target.transform.forward`(=이제 이동 방향을 따르는 캐릭터 회전) 대신 새로 노출한 `walker.CameraForward`를 기준으로 캐릭터 뒤를 따라가도록 변경 — 그래야 가만히 서서 마우스만 돌려도 카메라가 자유롭게 둘러볼 수 있음(캐릭터 실제 회전 기준이면 안 움직일 때 카메라도 고정됨).

**면 전환 시 parallel-transport(2026-09-12에 이미 확립된, 모서리에서 방향이 안 틀어지게 하는 안전장치)를 `cameraForward`/`characterForward` 둘 다에 동일하게 적용** — 예전에 사용자가 겪었던 "면이 바뀔 때마다 카메라를 다시 돌려줘야 해서 불편하다"는 문제가 새 구조에서도 재발하지 않도록 함(카메라 기준 방향도 캐릭터 방향과 동일하게 면을 넘어도 왜곡 없이 이어짐).

## 검증

리플렉션으로 세 가지 시나리오 확인:
1. 이동 입력 없이 `cameraForward`만 바꿈 → `characterForward`/`transform.forward` 전혀 안 바뀜(가만히 서서 카메라만 도는 것 확인).
2. `moveDir = cameraForward * y + cameraRight * x` 공식이 카메라 기준으로 정확히 계산됨(순수 W 입력 시 `moveDir`이 정확히 `cameraForward`와 같음).
3. 면 전환(+Z→+X) 시 `cameraForward`/`characterForward` 둘 다 동일한 parallel-transport 회전을 받아 똑같이 변환됨(회전축과 정확히 일치하는 값으로 처음 테스트했다가 "변화 없음"을 버그로 오인할 뻔했는데, 회전축이 아닌 값으로 재검증해서 실제로는 정상 작동함을 확인).

## 한계

- 실제 키보드 입력(`ReadKeyboardInput()` → `moveInput`)이 리플렉션 주입값을 매 프레임 덮어써서, "실제 WASD 입력 → 캐릭터 회전"까지의 전체 체인은 이 자동화 환경에서 하드웨어 키 입력을 흉내낼 수 없어 끝까지 리플렉션으로 검증은 못 함 — 다만 `ReadKeyboardInput()`/`moveDir` 계산 부분은 이번에 안 건드린 기존 코드라 위험 낮음. 사용자가 실제 플레이로 최종 확인 필요.
