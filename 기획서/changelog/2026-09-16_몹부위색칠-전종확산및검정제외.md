#기획 #먹괴음 #changelog

# 부위 색칠 처치 시스템 — 나머지 4종 확산 + 검정 색상 제외

## 배경

[[changelog/2026-09-16_몹부위색칠처치시스템]]에서 평(Pyeong) 1종에만 적용해뒀던 시스템을, 사용자가 "모든 몹은 7번 맞으면 죽는거야?"라고 확인차 물어봐서 나머지 4종(원/분/흡/광)까지 적용할지 물었고, 사용자가 "색을 부여할 때, 검은색은 없애야지"로 응답 — 전종 확산에 동의하면서 동시에 색상 로직 자체의 결함을 지적함.

## 왜 검정을 빼야 했는가

먹괴음은 "색을 먹어치운 먹물 괴물"이라 부위 색칠 전 기본 상태가 이미 어둡고 무채색에 가까움. 6색 팔레트(빨/파/노/초/보/검)에서 무작위로 고르던 기존 로직이 우연히 검정을 뽑으면, 눈으로 봤을 때 "맞았는데 부위가 안 변한 것처럼" 보임 — 실제로는 정상적으로 처치 판정이 진행 중인데 시각 피드백만 없어서 사용자가 "맞았나?" 혼란스러울 수 있는 문제. 색 구슬 드랍(`ColorOrbPickup`/`EnemyHealth.DropColorOrb`)은 검정도 유효한 드랍 색이라 그대로 두고, **색칠 연출에서만** 검정을 제외하도록 범위를 좁힘.

## 확산 검증

나머지 4종 프리팹의 렌더러 이름 규칙을 먼저 확인 — 전부 평과 똑같은 `InkGolem_<종>_<부위>` 패턴이라 `MonsterPaintParts.ClassifyByName()`을 코드 수정 없이 그대로 재사용 가능함을 리플렉션으로 확인:
- `EnemyWon`(26개 렌더러) → 정확히 7부위 분류(미분류: 안테나/파우치/포신 부속 등 장식 6개)
- `EnemyBun`(27개) → 정확히 7부위 분류(미분류 없음)
- `EnemyHeup`(23개) → 정확히 7부위 분류(미분류: 뿔)
- `EnemyGwang`(24개) → 정확히 7부위 분류(미분류: 왕관/고리)

## 결과물

- **`OrbColorPalette.GetRandomVividColor()` 신규** — 검정을 뺀 5색 중 무작위 하나를 돌려줌. `OrbColor.Black`의 실제 배열 인덱스를 건너뛰는 방식이라 팔레트 순서가 나중에 바뀌어도 안전. `GetRandomColor()`(6색 전체, 구슬 드랍용)는 그대로 남겨둠 — 색칠 전용으로만 신규 메서드 사용.
- `MonsterPaintParts.PaintRandomPart()`가 `GetRandomColor()` 대신 `GetRandomVividColor()`를 쓰도록 변경.
- `EnemyWon.prefab`/`EnemyBun.prefab`/`EnemyHeup.prefab`/`EnemyGwang.prefab` 4개 전부에 `MonsterPaintParts` 부착(`PrefabUtility`로, `EnemyPyeong` 때와 동일한 방식) — 이제 **5종 전부** 부위 색칠 처치 시스템 적용됨.

## 검증

- `EnemyWon.prefab` 인스턴스로 8회 연속 999 데미지 공격 — 6회까지 `CurrentHP` 6→1/`PaintedCount` 1→6 정상 감소, 7회째 `CurrentHP=0`/`PaintedCount=7`/`IsDead=True` 정확히 확인. (원/분/흡/광 나머지 3종은 렌더러 분류 결과가 동일 패턴이라 별도 개별 재현 없이 이 결과로 갈음 — 다만 실제 플레이 재확인은 아직 안 함.)
- `GetRandomVividColor()`를 2000회 반복 샘플링 — 검정 등장 0회 확인.

## 한계

- 나머지 3종(분/흡/광)은 EnemyWon과 동일한 코드 경로를 타므로 코드상 안전하다고 판단했지만, 개별 실측 검증은 안 함.
- `EnemyBun`(분열형)은 처치 시 미니언 2마리를 자기 복제하는 별도 로직이 있는데, 이건 `Die()`/`OnDeath()` 이벤트 훅으로 구현돼 있어서 부위 색칠 경로를 타도 정상 호출될 것으로 판단되나(코드 경로상 `Die()` 자체는 안 바뀜) 분열까지 포함한 실측은 안 함.
