# 흡(Heup) 재설계 — 환경 구역 대신 플레이어에게 붙어 색 흡수

## 배경

층별 콘텐츠 다양화 확인 중 사용자 리포트 "3층까지 왔는데, 몹이 다 똑같은데?" → 조사 결과 스폰 자체는 정상 다양화됐지만(실제로 원/평 섞여 나옴), 흡(Heup)의 시그니처 행동인 "저체력 시 회복하러 도망감"이 [[MonsterPaintParts]] 도입 이후 완전히 망가져 있어서 다른 종과 구별이 안 되는 상태였음이 드러남.

## 1차 발견 — 저체력 판정 단위 불일치 버그

`EnemyHeup`/`CubeEnemyHeup`가 "HP 50% 밑" 판정을 숫자 체력(`currentHP`/`maxHP`)으로 직접 비교하는데, `MonsterPaintParts`가 붙으면 `TakeDamage()`가 숫자 체력을 아예 안 건드리고 리턴함:
- **큐브(`CubeEnemyHeup`)**: `currentHP`가 맞아도 안 줄어서 "저체력" 조건이 평생 안 걸림 → 회복 행동 자체가 사라지고 그냥 평범하게 쫓아오는 몹이 됨(사용자가 목격한 증상).
- **평지(`EnemyHeup`)**: `EnemyHealth.CurrentHP`는 이미 "남은 부위 수"(최대 7)로 재해석돼있는데 `maxHP`는 그대로 20 같은 숫자라서, 반대로 스폰 직후부터 영원히 "저체력"으로 고정 — 플레이어를 아예 안 쫓아오고 계속 회복 구역만 찾아다님.

`MonsterPaintParts.HealthFraction`(0~1 정규화 비율) 신규 추가로 양쪽 다 일관된 단위로 판정하도록 수정.

## 2차 — 사용자 요청으로 회복 메커니즘 자체를 재설계

버그를 고치던 중 사용자가 "아 흡은 플레이어한테 붙어서 플레이어의 색을 흡수하는 느낌으로 가자"로 방향 전환. 확인 질문 2개:
- 흡수 비용: **보유 색 구슬 소모** (HP 감소나 무페널티 대신)
- 적용 범위: **평지/큐브 둘 다 동시에**

## 발견한 충돌 — 4층 벽 폭발 페널티

흡의 `OnAbsorbStart` 이벤트에 이미 4층 전용 [[WallExplosionHazard]](흡이 회복 구역 도달 시 유예 시간 후 벽 폭발 즉사 페널티)가 연결돼 있음을 발견 — 흡수 대상을 환경 구역에서 플레이어로 완전히 바꾸면 이 기믹이 무효화됨. 사용자 확인: **"4층 기믹도 같이 새 방식으로 재설계"**. 실제로는 `OnAbsorbStart`가 트리거만 "구역 도달"→"플레이어에게 달라붙음"으로 바뀌고 `WallExplosionHazard`의 로직 자체(이벤트 발동→유예 시간→안 죽어있으면 폭발)는 그대로 재사용 가능해서, 주석/로그 문구만 갱신하고 코드 구조는 안 건드림.

## 결과물

- **`MonsterPaintParts.HealthFraction`** 신규 — 남은 부위 비율(1=멀쩡, 0=전부 칠해짐).
- **`MonsterPaintParts.HealRandomPart()`** 신규 — `PaintRandomPart()`의 반대 동작(이미 칠해진 부위 중 하나를 원래 색으로 되돌림). "회복 중엔 이미 칠해진 부위를 하나씩 되돌림"이라는 이전 사용자 결정을 실제로 구현.
- **`ColorSystemManager.TryDrainRandomOrb()`** 신규 — 보유 색 중 무작위 하나를 빼앗음(없으면 false).
- `EnemyHeup`/`CubeEnemyHeup` 둘 다 재작성 — 흡수 대상이 `RestoredAreaRegistry` 정적 구역에서 플레이어(살아있는 타겟, 매 프레임 거리 재확인 필요)로 바뀜. 흡수 중엔 `healPerSecond`를 "초당 흡수 시도 횟수"로 재해석해 일정 간격마다 `TryDrainRandomOrb()` 시도 — 성공했을 때만(플레이어에게 구슬이 있을 때만) 회복. 플레이어가 흡수 도중 멀어지면 즉시 끊김.
- `WallExplosionHazard.cs` 문서/로그 문구 갱신(코드 구조 변경 없음).

## 부수 발견 — SC_CubePrototype에 색 구슬 시스템 자체가 없었음

테스트 중 `ColorSystemManager.Instance`가 null임을 발견 — 이 프로토타입 씬은 이동/AI 검증용으로만 만들어져서 `ColorSystemManager`/`ColorOrbPool`/플레이어의 `ColorSkillController`가 하나도 연결된 적이 없었음. 사용자 확인 후 최소 연결:
- `CubeFaceRoomBuilder`(에디터, 1층 최초 세팅)에 `ColorSystemManager`/`ColorOrbPool` GameObject 자동 생성 추가.
- `CubeEnemyBase.OnDeath()`에 `DropColorOrb()` 추가 — 원본 `EnemyHealth.Die()`엔 있었는데 큐브 버전엔 아예 빠져있었음(처치해도 구슬이 하나도 안 드랍되던 상태였음).
- **`ColorSkillController`(강타/흐름/번쩍)는 스킵** — `[RequireComponent(typeof(PlayerController))]`를 강제해서 `CubeSurfaceWalker` 기반인 이 플레이어에는 그대로 못 붙임. 별도 리팩터가 필요해서 이번 범위에서 제외.

## 검증

- 플레이어에게 구슬 3개(빨/파/노) 지급 후 `EnemyHeup.TryAbsorbFromPlayer()` 6회 호출 — 정확히 3번만 성공(부위 5→2로 회복, 구슬 3→0), 구슬 소진 후 3번은 정상적으로 아무 일도 안 함(부위/구슬 변화 없음).
- `CubeEnemyHeup`을 플레이어 근처에 배치, 저체력 상태로 만든 뒤 `OnChasingTick()` 1회 호출 — `OnAbsorbStart` 정확히 1회 발동 + Busy 상태 진입 확인. `OnBusyTick()`을 시간 누적이 간격을 넘도록 반복 호출 — 정확히 그 시점에 1회 회복(부위 5→4, 구슬 2→1) 확인. 플레이어를 멀리 이동시킨 뒤 `OnBusyTick()` 호출 — 즉시 `Chasing` 상태로 복귀 확인.
- 신규 `ColorSystemManager`/`ColorOrbPool`이 씬에 정상 존재함을 재빌드 후 확인.

## 한계

- `ColorSkillController`(색 스킬 3종)는 이번에 큐브 프로토타입에 연결 안 함 — 나중에 `BrushWeapon`처럼 `PlayerController` 없이도 동작하도록 일반화하면 붙일 수 있음.
- 씬 재빌드(`CubeFaceRoomBuilder.BuildFromCLI()`)가 `currentFloor`를 1로 리셋시키므로, 사용자가 진행 중이던 3층 진행 상황은 이 작업으로 초기화됨.
- 4층(평지 던전) 실측 재확인은 안 함 — 코드 구조상 안전하다고 판단했으나 실제 플레이로 "제때 못 끊으면 벽 폭발" 흐름이 여전히 자연스럽게 이어지는지는 다음에 확인 필요.
